# Java 运算符：整数除法、短路，以及那个 -1

运算符是编程里最不设防的一块：语法一眼就懂，所以出错时第一反应总是「逻辑写错了」，而不是「这个符号本身的行为和我想的不一样」。

但真正在项目里造成事故的，往往就是这些符号的默认行为。整数除法把 0.5 悄悄吃掉，`%` 在负数上返回负值，浮点数比不出相等，位运算和比较混写直接编译不过。这些都不是 bug，是语言规定，只是没人提前告诉你。

这篇按「最容易误解」的顺序过一遍：算术、赋值、逻辑、位运算、优先级、浮点、三元。

## 一、整数除法截断，取余跟着被除数走

```java
System.out.println(7 / 2);      // 3
System.out.println(7.0 / 2);    // 3.5
System.out.println(-7 % 2);     // -1
System.out.println(7 % -2);     // 1
```

四个结果，两条规律：

- **两个整数相除，结果还是整数**，小数部分直接截断（不是四舍五入）。想要小数，至少一边得是浮点：`7 / 2.0`。
- **`%` 的结果符号跟被除数走**，不跟除数。所以 `-7 % 2` 是 `-1`，`7 % -2` 是 `1`。

第二条会直接毁掉一个看起来天经地义的判奇数写法：

```java
n % 2 == 1      // n = -3 时得 -1，判断为 false
```

`-3` 明明是奇数，`-3 % 2` 却是 `-1`，和 `1` 不相等。正确写法只有两种：

```java
n % 2 != 0      // 通用
(n & 1) == 1    // 位运算，负数也正确
```

同一个坑还有一个更常见的变体：求平均值忘了转 `double`。

```java
int avg = (a + b) / 2;          // 1 和 2 平均得 1
double avg = (a + b) / 2.0;     // 1.5
```

统计类代码里「百分比全是 0」的元凶基本都是这一行——`1 / 2` 永远是 `0`，乘 100 还是 0。

自增自减也归在这里，只有一条要记：**前缀先加后用，后缀先用后加**。实测：

```java
int i = 5;
System.out.println(i++);   // 5，然后 i 变 6
System.out.println(++i);   // 7
```

## 二、复合赋值能过、拆开写就编译不过

```java
short s = 1;
s += 1;        // 合法
s = s + 1;     // 编译错误：possible lossy conversion from int to short
```

两行在做同一件事，一行过一行不过。原因分两步：

1. `byte` / `short` / `char` 参与算术运算时会先**提升为 `int`**，所以 `s + 1` 的类型是 `int`。
2. `s = (int 值)` 赋给 `short` 需要强转；而 `s += 1` 被规定为等价于 `s = (short)(s + 1)`，**自带隐式强转**。

`int` 上也能看到这个隐式转换的痕迹：

```java
int x = 2;
x += 3.5;          // 5，不是 5.5
```

`x + 3.5` 是 `double`，复合赋值把它强转回 `int`，`.5` 被截掉。这条在「为什么金额算着算着少了零头」的场景里出现过。

结论：复合赋值不是简写，是**简写 + 强转**。需要保留精度时，别图省事。

## 三、`&&` 短路不是性能优化，是正确性

| 运算符 | 含义 | 短路 |
| :--- | :--- | :--- |
| `&` | 逻辑与 | 否，两边都算 |
| `\|` | 逻辑或 | 否，两边都算 |
| `^` | 异或 | 否，不同为 `true` |
| `&&` | 短路与 | 左 `false` 时右边不算 |
| `\|\|` | 短路或 | 左 `true` 时右边不算 |

最典型的用法：

```java
String s = null;
if (s != null && s.length() > 0) { }
```

左边为 `false`，右边根本不会执行，所以 `s.length()` 不会被调用。把 `&&` 换成 `&`，实测立刻抛异常：

```text
NullPointerException: Cannot invoke "String.length()" because "<local1>" is null
```

所以空判必须写 `&&`。`&` 只在明确要「两边都执行」时才用（比如两边都有副作用），现实业务里几乎见不到。

顺带把比较运算符放这里：` ==`、`!=`、`>`、`<`、`>=`、`<=` 产出的都是 `boolean`。比基本类型比值，比引用类型比地址——**所以字符串比较永远用 `equals()`**。这条在后面字符串那篇会展开，但根因就在这里。

## 四、补码：`~5` 为什么是 `-6`

Java 的整数用**补码**存：正数原码即补码，负数取反加一。最高位是符号位，所以 `int` 的范围是 -2³¹ ~ 2³¹-1，负数比正数多一个。

补码的设计目的是让**减法用加法实现**，硬件只需要一套加法器。代价是一批反直觉的位运算结果。

设 `a = 5`、`b = 3`，实测：

| 表达式 | 结果 | 说明 |
| :--- | :--- | :--- |
| `5 & 3` | 1 | 都为 1 才 1 |
| `5 \| 3` | 7 | 有一位 1 就 1 |
| `5 ^ 3` | 6 | 不同才 1 |
| `~5` | **-6** | 逐位取反，含符号位 |
| `5 << 1` | 10 | 左移等于乘 2 |
| `-5 >> 1` | **-3** | 高位补符号位 |
| `-5 >>> 1` | **2147483645** | 高位一律补 0 |

三个必须记住的性质：

- **`~n = -n - 1`**。`~5` 是 `-6`，不是 `4`。看到这个结果别怀疑编译器。
- **`>>` 与 `>>>` 在负数上完全不同**。`>>` 补符号位，结果仍是负数；`>>>` 把符号位当普通位搬走，得到一个巨大正数。所以 `>>>` 处理负数几乎没有意义——它真正的用途是二分查找里避开溢出：`mid = (low + high) >>> 1`。
- **移位数先对 32 取模**。实测 `1 << 32` 是 `1`（不是 0），`1 << 33` 是 `2`。想清某一位别指望移位，直接赋值。

## 五、五个能直接抄的位运算套路

```java
boolean odd = (n & 1) == 1;          // ① 判奇偶，负数也正确
int lowbit = n & -n;                 // ② 取最低位的 1
n &= (n - 1);                        // ③ 清最低位的 1
a ^= b; b ^= a; a ^= b;              // ④ 异或交换
boolean bit = ((n >> k) & 1) == 1;   // ⑤ 判断第 k 位
```

前两个值得知道原理，因为面试会追问：

- **`n & -n` 取最低位 1**：`-n` 是取反加一。取反后最低位的 `1` 变 `0`、右边全变 `1`；加一时进位把那一位重新变回 `1`、右边归 `0`。相与时只有那一位两边都是 `1`。实测 `6 & -6 = 2`。
- **`n & (n-1)` 清最低位 1**：`n-1` 把最低位的 `1` 变 `0`、右边全变 `1`，相与正好清掉它。实测 `6 & 5 = 4`。用它数二进制里 1 的个数，循环次数等于 1 的个数，比逐位扫快。

异或交换有个致命前提：**`a != b`**。`a == b` 时第一步 `a ^= b` 就把 `a` 清零，后面全错。这个技巧只在面试里有价值，工程里用临时变量。

实测一组对比，说明为什么判奇偶该用位运算：

```text
(-3) & 1  = 1
-3  % 2   = -1
```

同样的输入，一个得 1 一个得 -1——`%` 的符号规则在这里成了陷阱。

三个工程用途也顺手记一下：

| 场景 | 做法 | 好处 |
| :--- | :--- | :--- |
| 权限 / 状态标志 | `READ = 1 << 0`、`WRITE = 1 << 1`，组合用 `\|`，判断用 `&` | 一个 int 存 32 个开关 |
| 状态压缩 DP | 用二进制位表示「哪些元素被选过」 | 集合状态变成可下标的整数 |
| 哈希 / 位图 | `hash & (n-1)` 定位桶 | 取模换位与，快一个数量级 |

`HashMap` 的容量永远是 2 的幂，就是为了让 `hash & (n-1)` 能代替 `hash % n`——这是位运算在标准库里的存在感。

## 六、优先级：只需记三条

完整优先级表有十几级，背它没有意义。实际只需要三条：

1. **`&&` 高于 `||`**：`a || b && c` 等价于 `a || (b && c)`。
2. **` ==` 高于 `&`**：`1 == num & 1` 被解析成 `(1 == num) & 1`，即 `boolean & int`，直接报 `bad operand types for binary operator '&'`。
3. **不确定就加括号**。括号不花钱，猜优先级要花半小时。

第二条是位运算与比较混用时的标准翻车姿势。报错信息看起来像类型问题，实际是优先级问题：

```java
boolean odd = 1 == num & 1;      // 编译错误
boolean odd = (num & 1) == 1;    // 正确
```

还有个跨语言差异值得记：MySQL 里 `&` 的优先级**高于**等号，`id & 1 = 0` 能跑；Java 里反过来。同一条表达式换个语言就编译不过，结论是「跨语言一律加括号」。

**三元运算符** `条件 ? 值1 : 值2` 有两条限制：

- 两个分支的类型必须兼容——编译器要推导出唯一类型。一边 `int` 一边 `String` 直接报错。
- 它是**表达式不是语句**，必须产出值，不能单独当一行调用。

## 七、浮点数：`0.1 + 0.2` 与金额红线

```java
System.out.println(0.1 + 0.2);              // 0.30000000000000004
System.out.println(0.1 + 0.2 == 0.3);       // false
```

这不是 bug，是 IEEE 754 的必然：`float` / `double` 用二进制表示小数，而 `0.1` 在二进制里是无限循环小数，和十进制里的 `1/3` 一样。存进去的那一刻就已经截断了。

正确的做法有三条：

```java
Math.abs(a - b) < 1e-6;                          // ① 比较用误差范围
new BigDecimal("0.1").add(new BigDecimal("0.2")); // ② 金额用 BigDecimal，实测得 0.3
long cents = 1999;                                // ③ 或者以「分」为单位用 long
```

第②条有个细节：`BigDecimal` 的构造**必须传字符串**。`new BigDecimal(0.1)` 会把 `double` 的误差一起带进去，得到一个 `0.1000000000000000055511151231257827...`。

记法只有一句：**看到「金额 + `double`」就直接改 `BigDecimal`**，别等到对账差一分钱再回头。

## 小结

- 整数除法**截断**，`%` 的符号**跟被除数**；判奇数写 `n % 2 != 0` 或 `(n & 1) == 1`，别写 ` == 1`。
- 复合赋值 = 简写 + **隐式强转**，所以 `s += 1` 能过、`s = s + 1` 不能。
- `&&` / `||` 短路是**正确性**基础（空判靠它），`&` / `|` 不短路，只在需要两边都执行时用。
- 补码决定了 `~n = -n-1`、`>>` 补符号位、`>>>` 补 0、移位数对 32 取模（`1 << 32` 是 1）。
- 位运算五个套路：判奇偶、`n & -n`、`n & (n-1)`、异或交换（`a != b`）、取第 k 位。
- 优先级只记三条：`&&` 高于 `||`、` ==` 高于 `&`、不确定就加括号。
- 浮点数永不比相等，金额用 `BigDecimal`（字符串构造）或「分」为单位的 `long`。
