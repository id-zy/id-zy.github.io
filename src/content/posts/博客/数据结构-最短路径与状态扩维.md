# Dijkstra：边权为什么必须非负，状态不够用时扩哪一维

最短路径听起来像个已经解决的问题：把边权加起来取最小，谁不会。

真正写的时候，第一个坑不在算法，而在那个前置条件——为什么非要「边权非负」。把它当成一句谨慎的备注跳过，代码在样例上照样跑对，然后在某个带负权的图上安静地给出错误答案。第二个坑在题目加了约束之后：骨架一个字都不用改，难的是不知道该往状态里再塞一维什么。

前半用一个四节点反例说明非负权在保护什么，再用实测数字比较线性扫描、二叉堆、惰性删除这几档实现。后半落在一道真实题目上：同一套 Dijkstra，只把状态从「节点」扩成「节点 + 连续字符数」，就从不会做变成通过，而扩错的两种写法我也跑了出来。

## 一、出堆即定型，其余动作都在保证它有资格执行

Dijkstra 的全部赌注压在一条不变式上：**优先队列里取出的最小距离，就是该节点的最终答案，此后不会再被改小。** 剩下的代码都是为了让它成立。

核心动作只有一行，就是松弛：从 u 走到 v，可能比已知的到 v 更近。

```text
if dist[u] + w(u, v) < dist[v]:
    dist[v] = dist[u] + w(u, v)
```

流程只有四步：起点距离设为 0 并入队，其余留作无穷；每次取出距离最小的未定型节点 u；对 u 的每条出边松弛一次，改小了就把新版本入队；队列空或全部定型则结束。

## 二、松弛一行，六个节点跑一遍

拿一张教科书常用的六点图验证骨架。邻接表里每个元素是 `(邻居, 权值)`：

```python
import heapq
from math import inf

def dijkstra(graph, start):
    n = len(graph)
    dist = [inf] * n
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:              # 堆里的过期版本，丢弃
            continue
        for v, w in graph[u]:
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

g = [[(1, 7), (2, 9), (5, 14)], [(2, 10), (3, 15)], [(3, 11), (5, 2)],
     [(4, 6)], [(5, 9)], [(4, 9)]]

print(dijkstra(g, 0))
```

输出：

```text
[0, 7, 9, 20, 20, 11]
```

4 号节点值得看一眼：它先以 26 入队（0 到 3 是 20，加 6），后来 5 号定型时只有 11，加 9 得 20，把 26 改小。**后出堆的节点改动先前算出的答案，不违反不变式**——被改的 4 号当时还没定型。这就是「定型」：不是「算过一次」，而是「取出来过」。

## 三、非负权是地基：一个四节点反例

教科书版会维护 visited 标记，出堆即定型，之后不再改动。加上这个标记，再看一个四节点的图：0 到 1 权重 2，0 到 2 权重 5，2 到 1 权重 -4，1 到 3 权重 1。

```python
def dijkstra_locked(graph, start):
    n = len(graph)
    dist = [inf] * n
    visited = [False] * n
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if visited[u]:
            continue
        visited[u] = True            # 出堆即定型，此后不再改
        for v, w in graph[u]:
            if visited[v]:
                continue
            nd = d + w
            if nd < dist[v]:
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist

g_neg = [[(1, 2), (2, 5)], [(3, 1)], [(1, -4)], []]
print(dijkstra_locked(g_neg, 0))
```

输出：

```text
[0, 2, 5, 3]
```

正确答案是 `[0, 1, 5, 2]`：0 到 2 走 5，2 到 1 再减 4 得 1，1 到 3 加 1 得 2。程序给 1 号节点 2、给 3 号节点 3，两个都偏大。

错在哪很清楚：1 号的 2 是最小未定型距离，被取出定型；之后 2 号以 5 出堆，5 减 4 得 1 更小，可 1 号已定型，改进被 `if visited[v]: continue` 挡住，连带 3 号一起错。**一次提前定型，错误顺着路径传了下去。**

非负权就是为杜绝这件事：边权非负时，「还有更短的路到 v」意味着它必先经过某个未定型的 x，而 x 到 v 的剩余不会倒扣，故 x 的距离比 v 还小——可优先队列取的正是当前最小，矛盾。前提就是「剩余不会倒扣」这半句。

反过来说，负权图不是「Dijkstra 效果差一点」，是「答案不可信」。这类图交给 Bellman-Ford，或者先用 Johnson 把权重调正。

## 四、不锁定的写法，在负环上转不停

本文正片用的是不加 visited 的版本（第二节那段代码），它让同一节点被反复取出、反复松弛。这种写法在上一节的四节点图上给出的是正确答案 `[0, 1, 5, 2]`——改进会被重新入队，错误传不下去。

听起来像个免费的升级，其实不是。它只是把「定型」换成了「总能再改一次」，代价是碰到负环就没有终止条件：

```python
g_cycle = [[(1, 1)], [(2, 1)], [(1, -3)]]     # 1 -> 2 -> 1，每圈净减 2
dist = [inf] * 3
dist[0] = 0
pq = [(0, 0)]
pops = 0
while pq and pops < 20000:                    # 人为设上限才停得下来
    d, u = heapq.heappop(pq)
    pops += 1
    for v, w in g_cycle[u]:
        nd = d + w
        if nd < dist[v]:
            dist[v] = nd
            heapq.heappush(pq, (nd, v))

print(pops, dist[1], dist[2])
```

输出：

```text
20000 -19997 -19996
```

两万次出堆后，两个距离还在每圈减 2。这段代码没有「算完」，只有「你什么时候叫停」。所以两条结论不冲突：不带 visited 的写法在无负环时能收敛，但对负环毫无防御；带 visited 的写法严格依赖非负权。**判断标准仍是「Dijkstra 只用于非负权」**——你要的那条保证本来就挂在非负权上。

## 五、惰性删除省掉的不是出堆次数，是边扫描

Python 的堆没有 decrease-key，改不了堆里的元素。标准做法是**惰性删除**：不改旧记录，直接塞新版本，出堆时用 `if d > dist[u]: continue` 扔掉过期版本。

堆会因此变大，这是代价。但省下来的是什么？不是出堆次数——过期版本照样会被弹出、照样计入，而是**边扫描**：过期版本不该再展开邻居。拿一张 600 个点、每点 10 条边的随机图对比，两种写法只差那一行 `continue`：

| 写法 | 出堆 | 入堆 | 边扫描 |
| :--- | ---: | ---: | ---: |
| 带惰性删除 | 1,167 | 1,166 | **6,000** |
| 无惰性删除 | 1,167 | 1,166 | 11,670 |

出堆入堆完全一样，边扫描差 5,670 次、接近两倍：每次弹出过期版本，无删除版都把邻居再遍历一遍，做注定失败的比较。那行 `continue` 是复杂度的一部分——`O((V+E)logV)` 算的是「每条边只在成功松弛的那次展开被扫到」。

## 六、容器怎么选：实测里堆从来没输过

教科书列三档：线性扫描 dist 数组是 O(V²)，适合稠密图；二叉堆是 O((V+E)logV)，通用首选；斐波那契堆是 O(E + VlogV)，理论最优但常数极大，工程上少用。照理论，稠密图（E 接近 V²）该轮到 O(V²)。

实测完全图、权重 1 到 100 随机、每档三次取最优：

| V | 边数 | 线性扫描 | 二叉堆 | 堆快 |
| ---: | ---: | ---: | ---: | ---: |
| 400 | 159,600 | 9.2 ms | 4.2 ms | 2.20 倍 |
| 800 | 639,200 | 37.9 ms | 17.5 ms | 2.16 倍 |
| 1,600 | 2,558,400 | 147.4 ms | 67.1 ms | 2.20 倍 |

方向反了：堆在稠密图上还快一倍。原因在两者的工作形态——线性扫描跑的是 V² 次「取最小」，全是解释器的循环开销；堆跑的是 E 次松弛，只有真正改小才上浮，而稠密图里绝大多数边都松弛失败。

理论那一档优势要靠两件事兑现：C 级别的紧凑内层循环，和斐波那契堆的 decrease-key。解释型语言两样都没有，`O(V²)` 的常数项反而更贵。稀疏图的对比更极端（2,000 个点，每点出度 4）：

```text
二叉堆 1.2 ms   线性扫描 178.4 ms   扫描慢 153.6 倍
```

差距在这里是结构性的：线性扫描每轮都要把 V 个位置过一遍找最小值，V 趟就是 V² 次比较，与边数无关，稀疏图的边数根本喂不饱这个循环。

顺带一个计时教训：第一版脚本在计时区间里把堆调用了两次，测出「线性扫描快 5% 到 8%」，结论正好反了。对比两个实现时区间内只能各跑一次，减抖动靠多轮取最优。结论是：解释型语言里默认上堆，`O(V²)` 留给 C 和更小的 V。

## 七、状态不够用就扩一维：3970

算法本体讲完了，坑全在状态上。题目 3970：n 个点的有向带权图、每点一个标签，求 0 到 n-1 的最小总边权，且标签拼起来最多含 k 个连续相同字符。

裸的最短路只关心「到哪个点」，这道题不行：**同一个点从不同来路到达时，剩余的可走空间不一样**。末尾已连着 3 个 a 与刚换过字符，后续能走的边完全不同；只看编号会把两条路合成一条。所以要扩一维：状态是 `(节点, 末尾连续相同字符数)`，取 1 到 k。仍求最小代价、边权为正，还是 Dijkstra，只是堆里多存一个数：

```python
def shortest_path(n, edges, labels, k):
    g = [[] for _ in range(n)]
    for u, v, w in edges:
        g[u].append((v, w))
    dis = [[inf] * (k + 1) for _ in range(n)]
    dis[0][1] = 0                       # 起点标签占第一段连续
    pq = [(0, 0, 1)]                    # (代价, 节点, 连续数)
    while pq:
        d, x, c = heapq.heappop(pq)
        if d > dis[x][c]:               # 过期版本，丢弃
            continue
        if x == n - 1:
            return d                    # 第一次出堆即最小
        for y, w in g[x]:
            nc = c + 1 if labels[y] == labels[x] else 1
            nd = d + w
            if nc <= k and nd < dis[y][nc]:
                dis[y][nc] = nd
                heapq.heappush(pq, (nd, y, nc))
    return -1

print(shortest_path(3, [[0, 1, 1], [1, 2, 1], [0, 2, 3]], "aab", 1))
print(shortest_path(3, [[0, 1, 1], [1, 2, 1], [0, 2, 3]], "aab", 2))
print(shortest_path(3, [[0, 1, 1], [1, 2, 1]], "aaa", 2))
```

输出：

```text
3
2
-1
```

三个数与期望一致：k 为 1 只能直连走 3，k 为 2 可绕行得 2，全同标签链返回 -1。规模也验了：n 与边各 50,000、k 为 50，状态表 255 万槽位，耗时 37.8 ms。**k 不超过 50 正是这道题敢开二维的理由**——k 到 10⁵ 这张表就撑不住。

## 八、扩维之后要守的三个细节

第一，**连续数的初值取 1 而不是 0**。起点标签本身占掉第一段，取 0 会让「起点到同标签邻居」这条边少算一次。

第二，**`nc <= k` 必须写在下标 `dis[y][nc]` 之前**。`nc` 最大能到 `k + 1`，先取值就数组越界。这里的短路求值顺序是正确性，不是风格。

第三，**`if d > dis[x][c]: continue` 不能省**。同第五节，堆里会积压过期版本，不丢掉就会把同一状态反复展开。

顺带一个反直觉的：这道题不能用 BFS。层序不等于代价序——0 到 1 权重 5、0 到 2 权重 1、2 到 1 权重 1 的三点图，BFS 给 1 号 1 层，实际代价是 2。层数对，代价错。

## 九、把错法跑出来

扩维写错的方式比写对的多。上面解法的两个变体，都跑了同样三个用例：

| 写法 | 示例 1（期望 3） | 示例 2（期望 2） | 示例 3（期望 -1） |
| :--- | ---: | ---: | ---: |
| 状态带连续数，初值 1 | 3 | 2 | -1 |
| 状态带连续数，初值 0 | **2** | 2 | **2** |
| 状态只有节点 | **2** | 2 | **2** |

初值取 0 的那版从 `dis[0][0] = 0` 起算，走到同标签邻居时把连续数记成 1，看起来只差一个数，但整条链的计数都比真实少 1，于是 k 等于 1 时它敢走 0 到 1 到 2（给 2，应为 3），k 等于 2 时它敢走三个 a（给 2，应为 -1）。

只记节点的那版更彻底：末尾连着几个 a 的信息整个丢了，「走了两个 a」和「走了零个 a」成了同一状态。两个变体都过不了示例，但都不崩溃——**给出的是看起来合理的数字**。这类错误比报错难查得多，也是状态设计值得单独花十分钟的原因。

## 十、小结

- **非负权是「出堆即定型」的地基**。四节点反例里 1 号被提前定型后，负权改进被挡住，误差传到 3 号；负权图请换 Bellman-Ford。
- **不带 visited 的写法不是升级**。它在无负环时能收敛，但负环下没有终止条件——两万次出堆后距离还在 -19997。
- **惰性删除省的是边扫描**，同一张图上 6,000 对 11,670，出堆次数完全一样。那行 `continue` 决定复杂度，不是防御。
- **容器默认上堆**：稠密图上堆也比线性扫描快 2 倍左右，稀疏图上快 153 倍；`O(V²)` 那一档在解释型语言里吃不到。
- **图变复杂时先问状态够不够**：同一节点从不同来路到达、后续行为不同，就必须扩维；扩维后三个必查点是初值、越界判断顺序、过期条目的丢弃。初值差 1 会错两个用例，而且不报错。

真要记一句：**Dijkstra 的骨架永远不变，变的是你往状态里塞了什么。**
