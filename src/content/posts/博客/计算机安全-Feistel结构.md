# Feistel：轮函数不可逆，为什么还能解密

分组密码有一个设计上的分歧点：加密和解密要不要用同一套东西。

如果不一样，就得实现两套逻辑、验证两遍、可能只错一边。如果一样，实现量减半，出错面也减半。Feistel 结构选的是后者——**加密和解密用完全相同的结构，唯一的差别是轮密钥的顺序**。

做到这一点靠两个很朴素的运算：异或和交换。下面从结构讲到实测，最后说清它和 AES 的取舍。

## 一、安全三要素，和分组密码的位置

信息安全的三个基本属性：

| 属性 | 含义 | 被破坏的例子 |
|---|---|---|
| 机密性 Confidentiality | 未授权者看不到内容 | 明文传输密码 |
| 完整性 Integrity | 内容未被篡改 | 中间人改订单金额 |
| 可用性 Availability | 授权者随时能用 | DDoS 打瘫服务 |

分组密码主要解决第一条（配合 MAC 或 AEAD 才管第二条）。它的工作方式是把明文切成固定长度的块（DES 是 64 bit，AES 是 128 bit），每块用密钥做一串可逆变换。

「可逆」是整个设计的地基——解不回来就没意义。但**怎么实现可逆**，Feistel 和 SPN 走了两条路。

## 二、Feistel 结构：每轮只做两件事

把块切成左右两半 $L$、$R$，第 $i$ 轮：

$$L_{i+1} = R_i, \qquad R_{i+1} = L_i \oplus F(R_i, K_i)$$

就这两句。右半段先过一遍轮函数 $F$（带轮密钥 $K_i$），结果异或到左半段上，然后左右交换位置。

做完 $n$ 轮，再把最后的两半换回来拼成密文（多这一次交换是为了让解密流程和加密流程完全对称）。

解密怎么做？把公式反着解：

$$L_i = R_{i+1} \oplus F(L_{i+1}, K_i), \qquad R_i = L_{i+1}$$

看起来是两个式子，但对照加密那两行会发现：**它们长得一模一样，只是轮的顺序反了**。所以实现上不用写第二套代码，把轮密钥数组倒过来喂进同一个函数就行。

## 三、为什么不需要 F 可逆

这是整个结构最反直觉的地方。

每轮做的运算是 `L ^ F(R, K)`。异或有个性质：$(a \oplus b) \oplus b = a$，**自己做自己的逆**。所以想知道 $L_i$，只要拿 $R_{i+1}$ 再异或一次同样的 $F(R_i, K_i)$ 就还原了——这里根本不需要求 $F$ 的逆函数，只需要**重新计算** $F(R_i, K_i)$ 的值。

而 $R_i$ 从哪来？它就是上一轮的 $L_{i+1}$，明明白白躺在密文里。

所以整条链能倒推，靠的是「异或自逆」加「另一半数据没被改」，和 $F$ 能不能求逆毫无关系。**$F$ 可以是一个彻底不可逆的函数**——单向、有碰撞、多对一，都不影响解密。

这就是 Feistel 的核心价值：轮函数不必是双射。设计者可以放心用那些「混淆效果好但不可逆」的构件，选择面比 SPN 宽。

## 四、跑一遍：16 轮往返

实现一个最小版本，轮函数故意用不可逆的平方：

```python
MASK = 0xFFFFFFFF

def f(x, k):
    return (x * x + k) % (MASK + 1)

def encrypt(block, keys):
    L, R = (block >> 32) & MASK, block & MASK
    for k in keys:
        L, R = R, L ^ f(R, k)
    return (R << 32) | L

def decrypt(block, keys):
    return encrypt(block, list(reversed(keys)))

keys = [(0x1111 * i) % (MASK + 1) for i in range(1, 17)]
m = 0x0123456789ABCDEF
c = encrypt(m, keys)
print(f"  明文 {m:016X} -> 密文 {c:016X}")
print(f"  解密回原文：{decrypt(c, keys) == m}")

seen = {}
for x in range(200000):
    y = f(x, keys[0])
    if y in seen:
        print(f"  f({seen[y]}) = f({x}) = {y}，两输入同输出 → f 不可逆")
        break
    seen[y] = x
```

```text
  明文 0123456789ABCDEF -> 密文 55FA111E552DA368
  解密回原文：True
  f(0) = f(65536) = 4369，两输入同输出 → f 不可逆
```

`decrypt()` 只有一行——把 `keys` 倒序再调 `encrypt()`。16 轮下去，明文完整回来了。

最后三行是这个实验里最该看的部分：`f(0)` 和 `f(65536)` 都等于 4369，因为 $65536^2 = 2^{32}$，在模 $2^{32}$ 下和 $0^2$ 同余。**这个轮函数是多对一的，不存在逆函数。**可它照样能解密。

传统分组密码里，DES 的 F 函数虽然由 S 盒和置换组成（每步都是双射），但 Feistel 框架本身从来没要求 F 可逆——这一点在理论上给了设计者自由。

## 五、雪崩：差异 bit 数会收敛到一半

好的分组密码有个标准：改明文 1 bit，密文应该有一半左右的 bit 变化。这样攻击者无法从密文的局部差异推断明文的局部差异。

```python
MASK = 0xFFFFFFFF

def f(x, k):
    return (x * x + k) % (MASK + 1)

def encrypt(block, keys):
    L, R = (block >> 32) & MASK, block & MASK
    for k in keys:
        L, R = R, L ^ f(R, k)
    return (R << 32) | L

keys = [(0x1111 * i) % (MASK + 1) for i in range(1, 17)]
m = 0x0123456789ABCDEF

print(f"  {'轮数':>4}{'密文差异 bit':>16}")
for rounds in (1, 2, 4, 8, 16, 32):
    ks = keys[:rounds]
    a = encrypt(m, ks)
    b = encrypt(m ^ 1, ks)
    print(f"  {rounds:>4}{bin(a ^ b).count('1'):>16}")
```

```text
    轮数        密文差异 bit
     1              20
     2              38
     4              40
     8              35
    16              32
    32              32
```

块长 64 bit，理想值是 32 bit。看这列数字：1 轮 20 bit、2 轮就冲到 38、4 轮 40（超过一半），然后回落，16 轮、32 轮都稳定在 32。

两个观察：

**第一，1 轮就有 20 bit 的差异**，说明本例的平方函数扩散性太强了（改 1 bit 输入，平方后高位全变）。真实分组密码的轮函数要弱得多——DES 的 F 是 6→4 bit 的 S 盒加置换，单轮扩散有限，所以必须堆到 16 轮。

**第二，差异 bit 数不是单调上升的**。它先冲到 40（超过一半），再回落到 32。原因是异或和取模都是非线性与线性混合的操作，中间轮次可能出现「过度扩散」，最终收敛到统计期望值 32。**「轮数越多越好」的准确说法是「轮数够多才会收敛到一半」，而不是「越多越过半」。**

## 六、分组模式：ECB 为什么不能用

分组密码只负责「一个块怎么加密」。一条消息比块长时，要选择模式把它们串起来。最朴素的是 ECB（电子密码本）：每个块独立加密。

问题很直观：

```python
MASK = 0xFFFFFFFF

def enc(block, k):
    L, R = (block >> 32) & MASK, block & MASK
    for i in range(4):
        L, R = R, L ^ ((R * 7 + k + i) & MASK)
    return (R << 32) | L

keys = [(0x1111 * i) % (MASK + 1) for i in range(1, 17)]
blocks = [0x1111111111111111] * 3

ecb = [enc(b, keys[0]) for b in blocks]
print("  ECB：三个相同明文块")
for x in ecb:
    print(f"    {x:016X}")
print(f"  密文完全相同：{len(set(ecb)) == 1}")

prev, cbc = 0xDEADBEEF, []
for b in blocks:
    prev = enc(b ^ prev, keys[0])
    cbc.append(prev)
print("  CBC：同样的三个块")
for x in cbc:
    print(f"    {x:016X}")
print(f"  密文完全相同：{len(set(cbc)) == 1}")
```

```text
  ECB：三个相同明文块
    99AD455A777DFFDA
    99AD455A777DFFDA
    99AD455A777DFFDA
  密文完全相同：True
  CBC：同样的三个块
    BB24B52B0B268607
    8A2A4560C48A8F7D
    1DE9E9451FE0B525
  密文完全相同：False
```

ECB 下三个相同的明文块产出三份一模一样的密文。这意味着**攻击者不需要解密就能看出「第 1、2、3 块内容相同」**——结构信息泄漏了。经典的演示是一张图片用 ECB 加密后，轮廓依然清晰可见，因为大片同色区域加密后还是同样的大块色块。

CBC 的做法是让每个块先和前一块的密文异或，再做加密。第一块和一个初始向量（IV）异或。这样同样的明文块在不同位置得到不同结果，上面的三块密文就全不一样了。

CBC 的代价是不能并行加密（第 n 块依赖第 n-1 块的结果），但解密可以并行（每块的解密只依赖密文，不依赖前一块的解密结果）。另一个注意点：IV 不需要保密，但必须随机且每次不同，否则相同的消息首块仍会得到相同密文。

## 七、密钥空间：56 bit 为什么不够了

穷举密钥的代价是密钥空间的规模：

```python
for bits in (40, 56, 64, 128):
    space = 2 ** bits
    sec = space / 1e9
    if sec < 3600:
        unit = f"{sec:.0f} 秒"
    elif sec < 86400:
        unit = f"{sec / 3600:.1f} 小时"
    elif sec < 3.15e7:
        unit = f"{sec / 86400:.1f} 天"
    else:
        unit = f"{sec / (365.25 * 86400):.2e} 年"
    print(f"  {bits:>4} bit  空间 2^{bits} ≈ {space:.2e}  按 10^9 次/秒 {unit}")
```

```text
    40 bit  空间 2^40 ≈ 1.10e+12  按 10^9 次/秒 1100 秒
    56 bit  空间 2^56 ≈ 7.21e+16  按 10^9 次/秒 2.28e+00 年
    64 bit  空间 2^64 ≈ 1.84e+19  按 10^9 次/秒 5.85e+02 年
   128 bit  空间 2^128 ≈ 3.40e+38  按 10^9 次/秒 1.08e+22 年
```

按单机每秒 10 亿次算：40 bit 只要 18 分钟，56 bit 要 2.28 年，64 bit 要 585 年，128 bit 是天文数字。

注意这个估算是**单机**。56 bit 在 1998 年就被专用硬件 56 小时攻破了（EFF 的 Deep Crack），因为它能做到每秒上千亿次。所以 2.28 年这个数字说明的不是「DES 还挺安全」，而是「用通用计算机算不出来，但专用硬件可以」——这正是 DES 被淘汰的原因。

**判断密钥长度够不够，要按攻击者的能力上限算，不是按自己的机器算。**现在 128 bit 是底线，因为即使算力提升 10⁹ 倍，128 bit 仍需 10¹³ 年。

## 八、DES 和 AES 的分野

DES 用 Feistel，AES 用 SPN（代换-置换网络）。两者的差别不在安全强度，而在设计取舍：

| 维度 | Feistel（DES） | SPN（AES） |
|---|---|---|
| 加解密实现 | 同一套，轮密钥逆序 | 需要逆运算（逆 S 盒、逆列混合） |
| 轮函数要求 | 可逆不可逆都行 | 每一步必须可逆 |
| 每轮处理范围 | 只改一半数据 | 改全部数据 |
| 达到充分扩散所需轮数 | 多（16 轮） | 少（10–14 轮） |
| 硬件实现 | 面积小 | 面积大 |

Feistel 的每一轮只改一半数据，所以扩散慢，要多堆轮数；SPN 每轮改全部数据，扩散快，轮数少，但每一步都得是双射，逆运算也必须实现。

**「加解密共用一套」省下的是实现成本，付出去的是轮数。**这笔账在 1970 年代（硬件昂贵）划得来，到今天（硬件便宜、吞吐要求高）就未必了——AES 有硬件指令集支持后，逆运算的开销可以忽略。

## 九、小结

- **Feistel 每轮只做两件事**：$F(R_i, K_i)$ 异或到左半段，然后左右交换。解密是同一套流程加轮密钥逆序。
- **不需要 F 可逆**，靠的是异或自逆加「另一半数据没被改」。实测用平方函数（$f(0) = f(65536)$）照样完整往返。
- **雪崩不是单调的**：改 1 bit，差异从 20 冲到 40 再回落到 32（块长一半）。「轮数够多」是为了收敛到一半，不是越过半越好。
- **ECB 会泄漏结构**：三个相同明文块出三份相同密文。CBC 靠异或前一块（首块用 IV）打破这个规律，代价是加密不能并行。
- **密钥长度要按攻击者算力估**：56 bit 单机 2.28 年，专用硬件 56 小时——所以 DES 退场。128 bit 是现在的地板。
- **Feistel 与 SPN 是取舍不是优劣**：前者省实现（一套代码）、费轮数；后者快扩散、但要实现逆运算。AES 选了后者。
