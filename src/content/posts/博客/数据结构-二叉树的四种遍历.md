# 二叉树的四种遍历：递归和迭代的差别不在速度

二叉树的遍历是算法面试里出现频率最高的题，也是「背模板」最严重的题。但模板之外有三个问题几乎没人讲清：

1. 递归版和迭代版**到底差在哪**？（很多人以为是速度，实测差 10%~30%，可以忽略）
2. 前序迭代为什么一定要**先压右孩子**？
3. 层序用 `list.pop(0)` 当队列，为什么会慢 1300 倍？

这篇把四种遍历的递归、迭代、以及 O(1) 空间的 Morris 遍历放在一起，全部实测。

## 一、四种遍历只差「根在哪」

| 遍历 | 顺序 | 一句话用途 |
| :--- | :--- | :--- |
| 前序 Preorder | 根 → 左 → 右 | 复制树、序列化、打印目录结构 |
| 中序 Inorder | 左 → 根 → 右 | **BST 得升序**、表达式树求值 |
| 后序 Postorder | 左 → 右 → 根 | 删除树、自底向上算 |
| 层序 Level | 逐层，从左到右 | 最短路径、右视图、按层统计 |

前三种是**深度优先**（DFS），差别只在「访问根」这一步放在递归的哪个位置：

```python
def pre(x):   # 前序
    if not x: return
    visit(x)          # 根在最前
    pre(x.left); pre(x.right)

def ino(x):   # 中序
    if not x: return
    ino(x.left)
    visit(x)          # 根在中间
    ino(x.right)

def post(x):  # 后序
    if not x: return
    post(x.left); post(x.right)
    visit(x)          # 根在最后
```

**就这一个位置差异**，决定了用途完全不同：中序能把 BST 变有序（因为「左 < 根 < 右」正好被展开成升序）；后序适合「先处理孩子再处理自己」（删除树必须先删孩子，否则父结点没了找不到孩子）。

层序是**广度优先**（BFS），用队列而不是栈，所以它的代码结构和前三种完全不同。

## 二、前序：迭代为什么先压右孩子

递归版就是上面那三行。迭代版靠一个栈模拟系统调用：

```python
def pre_iter(root):
    if not root:
        return []
    res, stack = [], [root]
    while stack:
        node = stack.pop()
        res.append(node.val)      # 弹出即访问
        if node.right:            # 先压右
            stack.append(node.right)
        if node.left:             # 再压左
            stack.append(node.left)
    return res
```

**为什么先压右、再压左？** 因为栈是后进先出：后压进去的先出来。想让左子树先被处理，就得让它**后**压进去。写反了，输出就变成「根 → 右 → 左」，那不是前序。

这个「压栈顺序和输出顺序相反」的直觉，是理解所有迭代遍历的钥匙。

## 三、中序：BST 的排序器

### 迭代模板（最值得背的一个）

```python
def in_iter(root):
    res, stack = [], []
    cur = root
    while stack or cur:
        while cur:                # 一路向左，把沿途全部压栈
            stack.append(cur)
            cur = cur.left
        node = stack.pop()        # 左到头了，弹出并访问
        res.append(node.val)
        cur = node.right          # 转去处理右子树
    return res
```

这个模板的精髓是**「先把左链全部压栈，再弹一个、转右」**。它同时解决了两个问题：

- 不用记「我现在该往哪走」——栈顶就是下一个该访问的结点；
- 右子树处理完后自然会回到上一层继续弹栈，不需要额外的回溯逻辑。

**这个模板是中序专属的**。前序可以用更简单的「弹出即访问」，后序需要额外标记，都不能直接套这个写法。

### 中序遍历 + BST = 升序

这是面试高频考点：判断一棵树是不是 BST，最稳的做法就是中序遍历看是否严格递增（比递归比较上下界更不容易写错）。

```python
def is_bst(root):
    prev = None
    for v in in_iter(root):
        if prev is not None and v <= prev:    # 必须严格递增
            return False
        prev = v
    return True
```

注意 `<=`：BST 一般不允许重复键，所以相等也算违反。

## 四、后序：最难的一种

后序的麻烦在于：弹出栈顶时，你**不知道它的右子树处理完没有**——如果还没处理，你就得先处理右子树再回来访问它。

### 双栈法：用「根右左」再反转

```python
def post_two_stacks(root):
    if not root:
        return []
    s1, s2 = [root], []
    while s1:
        node = s1.pop()
        s2.append(node)              # 按「根右左」收集
        if node.left:
            s1.append(node.left)     # 先压左
        if node.right:
            s1.append(node.right)    # 再压右（右先出）
    return [x.val for x in reversed(s2)]   # 反转 -> 左右根
```

思路很巧：先按「根 → 右 → 左」收集，再整体反转就得到「左 → 右 → 根」。**代价是多一个 O(n) 的栈**。

### 标记法：单栈 + 「访问过了吗」

```python
def post_marker(root):
    if not root:
        return []
    res, stack = [], [(root, False)]
    while stack:
        node, visited = stack.pop()
        if visited:
            res.append(node.val)          # 第二次弹出 -> 访问
            continue
        stack.append((node, True))        # 先把自己标记好放回去
        if node.right:
            stack.append((node.right, False))
        if node.left:
            stack.append((node.left, False))
    return res
```

每个结点被压两次、弹两次：第一次弹出时「把自己标记为已访问再放回去」，然后压右、压左；等孩子都处理完，它会第二次被弹出，这时候才真正访问。

**空间还是 O(h)**（栈里最多 2h 个元素），但省掉了第二个栈。实测比双栈略慢（多了一倍元组创建），见后面的表。

## 五、层序：队列，以及一个反直觉的递归写法

### 队列版（标准答案）

```python
from collections import deque

def level_order(root):
    if not root:
        return []
    res, q = [], deque([root])
    while q:
        node = q.popleft()
        res.append(node.val)
        if node.left:  q.append(node.left)
        if node.right: q.append(node.right)
    return res
```

### 需要「按层分组」时：先量一下队列长度

LeetCode 102 要求返回 `[[1], [2,3], [4,5,6,7]]` 这种按层嵌套的结构。做法是在每轮开始前记下 `len(q)`，这一轮只处理这么多个：

```python
def level_order_grouped(root):
    if not root:
        return []
    res, q = [], deque([root])
    while q:
        level = []
        for _ in range(len(q)):       # 关键：先固定这一层的数量
            node = q.popleft()
            level.append(node.val)
            if node.left:  q.append(node.left)
            if node.right: q.append(node.right)
        res.append(level)
    return res
```

如果写成 `while q: for node in q:` 就会边遍历边改队列，直接乱序甚至死循环。

### 递归版：DFS 的顺序 + 按层收集

层序居然能用递归写，而且不用队列——诀窍是**带着层号走**，遇到新层就开一个空列表：

```python
def level_recursive(root):
    res = []
    def dfs(node, level):
        if not node:
            return
        if level == len(res):        # 第一次到这一层
            res.append([])
        res[level].append(node.val)
        dfs(node.left, level + 1)
        dfs(node.right, level + 1)
    dfs(root, 0)
    return res
```

访问顺序其实是**前序**（一条道走到黑），但因为每个结点都记住了自己的层号，最后填出来的结构是「按层」的。这就是「**DFS 的遍历顺序 + 按层归档**」，理解了这一点，就不会觉得递归写层序很玄。

## 六、Morris 遍历：O(1) 空间的中序

前面所有实现的空间都是 O(h)。Morris 的思路很反叛：**把空着的右指针临时借来当「返回上一层的路」，用完再拆掉**。

```python
def morris_inorder(root):
    res, cur = [], root
    while cur:
        if cur.left is None:          # 没有左子树：访问，往右走
            res.append(cur.val)
            cur = cur.right
        else:
            prev = cur.left
            while prev.right and prev.right is not cur:
                prev = prev.right     # 找左子树的最右结点（中序前驱）
            if prev.right is None:
                prev.right = cur      # 建线索：让前驱指回自己
                cur = cur.left
            else:
                prev.right = None     # 拆线索：说明左子树走完了
                res.append(cur.val)
                cur = cur.right
    return res
```

每一步做两件事之一：

- **第一次到 cur**：找到左子树的最右结点 `prev`，把 `prev.right` 指向 `cur`（建线索），然后钻进左子树；
- **第二次到 cur**（从线索回来）：说明左子树已遍历完，此时拆掉线索、访问 cur、转右子树。

**代价**：每个结点要被访问两次（找前驱 + 遍历），所以常数项比普通迭代大；但空间是 **O(1)**，不占栈。适合「树极深、内存极紧」的场景。

## 七、实测：递归 vs 迭代 vs Morris

完美二叉树，2¹⁷−1 = 131,071 个结点，高度 17（单位 ms，重复三次取中位，波动约 ±20%）：

```text
前序-递归      10.3      前序-迭代       8.1
中序-递归      10.3      中序-迭代       8.6     中序-Morris   13.5
后序-递归      10.9      后序-双栈      11.1     后序-标记     16.0
层序-deque      9.5
```

### 结论 1：递归不比迭代慢多少

递归 10.3 ms vs 迭代 8.1 ms，差 **27%**。原因是 CPython 的函数调用虽然贵，但 `while stack` 循环里的 `append`/`pop`/属性访问也不便宜，两边的常数项被拉平了。

所以「递归慢所以要写迭代」在 Python 里是**伪命题**。真正让你必须写迭代的是下面这条。

### 结论 2：递归的硬伤是深度上限，不是速度

Python 默认递归上限是 **1000 层**。把上限设回默认值，拿斜树（每个结点只有右孩子）试：

```text
斜树 n=  500  递归 成功
斜树 n=  900  递归 成功
斜树 n= 1200  递归 抛 RecursionError
斜树 n= 5000  递归 抛 RecursionError
              迭代 全部成功（1200 / 5000 都没问题）
```

**1200 个结点的树就能把递归打崩**。而「1200 个结点」对一个链表式的数据结构来说小得可笑。这是工程上必须改用迭代的唯一硬理由。

（另注：递归深度等于树高。平衡树 h≈log₂n，1 万个结点也只有 14 层；但斜树 h=n，一千个结点就爆。）

### 结论 3：Morris 用空间换来的时间，不便宜

Morris 13.5 ms vs 普通迭代 8.6 ms，**慢 57%**。因为每个有左子树的结点都要额外走一遍「找前驱」的路，这部分开销摊下来接近翻倍。

所以 Morris 只在「内存真的不够」时才有意义——比如在 32 位嵌入式设备上遍历一棵极深的树。

## 八、层序的坑：队列别用 `list.pop(0)`

这是最容易踩、后果最大的一个坑。

```python
q = [root]
while q:
    node = q.pop(0)      # ← 每弹一个，整个列表前移一次
```

`list.pop(0)` 不是 O(1)，是 **O(n)**——它要把后面所有元素往前挪一格。用在 BFS 里，每次出队都要挪一遍，整体退化成 **O(n²)**。

实测（完美二叉树，结点数递增）：

```text
n=  16383  deque 1.78 ms    list.pop(0)    27.71 ms    慢   15.5 倍
n=  65535  deque 4.99 ms    list.pop(0)  1748.47 ms    慢  350.3 倍
n= 262143  deque 20.36 ms   list.pop(0) 26917.25 ms    慢 1322.1 倍
```

结点数涨 16 倍，差距从 15 倍涨到 1322 倍——**这就是 O(n) vs O(n²) 的形状**。26 万个结点要跑 27 秒，换成 `deque` 只要 20 毫秒。

`collections.deque` 的 `popleft()` 是 O(1)（双端链表 + 分块数组），**BFS 一律用它**。想用索引又想 O(1) 出队，也可以自己维护一个 `head` 指针：`q[head]; head += 1`，比 pop(0) 好但不如 deque。

## 九、还有三个容易说错的地方

### 1. 「前序 + 空标记」可以唯一反序列化

很多资料说「前序序列需要配合中序才能唯一确定二叉树」——这话对**不含空标记**的纯值序列是对的，但**带空标记的前序遍历足以唯一还原**：

```text
    1
   / \
  2   3     前序 + 空标记:  [1, 2, #, #, 3, #, #]   -> 唯一还原
```

因为空标记把「哪个位置没有孩子」写死了，左右归属不再有歧义。LeetCode 的序列化题（297）用的就是这一招。这和「前序 + 后序不能唯一还原」是两件不同的事——后者缺的是「左右归属」信息，而空标记恰好补上了这个信息。

### 2. 后序标记法的空间不是 O(1)

标记法看起来只用一个栈，很省。但栈里每个元素是 `(node, visited)` 元组，而且**每个结点会被压两次**，所以栈的峰值可以到 2h。它省的是「第二个栈」，不是「空间复杂度」——仍然是 O(h)，只是常数变大（实测比双栈慢 44%）。

### 3. 判断完全二叉树必须让空孩子也入队

```python
def is_complete(root):
    if not root:
        return True
    q = deque([root])
    seen_empty = False
    while q:
        x = q.popleft()
        if x is None:
            seen_empty = True
        else:
            if seen_empty:        # 空位之后还有结点 -> 不是完全二叉树
                return False
            q.append(x.left)      # 空孩子也要入队
            q.append(x.right)
    return True
```

写成「只入队非空孩子」的话，判的其实是「是不是满二叉树」——因为「缺在哪一层」这个信息被丢掉了。

## 十、小结

- **四种遍历只差「根在哪」**：前序根在前、中序中间、后序最后；层序是 BFS，结构完全不同。
- **前序迭代先压右、再压左**，因为栈后进先出。这个「压栈顺序 = 输出的反序」是所有迭代遍历的钥匙。
- **中序迭代模板**（一路向左压栈 → 弹一个 → 转右）最值得背，它是判断 BST 的基础。
- **后序必须知道「右子树处理完没有」**：双栈法用「根右左 + 反转」（多 O(n) 空间），标记法用「压两次」（仍 O(h)，但慢 44%）。
- **层序可以用递归写**：DFS 顺序 + 带层号归档。按层分组要在每轮前 `len(q)` 定量。
- **Morris 是 O(1) 空间**，靠临时改写右指针做线索；代价是慢 57%（每个结点多走一次找前驱）。
- **递归和迭代的实测差距只有 27%，不是性能问题**；真正的硬伤是 Python 默认 1000 层上限，**1200 个结点的斜树就抛 RecursionError**。
- **BFS 队列必须用 `deque`**：`list.pop(0)` 是 O(n)，26 万结点实测慢 **1322 倍**（27 秒 vs 20 毫秒）。
