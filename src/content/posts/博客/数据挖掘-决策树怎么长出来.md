# 决策树怎么长出来：三把尺子量同一次划分

决策树的生长过程极其朴素：每个节点挑一个属性、按某种方式把记录分两堆或几堆，递归下去直到分干净。真正有内容的是**凭什么挑这个属性**——同一个节点，用熵挑可能选 Outlook，用基尼挑可能选 Humidity。

本文用同一份 14 条天气记录（4 个属性、是否打球）把三把尺子都量一遍，数字全部来自实跑。会看到一个反直觉的地方：信息增益最偏爱「取值多」的属性，而补救它的增益率，其实也拦不住主键。

## 一、分类任务：给记录贴一个离散标签

分类的定义是确定对象属于哪个预定义的目标类。输入是一堆记录，每条记录写成 $(x, y)$：$x$ 是属性集合，$y$ 是类标号。

区分分类与回归只有一条线：**类标号必须是离散的**。预测房价是回归，预测「买/不买」是分类。

任务本身是学一个映射 $f: x \mapsto y$，学出来的 $f$ 叫分类模型，两个用途：描述性建模（解释什么因素导致什么结果）和预测性建模（对新记录打标签）。

标准流程三步：拿类标号已知的训练集建模型，再用类标号未知的检验集评估。评估靠混淆矩阵——把「真正、假正、真负、假负」四种情况数出来，准确率是 $(f_{11}+f_{00})/\text{总数}$，错误率是 $(f_{10}+f_{01})/\text{总数}$。

只看准确率会掉坑：99% 的样本是负类时，全判负类也能拿 99%。所以混淆矩阵必须一起看，正类的漏检（$f_{01}$）和误报（$f_{10}$）代价往往完全不对等。

## 二、Hunt 算法：建树只有两个问题

Hunt 算法的递归定义三句话：当前节点的记录全属同一类，就标成叶；否则选一个属性测试条件把记录分下去，对每个分支递归。

落到实现上只剩两个设计问题，其余都是细节：

- **怎么分**：为每种属性类型准备属性测试条件，再给一个客观度量比较不同测试的优劣。
- **什么时候停**：所有记录同类、或所有记录属性值相同、或没有属性可用了。

第一个问题就是后面七节的全部内容。第二个问题看似简单，实际决定了树会不会长成一棵「每条记录一个叶子」的废物——那是过拟合的极端形态。

## 三、第一把尺子：熵与信息增益

熵度量不确定性。对 $c$ 个类、第 $i$ 类占比 $p_i$：

$$Entropy(D) = -\sum_{i=1}^{c} p_i \log_2 p_i$$

14 条记录里 9 条打球、5 条不打，代入得 0.9403——这是根节点的「乱度」。熵为 0 表示全同类，为 1 表示二分类里各占一半。

信息增益是「分完之后乱度降了多少」：原本的熵，减去各子集按比例加权后的熵。谁降得多，谁就是好划分。

跑一遍四个属性，结果很清楚：

```python
import math
from collections import Counter

DATA = [
    ("Sunny", "Hot", "High", "Weak", "No"),
    ("Sunny", "Hot", "High", "Strong", "No"),
    ("Overcast", "Hot", "High", "Weak", "Yes"),
    ("Rain", "Mild", "High", "Weak", "Yes"),
    ("Rain", "Cool", "Normal", "Weak", "Yes"),
    ("Rain", "Cool", "Normal", "Strong", "No"),
    ("Overcast", "Cool", "Normal", "Strong", "Yes"),
    ("Sunny", "Mild", "High", "Weak", "No"),
    ("Sunny", "Cool", "Normal", "Weak", "Yes"),
    ("Rain", "Mild", "Normal", "Weak", "Yes"),
    ("Sunny", "Mild", "Normal", "Strong", "Yes"),
    ("Overcast", "Mild", "High", "Strong", "Yes"),
    ("Overcast", "Hot", "Normal", "Weak", "Yes"),
    ("Rain", "Mild", "High", "Strong", "No"),
]

def entropy(rows):
    n = len(rows)
    cnt = Counter(r[-1] for r in rows)
    return -sum((c / n) * math.log2(c / n) for c in cnt.values())

def parts_of(rows, idx):
    d = {}
    for r in rows:
        d.setdefault(r[idx], []).append(r)
    return d

def gain(rows, idx):
    n = len(rows)
    return entropy(rows) - sum(len(v) / n * entropy(v) for v in parts_of(rows, idx).values())

def iv(rows, idx):
    n = len(rows)
    return -sum((len(v) / n) * math.log2(len(v) / n) for v in parts_of(rows, idx).values())

print(f"Entropy(D) = {entropy(DATA):.4f}")
print(f"{'属性':<12}{'增益':>8}{'固有信息':>12}{'增益率':>10}")
for i, name in enumerate(["Outlook", "Temperature", "Humidity", "Windy"]):
    g, v = gain(DATA, i), iv(DATA, i)
    print(f"{name:<12}{g:>8.4f}{v:>12.4f}{g / v:>10.4f}")
```

```text
Entropy(D) = 0.9403
属性                增益        固有信息       增益率
Outlook       0.2467      1.5774    0.1564
Temperature   0.0292      1.5567    0.0188
Humidity      0.1518      1.0000    0.1518
Windy         0.0481      0.9852    0.0488
```

Outlook 胜出，湿度次之，温度几乎没用。这个结论和教科书一致：晴天多半不打、阴天全打，Outlook 一次就把集合劈得最开。

信息增益的缺点藏在它的构造里：它奖励「分完很纯」，而**取值越多越容易分得纯**。14 条记录用编号去分，每堆只有 1 条，纯度满分。

## 四、偏科：取值多的属性占便宜

给数据加一列「编号」，1 到 14 各不相同，再算一遍增益与增益率。增益率就是把增益除以划分本身的信息量（固有信息 $IV$）：

$$IV(D, A) = -\sum_v \frac{|D_v|}{|D|} \log_2 \frac{|D_v|}{|D|}, \qquad GainRatio = \frac{Gain}{IV}$$

```python
import math

base = -sum((c / 14) * math.log2(c / 14) for c in (9, 5))   # 9 正 5 负
g_id = base                       # 分成 14 个单条子集，每个子集熵为 0
v_id = math.log2(14)              # 14 个等大分支的固有信息
print(f"编号属性的增益   = {g_id:.4f}")
print(f"固有信息         = {v_id:.4f}")
print(f"增益率           = {g_id / v_id:.4f}")
print(f"Outlook 的增益率 = {0.2467 / 1.5774:.4f}")   # 沿用上一段的两个数
print(f"四个真实属性的平均增益 = {(0.2467 + 0.0292 + 0.1518 + 0.0481) / 4:.4f}")
```

```text
编号属性的增益   = 0.9403
固有信息         = 3.8074
增益率           = 0.2470
Outlook 的增益率 = 0.1564
四个真实属性的平均增益 = 0.1189
```

编号属性的增益 0.9403 是理论满分——它把集合分成了 14 个纯子集。增益率把它除以 3.8074 压到 0.2470，**但仍然高于 Outlook 的 0.1564**。

这就是教科书上常被略过的一句：C4.5 的增益率并不能自己解决主键问题。它的实际做法是先按「增益不低于平均值」粗筛一遍（这份数据平均 0.1189），可编号属性的增益是 0.9403，粗筛也拦不住它。

**真正拦住主键的是别的东西**：建树前剔除唯一标识类字段、限制叶节点最少样本数、事后剪枝。公式只是尺子，不是守门员。

## 五、第二把尺子：基尼不纯度

CART 不用熵，用基尼：从数据集里随机抽两个样本，类标号不一致的概率。

$$Gini(D) = 1 - \sum_{i=1}^{c} p_i^2$$

同样 14 条记录，$1 - (9/14)^2 - (5/14)^2 = 0.4592$。判定方向反过来了：熵和增益要**最大**，基尼要**最小**，因为它度量的是不纯度。

对比两者的手感：熵要算 $\log_2$，基尼只做平方和，计算量小一个量级；数值上基尼的最大值只有 0.5（二分类各半），比熵的 1 低。CART 全程用基尼，一路建二叉树。

选划分时看的不是单个子集的基尼，而是加权和：

$$Gini_{split} = \sum_v \frac{|D_v|}{|D|} Gini(D_v)$$

取加权和最小的那个划分点。

## 六、属性测试条件：四种属性四种分法

决策树要给每一类属性准备「怎么测」的表示方式，这决定了树是二叉树还是多叉树。

| 属性类型 | 测试条件 | 分支数 |
| :--- | :--- | :--- |
| 二元属性 | 真/假两个输出 | 2 |
| 标称属性 | 多路划分，或所有二元分组 | $k$ 或 $2^{k-1}-1$ 种候选 |
| 序数属性 | 允许分组，但必须保持顺序 | 2 或多路 |
| 连续属性 | $A < v$ 与 $A \ge v$，或区间 $v_i \le A < v_{i+1}$ | 2 或多路 |

标称属性那一格的 $2^{k-1}-1$ 是个组合数：$k$ 个取值分成两组、两组都非空，共有这么多分法。$k=3$ 时是 3 种，$k=4$ 时是 7 种。只产二叉树的算法必须把这些分组全试一遍。

序数属性那条限制容易被忽略：气温「低/中/高」不能分成「低+高」对「中」，那违背了有序性，树会长出无法解释的规则。

## 七、连续属性：排序取中点逐个试

连续值不能像标称值那样枚举，标准做法是「排序—取中点—逐个试」。候选点取相邻两值的中点，因为任意落在两值之间的阈值，划分结果完全一样，取中点作代表即可。

拿一张四行表走一遍：年龄 10、15 打「否」，20、25 打「是」：

```python
def gini(rows):
    n = len(rows)
    cnt = {}
    for r in rows:
        cnt[r[-1]] = cnt.get(r[-1], 0) + 1
    return 1 - sum((c / n) ** 2 for c in cnt.values())

cont = [(10, "No"), (15, "No"), (20, "Yes"), (25, "Yes")]
vals = [v for v, _ in cont]
for t in [(vals[i] + vals[i + 1]) / 2 for i in range(len(vals) - 1)]:
    left = [r for r in cont if r[0] <= t]
    right = [r for r in cont if r[0] > t]
    w = (len(left) * gini(left) + len(right) * gini(right)) / len(cont)
    print(f"t={t:>5}  左 {len(left)} 条 右 {len(right)} 条  加权基尼 = {w:.4f}")
```

```text
t= 12.5  左 1 条 右 3 条  加权基尼 = 0.3333
t= 17.5  左 2 条 右 2 条  加权基尼 = 0.0000
t= 22.5  左 3 条 右 1 条  加权基尼 = 0.3333
```

17.5 是完美划分：左边全是「否」，右边全是「是」，加权基尼为 0。另外两个点各自剩下一条异类，都是 0.3333。

这条流程的代价是 $O(n \log n)$ 的排序加上 $O(n)$ 个候选点，每个点都要重算一次不纯度。属性多、样本多时这是建树的主要开销，所以工程实现通常维护「排序后的前缀类别计数」，让每个候选点的评估降到 $O(1)$。

## 八、朴素贝叶斯：另一条路

同一份数据换种思路：不算纯度，直接算概率。贝叶斯定理给出

$$P(Y|X) = \frac{P(Y)\,P(X|Y)}{P(X)}$$

分母对所有类都一样，比较时可以扔掉，只比分子 $P(Y)\prod_i P(X_i|Y)$。朴素的地方在于那个乘积——**它假设各属性在给定类标号下条件独立**，这个假设在真实数据里几乎总不成立，但分类效果常常还行。

条件概率靠计数估：类 $y$ 中取值 $x_i$ 的样本数除以类 $y$ 的样本总数。问题是某个取值一次都没出现时概率为 0，一乘就把整个后验清零。m 估计解决这个：

$$P(x_i|y) = \frac{n_c + m p}{n + m}$$

$n$ 是类 $y$ 的样本数，$n_c$ 是其中取 $x_i$ 的样本数，$p$ 是该属性的先验（通常取 $1/\text{取值个数}$），$m$ 是等价样本大小。

预测「Sunny / Cool / High / Strong」这条记录，$m$ 取 2，$p$ 取各属性取值个数的倒数（Outlook、Temperature 是 $1/3$，Humidity、Windy 是 $1/2$）：

```python
# 只留计数：类 -> (该类样本数, 每个属性各取值的出现次数)
stat = {
    "Yes": (9, [{"Sunny": 2, "Overcast": 4, "Rain": 3}, {"Hot": 2, "Mild": 4, "Cool": 3},
                {"High": 3, "Normal": 6}, {"Weak": 6, "Strong": 3}]),
    "No":  (5, [{"Sunny": 3, "Overcast": 0, "Rain": 2}, {"Hot": 2, "Mild": 2, "Cool": 1},
                {"High": 4, "Normal": 1}, {"Weak": 2, "Strong": 3}]),
}
test = [("Sunny", 3), ("Cool", 3), ("High", 2), ("Strong", 2)]   # (取值, 该属性取值个数)
m = 2
for cls, (n, counts) in stat.items():
    score = n / 14
    for (val, nv), c in zip(test, counts):
        score *= (c.get(val, 0) + m * (1 / nv)) / (n + m)
    print(f"{cls}: 后验分子 = {score:.6f}")
```

```text
Yes: 后验分子 = 0.006869
No: 后验分子 = 0.018180
```

判「不打」，约为「打」的 2.6 倍。这条记录在树里会走 Sunny→High 落到「否」，两条路的结论一致——一棵树和一次概率乘法，最终在做同一件事：找在给定属性下最可能的类。

## 九、什么时候停

停止条件写起来只有三种：全同类、属性用尽、所有记录属性值相同。但真正的树不会长到这一步，因为长到底一定过拟合——每个叶子只剩一条训练记录，训练集准确率 100%，检验集一塌糊涂。

现实中的刹车有四样：限制树的深度、要求叶节点最少样本数、要求划分带来的增益超过阈值、长完再剪枝。前三个在建树时拦，第四个建完回头砍。

评估时回到混淆矩阵：准确率回答「多少判对了」，但不回答「哪类判错了」。正负类代价不对称时（漏诊 vs 误诊），该看的是漏检率和误报率，而不是总体准确率。

## 十、小结

- **分类与回归的分界只有一条**：类标号必须离散。模型两种用途——描述性建模解释成因，预测性建模给新记录打标签。
- **建树只回答两个问题**：怎么分（属性测试条件 + 客观度量）、什么时候停。其余都是细节。
- **熵度量乱度**：14 条 9 正 5 负时熵为 0.9403；信息增益是「分完乱度降多少」，Outlook 拿 0.2467 最高，Temperature 只有 0.0292。
- **信息增益偏爱取值多的属性**：编号属性增益拿满 0.9403；增益率除以固有信息 3.8074 压到 0.2470，**仍高于 Outlook 的 0.1564**。拦主键靠剔除字段、最小叶样本与剪枝，不靠公式。
- **基尼是另一把尺子**：$1-\sum p_i^2$，同数据得 0.4592，方向相反要求最小，不做对数所以更快，CART 全程用它建二叉树。
- **四种属性四种分法**：二元两路，标称 $k$ 路或 $2^{k-1}-1$ 种二分，序数分组不能破坏顺序，连续属性用 $A < v$ 与 $A \ge v$。
- **连续属性排序取中点逐个试**：10/15/20/25 三个候选点加权基尼 0.3333、0、0.3333，17.5 是完美划分。
- **朴素贝叶斯用条件独立把联合概率拆成乘积**，再乘先验比大小；m 估计化解零概率，$m=2$ 时「不打」0.0182 对「打」0.0069。
- **停止条件决定树的质量**：深度上限、最小叶样本、增益阈值、事后剪枝，四样刹车缺一样都可能长成过拟合的树。
