# BI 入门：指标体系、分析方法与 Tableau 落地

「帮我搭一套指标体系」「这个指标跌了怎么办」——这两句话几乎覆盖了数据岗面试的一半。它们看起来是两个问题，其实是同一条链路上的两个环节：**先有指标口径，才能谈异动分析**。

这篇把三件事串起来：指标体系（定什么、怎么拆）、分析方法（跌了怎么查）、Tableau（怎么摆到看板上）。文中的指标数字都是用 `sprint_sql` 的真实表算出来的，不是举例。

## 一、BI 的三层链路

```text
指标定义  →  分析方法  →  工具落地
（定什么）    （怎么查）    （怎么给人看）
```

三段是接力关系，缺一段就断：

| 环节 | 产出 | 缺了会怎样 |
| :--- | :--- | :--- |
| 指标定义 | 口径清晰的指标树 | 数字一堆，但没人说得清「正确率」的分子分母是什么 |
| 分析方法 | 从异动到原因的路径 | 看到指标跌了，只会说「跌了」，说不清为什么 |
| 工具落地 | 可下钻的仪表板 | 分析结论停在文档里，业务看不到、用不上 |

三者的分工可以一句话概括：**指标体系负责「说同一门语言」，分析方法负责「顺着语言找原因」，Tableau 负责「把语言画出来」**。

## 二、北极星指标：一个数字锚住方向

北极星指标（North Star Metric）是**能最准确反映产品核心价值、并驱动长期增长的那一个数字**。注意它不是一个加总，也不是「注册用户数」这类只涨不跌的数字。

### 五个特征

- **唯一性**：全公司围绕一个，不是并列三个。
- **可量化**：能持续追踪。
- **用户价值导向**：反映用户真的获得了什么，而不是虚荣指标。
- **驱动长期增长**：提升它能带动收入与留存。
- **可拆解**：能分到部门、分到环节，否则无法组织协同。

### OMA 原则：怎么选

| 字母 | 含义 | 判断问法 |
| :--- | :--- | :--- |
| **O**utcome | 体现核心价值 | 这个数字涨了，用户是更受益了，还是只是我们更热闹了？ |
| **M**easurable & Actionable | 团队可控 | 产品和运营的动作能影响它吗？ |
| **A**head of revenue | 收入先导 | 它是收入的**领先**指标吗（而不是收入本身）？ |

经典例子：Airbnb 看**预订间夜数**（不是注册数）、Spotify 看**听歌总时长**、滴滴看**完成订单数**。放到做题平台上，北极星应该是**有效答题数**或**完课率**，而不是 DAU 或累计注册量——后者涨了不代表用户学到了东西。

## 三、AARRR：把用户旅程拆成五段

AARRR 是**获取 → 激活 → 留存 → 收益 → 传播**，每段回答一个不同的问题。

用 `funnel_event`（500 个用户、1349 条事件）实算一遍：

```sql
WITH s AS (
  SELECT COUNT(DISTINCT CASE WHEN event_name='register'        THEN user_id END) AS 获取,
         COUNT(DISTINCT CASE WHEN event_name='activate'        THEN user_id END) AS 激活,
         COUNT(DISTINCT CASE WHEN event_name='first_answer'    THEN user_id END) AS 首次答题,
         COUNT(DISTINCT CASE WHEN event_name='submit_homework' THEN user_id END) AS 提交作业,
         COUNT(DISTINCT CASE WHEN event_name='pay'             THEN user_id END) AS 付费
  FROM funnel_event
)
SELECT '获取' AS 阶段, 获取 AS 人数 FROM s
UNION ALL SELECT '激活',     激活     FROM s
UNION ALL SELECT '首次答题', 首次答题 FROM s
UNION ALL SELECT '提交作业', 提交作业 FROM s
UNION ALL SELECT '收益',     付费     FROM s;
```

实测结果：

```text
阶段	人数	相对上一步
获取(Acquisition) 注册用户	500	—
激活(Activation) 激活用户	356	71.2%
首次答题（关键行为）	262	73.6%
提交作业（深度使用）	152	58.0%
收益(Revenue) 付费用户	79	52.0%
```

这张表已经能直接回答产品会议上的三个问题：**漏斗哪一段最「漏」**（提交作业这一段只留下 58%）、**整体转化是多少**（500 → 79，15.8%）、**哪一段的绝对流失人数最多**（首次答题到提交作业，掉了 110 人）。

各阶段的典型指标：

| 阶段 | 一句话锚点 | 关键指标 | 本库能否算 |
| :--- | :--- | :--- | :--- |
| 获取 | 人从哪来 | DNU（日新增用户） | ✅ 500 |
| 激活 | 来了用没用 | DAU / WAU / MAU、DAU÷MAU（粘性）、日均时长 | ✅ 356 |
| 留存 | 还回不回来 | N 日留存率、N 级流失率 | ✅ 有 `daily_login` |
| 收益 | 赚不赚钱 | 付费率 → ARPU → ARPPU → LTV | ⚠️ 有付费人无金额 |
| 传播 | 带不带新 | K 因子 = 人均邀请数 × 邀请转化率 | ❌ 无邀请数据 |

最后两行要特别注意：**「算不出来」和「算出来是 0」是两件事**。没有金额字段就写「当前口径无法计算」，不能填 0——那会让人以为真的没人付费。这种诚实是数据岗的基本素养。

两个指标的用法也要说清：

- **DAU/MAU（粘性）** 越高说明用户越「天天回来」，但这个值低**不能直接断定产品失败**——定期理财、求职、买房租房类产品天然低频，得结合产品属性、工作日 / 假期、版本节奏一起看。
- **K 因子**大于 1 才是自增长（每个用户带来超过 1 个新用户），小于 1 意味着增长停下来就得靠投放续命。

## 四、指标分层与四维拆解

指标体系不是一堆指标的列表，而是**一棵可下钻的树**。

### 三个层次

| 层次 | 回答什么 | 做题平台示例 |
| :--- | :--- | :--- |
| 一级（结果指标） | 业务目标达成没有 | 有效答题数、完课率 |
| 二级（过程指标） | 目标由哪些环节构成 | 活跃学员数 × 人均答题量 |
| 三级（诊断指标） | 环节为什么波动 | 各渠道新增、各学科答题量、正确率分布、7 日留存 |

从 `v_answer_detail`（800 条答题记录、40 名学生、30 天）算一级指标：

```sql
SELECT COUNT(*) AS 答题量,
       COUNT(DISTINCT student_id) AS 活跃学员,
       ROUND(SUM(is_correct) / COUNT(*) * 100, 1) AS 平均正确率,
       COUNT(DISTINCT dt) AS 有数据天数
FROM v_answer_detail;
```

```text
答题量	活跃学员	平均正确率	有数据天数
800	40	68.8	30
```

按学科下钻（这是三级指标的位置）：

```text
学科	答题量	正确率
计算机网络	132	72.0
数据结构	119	71.4
数据库系统	145	68.3
数据挖掘	152	67.8
操作系统	127	66.9
算法设计与分析	125	66.4
```

六个学科的正确率在 66.4% ~ 72.0% 之间，极差只有 5.6 个百分点——这说明**从学科维度看不出明显问题**，继续拆下去也挖不到什么。这时候正确的动作是换维度（按班级、按难度、按时间），而不是硬解释这 5 个点的差距。

### 四种拆解维度

| 维度 | 用来回答 |
| :--- | :--- |
| 时间 | 日 / 周 / 月、同比 / 环比、工作日 vs 周末 |
| 地域 | 省市、城市等级 |
| 渠道 | 自然流量 / 投放 / 推荐、iOS vs Android |
| 用户分层 | 新老用户、RFM、付费 vs 免费 |

面试时的标准答法：**「指标跌了」→ 先按时间定位异常区间 → 再按渠道 / 地域 / 用户分层下钻 → 锁定到具体环节**。这就是下一节要讲的归因套路。

### 一个反直觉的例子

按难度拆，得出的结果和我预期相反：

```text
难度	答题量	正确率
简单	369	68.8
中等	222	67.6
困难	209	69.9
```

**困难题的正确率（69.9%）反而高于中等题（67.6%）。** 这个结果不能当结论用，它是数据质量的信号——这份练习数据是模拟生成的，答题对错近似随机分配，所以三个难度的正确率都贴近 68.8% 的总体均值。

实战里遇到这类反直觉数字，正确顺序是先**核对口径与数据来源**（分子分母对不对、时间范围是否一致、数据是不是模拟的），再决定要不要往下解释。跳过这一步直接写「困难题学生掌握得更好」，就是典型的错误结论。

## 五、HEART 与好指标四标准

### HEART：补上体验维度

AARRR 偏增长链路，衡量的是「业务跑得快不快」；HEART 偏体验质量，衡量的是「用户用得爽不爽」。两者互补。

| 字母 | 维度 | 关注什么 |
| :--- | :--- | :--- |
| H | Happiness 愉悦度 | 满意度、NPS、易用性评分 |
| E | Engagement 参与度 | 使用频率、深度、时长 |
| A | Adoption 采用度 | 新功能 / 新用户的接受与使用率 |
| R | Retention 留存度 | 一段时间后是否还在用 |
| T | Task success 任务完成度 | 核心任务的成功率、耗时、出错率 |

### 好指标四标准

1. **战略对齐**：能回答关键业务问题，和北极星、OKR 强相关。
2. **可量化**：口径清晰、公式明确、数据源稳定。
3. **可拆解**：能按维度下钻，也能拆成驱动因子。
4. **可行动**：指标变化能触发具体动作，团队能影响它。

还有一条不写在教材里但更重要的：**不易被操纵**。Goodhart 定律说「一旦某个指标成为目标，它就不再是好指标」。

两个经典坏指标：

- **页面停留时长**：挂机、误触、找不到入口都会把它拉长。这个数越高，未必体验越好。
- **累计下载量 / 累计注册数**：只涨不跌，永远不会「变差」，也就永远不会推动任何决策。

判断坏指标有个简单问法：**这个数字有没有可能变差？** 如果它只会涨，它就是虚荣指标。

## 六、四种分析方法：一条完整链路

四个方法不是并列选项，而是**接力顺序**：

```text
对比（发现异动） → 拆解（定位环节） → 归因（量化贡献） → 分群（落到"对谁做什么"）
```

| 方法 | 一句话 | 核心问题 | 关键原则 |
| :--- | :--- | :--- | :--- |
| 对比 | 建立参照系 | 好不好？和谁比？差多少 | 口径必须一致 |
| 拆解 | 把大指标拆成可行动的小指标 | 问题出在哪 | MECE、可行动、不过度拆 |
| 归因 | 变化由哪些因素驱动，各贡献多少 | 为什么变 | 相关 ≠ 因果，防辛普森悖论 |
| 分群 | 不同群体规律不同 | 谁不一样 | 组间差异大、组内相似、可触达 |

### 对比：单个数字没有意义

「今天卖了 100 万」是好是坏？必须放进参照系。五种常用参照：时间（同比 / 环比）、空间（地区 / 渠道）、目标（KPI 达成率）、竞争（行业大盘）、实验（A/B）。

三个易错点：**口径必须一致**（分母、时间范围、统计人群不同就不可比）；**绝对差异和相对差异都要看**（10 万跌到 9 万是 -10%，1 万跌到 0 是 -100%）；**判断显著性**（样本太小时差异可能只是噪音）。

### 拆解：拆到「能对应一个动作」为止

三种拆法：

```text
① 公式拆解：GMV = 流量 × 转化率 × 客单价
             转化率 = 加购率 × 下单率 × 支付率
② 维度拆解：按地区 / 渠道 / 品类 / 新老客下钻
③ 流程拆解：曝光 → 点击 → 加购 → 下单 → 支付，看哪一步流失率异常
```

三条原则：**MECE**（不重不漏）、**可行动**（拆到能采取措施的粒度）、**避免过度拆解**（拆太细样本不足，噪音盖过信号）。

### 归因：别把相关当因果

核心公式是贡献度拆解：

```text
贡献度 = 某子项变化量 / 总体变化量 × 100%
```

拆法有加法归因（总体 = A + B + C）、乘法归因（GMV = 流量 × 转化率 × 客单价）、漏斗归因（定位到具体步骤）。要做「因果」而不只是「相关」，得上 A/B 实验、DID、PSM。

**辛普森悖论**是最该警惕的陷阱：整体趋势和每个分群的趋势可能完全相反。经典场景是「A 方案整体转化率更高，但在每个渠道里都更低」——因为 A 方案的流量集中在转化率天然高的渠道。**只看整体平均，就会选错方案。**

### 分群：落到「对谁做什么」

常见维度：用户（RFM、生命周期、价值分层）、商品（ABC 分类、毛利）、渠道（ROI、转化质量）、地区（城市等级）。

四条判据：**组间差异大、组内相似、规模足够、可识别可触达**。最后一条最容易被忽略——分出一个「沉默的潜在高价值用户」群体却没有触达渠道，那这个分群只是好看。

### 串起来看

一个完整的例子：

1. **对比**：GMV 环比下降 10%
2. **拆解**：按渠道、新老客、品类下钻，发现抖音新客下降最明显
3. **归因**：量化贡献——抖音新客转化率下降贡献了 -7%
4. **分群**：进一步看，抖音新客里「低活价格敏感人群」流失最大
5. **策略**：针对该人群做定向券、内容优化、落地页承接

这条链路能讲满 2 分钟，就是及格的面试回答。

## 七、Tableau：不是什么画图软件

Tableau 的定位是**拖拽式的可视化查询引擎**——每拖一个字段，背后就是一条聚合查询。所以学会了 SQL 的聚合逻辑，Tableau 的操作其实是「用鼠标写 SQL」。

### 维度 vs 度量：唯一必须先分清的一对概念

| 概念 | 定义 | 对应 SQL | 例子 |
| :--- | :--- | :--- | :--- |
| **维度** | 定性的、用来分组切分的字段 | `GROUP BY` 的列 | 学科、难度、日期、班级 |
| **度量** | 定量的、用来算的字段 | `SUM` / `AVG` 的对象 | 答题量、正确率、分数 |

口诀就是：**能拿来 `GROUP BY` 的是维度，能拿来 `SUM`/`AVG` 的是度量。**

### 蓝药丸与绿药丸

拖到行 / 列上的字段会呈蓝色或绿色，这是 Tableau 最大的初学坎：

| 药丸 | 类型 | 效果 | 例子 |
| :--- | :--- | :--- | :--- |
| 蓝 | 离散 | 生成表头 / 标签，每个值一格 | 离散的「天」、学科名 |
| 绿 | 连续 | 生成连续坐标轴 | 连续日期、度量值 |

关键点：**同一个字段可以既是蓝的又是绿的**。`日期` 拖成蓝色是「每天一根柱子」，拖成绿色是一条连续时间轴。做趋势图时日期一般用**离散「天」**，否则坐标轴会按跨度自动跳档、出现断档。

### 一个工作表 ≈ 一条查询

| Tableau 位置 | 对应 SQL |
| :--- | :--- |
| 行 / 列 上的维度 | `GROUP BY` |
| 标记卡上的聚合 | `SELECT SUM(...)` / `AVG(...)` |
| 筛选器 | `WHERE` |
| 计算字段 | `SELECT` 里的表达式 |

这个对应关系想通了，Tableau 就没有「玄学」了——出图不对，就是那条隐含的 SQL 写错了。

## 八、计算字段与 LOD：和窗口函数是同一件事

### 行级别 vs 聚合级别

- **行级别计算**：逐行算，结果还能再被聚合。例如 `[单价] * [数量]`，外面再套 `SUM`。
- **聚合级别计算**：直接给出聚合值。例如 `SUM([销售额]) / SUM([数量])`（加权平均单价）。

对照 SQL：行级别 ≈ 在 `SELECT` 里对列做运算；聚合级别 ≈ 对整列做 `SUM`/`AVG`。**最常犯的错是用「比率的平均值」代替「总和的比」**——两者在样本量不等时完全不同。

### LOD：指定粒度算聚合

LOD（Level of Detail）表达式用来在**指定粒度**上算聚合，这是和 SQL 窗口函数最像的部分：

| LOD | 含义 | 等价 SQL |
| :--- | :--- | :--- |
| `{FIXED [维度] : 聚合}` | 固定按该维度算，不受视图维度影响 | `SUM(...) OVER (PARTITION BY [维度])` |
| `{INCLUDE [维度] : 聚合}` | 在当前视图粒度上再加一个维度 | 在 `PARTITION BY` 里追加 |
| `{EXCLUDE [维度] : 聚合}` | 在当前视图粒度上去掉一个维度 | 从 `PARTITION BY` 里剔除 |

典型场景：算「各学科答题量占全平台的比例」。分母要用 `{FIXED : SUM([答题量])}`，否则分母会跟着视图里的学科一起变，算出来永远是 100%。

这正好对应 SQL 里那个经典坑——**忘写 `PARTITION BY` 会让数据串行**（在讲同环比那篇实测过）。两者的错误形态一模一样：分母 / 窗口范围没固定住。

### 表计算：在结果层再算一层

表计算（占比、同比、环比、移动平均、排名）是在**视图已经算出的结果**上再算，特点是**依赖视图里的维度顺序**。

一句话区分：**LOD 在数据层算（相当于进 SQL），表计算在结果层算（出图之后）。**

## 九、图表选型、仪表板结构与常踩的坑

### 选型速查

| 要表达 | 用什么 | 别用什么 |
| :--- | :--- | :--- |
| 比大小 | 条形图（横排，便于读数） | 饼图、雷达图 |
| 看趋势 | 折线图、面积图 | 堆太多系列的柱状图 |
| 看构成 | 堆叠条形图、树状图 | 饼图（超过 3 类就别用） |
| 看分布 | 直方图、箱线图 | 只给平均值（掩盖分布） |
| 看相关 | 散点图 | 双轴折线 |
| 看地理 | 地图 + 颜色深浅 | 3D 地图 |

### 仪表板的标准结构

```text
┌──────┬──────┬──────┬──────┐
│指标卡1│指标卡2│指标卡3│指标卡4│   ← 顶部：核心指标
├──────┴──────┴──────┴──────┤
│        趋势（时间对比）      │   ← 中部：看走势与异动
├─────────────┬─────────────┤
│ 分群（维度下钻）│  明细 / TopN │   ← 底部：定位「谁不一样」
└─────────────┴─────────────┘
```

这个结构不是审美选择，它**正好对应前面的方法论**：指标卡 = 指标体系的一级指标，趋势 = 对比分析，下钻 = 拆解与分群。看板的版式和分析的链路是同构的。

### 六个常踩的坑

| 坑 | 解法 |
| :--- | :--- |
| 日期轴出现断档 | 日期用离散「天」，不要连续 |
| 双轴数字对不上 | 量纲不同就别勾「同步轴」 |
| 显示 0.688 而不是 68.8% | 轴 / 标签右键 → 格式 → 数字 → 百分比 |
| TopN 全是 100% | 小样本虚高：加「样本量 ≥ N」门槛 |
| 连 MySQL 报驱动错误 | 装 **64 位** MySQL Connector/ODBC |
| 多表 JOIN 后数字被放大 | 先做成宽表视图再连 Tableau，避免笛卡尔积 |

第四个坑值得用真实数据看。把上面那张答题明细按「学科 × 难度」拆成 18 组，按正确率降序排：

```text
学科	难度	答题量	正确率
计算机网络	困难	27	85.2
数据结构	困难	24	75.0
操作系统	简单	39	71.8
算法设计与分析	中等	77	71.4
数据结构	中等	41	70.7
数据结构	简单	54	70.4
```

排第一的「计算机网络 - 困难」只有 **27 条**样本，正确率 85.2%，而该学科整体正确率是 72.0%。这时候把它当「最难的知识点学生反而掌握最好」是错的——**27 条样本的正确率波动极大，一个小样本组天然容易冲到榜首**。

（这份数据拆到 18 组后最小样本是 24 条，还没到「2 条样本 100%」的极端程度，所以这个坑在本库只是轻微显现。但在真实业务里，按渠道 × 城市 × 新老客层层下钻，很容易拆出几条样本的格子，那一栏必然是 0% 或 100%。）

根子上，这不是「图画错了」，而是**指标口径没定义好**——比率类指标必须同时说明样本量门槛。这才是数据分析师真正的价值点。

## 小结

- BI 的三段是接力：**指标定义 → 分析方法 → 工具落地**，缺一段链路就断。
- 北极星指标按 **OMA 原则**选：体现核心价值、团队可控、收入先导。做题平台该看「有效答题数」，不是 DAU。
- AARRR 五段能用真实数据算出：本库实测 500 → 356 → 262 → 152 → 79，整体转化 15.8%，最「漏」的一段是首次答题到提交作业（只留 58%）。
- 指标是**一棵可下钻的树**（一级结果 / 二级过程 / 三级诊断），配合时间、地域、渠道、用户分层四个维度拆解。学科维度实测极差只有 5.6 个点，说明该换维度而不是硬解释。
- 遇到反直觉数字（如困难题正确率反而最高）**先质疑口径与数据来源**，别急着下结论。
- 好指标四标准 + 一条隐藏标准：**不易被操纵**。判断坏指标的问法是「这个数有没有可能变差」。
- 四种分析方法是一条链：**对比找差异 → 拆解找位置 → 归因找原因 → 分群找策略**；归因要防「相关当因果」和辛普森悖论。
- Tableau 的核心就一对概念：**维度（`GROUP BY`）vs 度量（`SUM`/`AVG`）**；LOD ≈ 窗口函数的 `PARTITION BY`，表计算是结果层再算一层。
- 看板版式与分析方法同构：指标卡 → 趋势 → 下钻，正好对应一级指标 → 对比 → 拆解。
