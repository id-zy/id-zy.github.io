# 群组测试：一头猪凭什么能带 log₂(t+1) 比特

N 桶水，其中一桶有毒，你有 t 轮测试机会：每轮可以把任意多桶混起来喂给任意多头猪，喝到毒药的猪会在固定时间后死亡。问最少需要几头猪。

这题的答案短得不像话——`⌈log_{t+1} N⌉`。但那个底数 `t+1` 是从哪冒出来的，比答案本身值得说。它不是凑出来的常数，是「一头猪能记住几个结局」的直译。下面从结局空间推到编码构造，再跑一遍完整的 8 桶 2 轮，最后停在两处实测出来的坑上。

## 一、问题：轮次是个新维度

先把参数对齐。总可用时间 `minutesToTest`，喝下毒药后到死亡需要 `minutesToDie`，最多能跑几轮就定了：`t = minutesToTest // minutesToDie`。

一轮的定义是：把若干桶分配给若干头猪喝，等一个 `minutesToDie` 的时长，看谁死。死的猪退出后续轮次，活着的继续参加下一轮。

关键在于「继续」两个字。传统的一次性检测里——Dorfman 二战时筛梅毒用的就是那种——一个检测单元只输出一个二值结果，用掉就没了。这里的猪跨轮次存活，它在第一轮没死这件事本身就是一条信息：说明毒不在它第一轮喝过的那批桶里。**状态被记住了**，于是同一头猪在 t 轮里能连续给出 t 次回答，而且能用「第几轮才倒下」来区分不同的肯定回答。

## 二、一头猪的结局不是两种，是 t+1 种

把一轮一轮看下去，一头猪的完整履历只有这几种可能：第 1 轮后死、第 2 轮后死、……、第 t 轮后死、全程存活。

```python
for t in range(0, 5):
    outcomes = [f"第{k}轮死" for k in range(1, t + 1)] + ["全程存活"]
    print(f"t={t} 轮  结局 {len(outcomes)} 种  {outcomes}")
```

```text
t=0 轮  结局 1 种  ['全程存活']
t=1 轮  结局 2 种  ['第1轮死', '全程存活']
t=2 轮  结局 3 种  ['第1轮死', '第2轮死', '全程存活']
t=3 轮  结局 4 种  ['第1轮死', '第2轮死', '第3轮死', '全程存活']
t=4 轮  结局 5 种  ['第1轮死', '第2轮死', '第3轮死', '第4轮死', '全程存活']
```

`t` 轮就是 `t+1` 种结局。第一行那个 `t=0` 不是摆设，它说明「一轮都跑不了」时猪只有一种结局，携带的信息量为零。

结局数之所以重要，是因为它可以被当成一个**符号**来用。第 k 轮死是一个符号，全程存活是另一个符号，一共 `t+1` 个互不相同的符号。一头猪就是一个能取 `t+1` 个值的变量。

## 三、下界：(t+1)^x ≥ N

x 头猪的最终状态是一个向量 `(s₁, s₂, …, sₓ)`，每个分量取自 `{0, 1, …, t}`，这样的向量一共 `(t+1)^x` 个。要从 N 个桶里唯一确定毒药在哪，状态数就不能少于桶数。

```python
import math

def lower_bound(n, t):
    if n <= 1:
        return 0
    return math.ceil(math.log(n) / math.log(t + 1))

for n, t in ((1000, 1), (1000, 2), (1000, 3), (1000, 4), (8, 2), (1, 5)):
    x = lower_bound(n, t)
    cap = (t + 1) ** x
    print(f"N={n:<5} t={t}  下界 x={x}  (t+1)^x={cap:<10} 容量够={cap >= n}")
```

```text
N=1000  t=1  下界 x=10  (t+1)^x=1024       容量够=True
N=1000  t=2  下界 x=7  (t+1)^x=2187       容量够=True
N=1000  t=3  下界 x=5  (t+1)^x=1024       容量够=True
N=1000  t=4  下界 x=5  (t+1)^x=3125       容量够=True
N=8     t=2  下界 x=2  (t+1)^x=9          容量够=True
N=1     t=5  下界 x=0  (t+1)^x=1          容量够=True
```

换成信息论的说法是同一句话：确定毒药在哪桶需要 `log₂N` 比特，一头猪最多提供 `log₂(t+1)` 比特（它有 `t+1` 种等概率结局），相除就是下界 `x ≥ log₂N / log₂(t+1) = log_{t+1}N`。

第一行 `N=1000, t=1` 是 10 头，对应 `2¹⁰ = 1024`——就是熟悉的二进制编码，多出来的 24 个状态是浪费的；最后一行 `N=1` 给 0 头，因为只有一桶时不需要测。

## 四、构造：把桶编号写成 (t+1) 进制

下界能取到，靠的是一个构造：把桶的十进制编号改写成 x 位的 `(t+1)` 进制数，让第 i 头猪负责第 i 位。

```python
def encode(idx, t, x):
    digits = []
    for _ in range(x):
        digits.append(idx % (t + 1))
        idx //= (t + 1)
    return list(reversed(digits))          # 高位在前

n, t, x = 8, 2, 2
for idx in range(n):
    print(f"桶 {idx}: base-{t+1} 编码 {encode(idx, t, x)}")
```

```text
桶 0: base-3 编码 [0, 0]
桶 1: base-3 编码 [0, 1]
桶 2: base-3 编码 [0, 2]
桶 3: base-3 编码 [1, 0]
桶 4: base-3 编码 [1, 1]
桶 5: base-3 编码 [1, 2]
桶 6: base-3 编码 [2, 0]
桶 7: base-3 编码 [2, 1]
```

喂食规则一句话：**第 i 头猪，在第 k 轮，喝所有「第 i 位编码等于 k」的桶**。第 i 位等于 0 的桶这头猪全程不喝，所以它存活；等于 k 的桶它恰好第 k 轮喝到，于是第 k 轮后死。死在第几轮，直接就是那一位数字。

这里有个容易漏掉的性质：整张喂食表在第一次喂之前就完全定好了，中途不根据结果调整，这叫**非自适应**。自适应方案（看到结果再决定下一轮怎么分）能做到同样好，但非自适应的优势是可以并行——所有轮次的准备一次性做完，不必等上一轮出结果。现实里的池检测要的正是这个。

## 五、跑一遍：8 桶、2 轮、2 头猪

按上面的规则生成喂食表，再让毒药依次进每个桶，看状态能不能反推回来：

```python
def encode(idx, t, x):
    digits = []
    for _ in range(x):
        digits.append(idx % (t + 1))
        idx //= (t + 1)
    return list(reversed(digits))

def simulate(poison, t, x, table):
    status = []
    for p in range(x):
        died = 0
        for k in range(t):
            if poison in table[p][k]:
                died = k + 1
                break
        status.append(died)              # 0 = 存活
    return status

def decode(status, t):
    idx = 0
    for s in status:                     # 高位在前
        idx = idx * (t + 1) + s
    return idx

n, t, x = 8, 2, 2
table = [[[] for _ in range(t)] for _ in range(x)]      # table[猪][轮] = 桶列表
for idx in range(n):
    for p, d in enumerate(encode(idx, t, x)):
        if d >= 1:
            table[p][d - 1].append(idx)

for p in range(x):
    for k in range(t):
        print(f"猪{p+1} 第{k+1}轮 喝 {table[p][k]}")

print()
ok = 0
for poison in range(n):
    st = simulate(poison, t, x, table)
    got = decode(st, t)
    ok += (got == poison)
    print(f"毒在桶{poison} -> 猪状态 {st} -> 解码 {got}  {'✓' if got == poison else '✗'}")
print(f"全部还原正确: {ok}/{n}")
```

```text
猪1 第1轮 喝 [3, 4, 5]
猪1 第2轮 喝 [6, 7]
猪2 第1轮 喝 [1, 4, 7]
猪2 第2轮 喝 [2, 5]

毒在桶0 -> 猪状态 [0, 0] -> 解码 0  ✓
毒在桶1 -> 猪状态 [0, 1] -> 解码 1  ✓
毒在桶2 -> 猪状态 [0, 2] -> 解码 2  ✓
毒在桶3 -> 猪状态 [1, 0] -> 解码 3  ✓
毒在桶4 -> 猪状态 [1, 1] -> 解码 4  ✓
毒在桶5 -> 猪状态 [1, 2] -> 解码 5  ✓
毒在桶6 -> 猪状态 [2, 0] -> 解码 6  ✓
毒在桶7 -> 猪状态 [2, 1] -> 解码 7  ✓
全部还原正确: 8/8
```

八桶水、两头猪、两轮。第 1 头猪管高位，第 2 头管低位。桶 0 谁都不喝——它的编码是 `[0, 0]`，两头猪全程喝不到它，所以两头都存活时答案就是桶 0。

解码就是把状态向量当成一个 `(t+1)` 进制数读回来——`[1, 2]` 读作 `1×3 + 2 = 5`，正好是桶 5。编码和解码是同一次进制转换的正反两向，中间没有查表。

## 六、多出来的信息，是拿时间换的

从桶数看：固定 t，x 头猪能区分的桶数是 `(t+1)^x`，单轮是 `2^x`。底数从 2 涨到 `t+1`，是指数的底在变，不是指数在变。从比特看，每头猪能带多少直接由结局数决定。两件事写在同一段代码里：

```python
import math

def lower_bound(n, t):
    if n <= 1:
        return 0
    return math.ceil(math.log(n) / math.log(t + 1))

N = 1000
base = lower_bound(N, 1)
print(f"N={N} 单轮需要 {base} 头")
for t in range(1, 8):
    x = lower_bound(N, t)
    print(f"t={t}  x={x}  比单轮少 {base - x} 头  降幅 {(base - x) / base:.0%}")

print()
for t in (1, 2, 3, 4, 7):
    bits = math.log2(t + 1)
    print(f"t={t} 结局 {t+1} 种  每头猪 {bits:.3f} 比特  是单轮的 {bits:.3f} 倍")
```

```text
N=1000 单轮需要 10 头
t=1  x=10  比单轮少 0 头  降幅 0%
t=2  x=7  比单轮少 3 头  降幅 30%
t=3  x=5  比单轮少 5 头  降幅 50%
t=4  x=5  比单轮少 5 头  降幅 50%
t=5  x=4  比单轮少 6 头  降幅 60%
t=6  x=4  比单轮少 6 头  降幅 60%
t=7  x=4  比单轮少 6 头  降幅 60%

t=1 结局 2 种  每头猪 1.000 比特  是单轮的 1.000 倍
t=2 结局 3 种  每头猪 1.585 比特  是单轮的 1.585 倍
t=3 结局 4 种  每头猪 2.000 比特  是单轮的 2.000 倍
t=4 结局 5 种  每头猪 2.322 比特  是单轮的 2.322 倍
t=7 结局 8 种  每头猪 3.000 比特  是单轮的 3.000 倍
```

两处值得停一下。一是只多给一轮（t 从 1 到 2），猪就从 10 头降到 7 头，砍掉三成。二是它不连续：`t=3` 和 `t=4` 都是 5 头，`t=5` 才掉到 4 头。因为 `⌈log N⌉` 是阶梯函数，轮次加成要攒够一整层才体现得出下一级台阶——以为「多加一轮就必然少一头」会算错。

`t=3` 时结局正好 4 种，一头顶两头用；`t=7` 时结局 8 种，一头顶八头。这些数字很漂亮，但别看成白捡的便宜——**它是拿时间买的**。`t=3` 意味着测试要跑满三个 `minutesToDie` 的周期，单轮只要一个。所以选轮次从来不是在优化「猪数」这一个量：猪便宜而时间贵（疫情流调要快）就该压 t，猪贵而时间松（药物初筛里细胞系很稀缺，实验周期本就以周计）才值得加 t。

## 七、浮点会多算一头

上面所有结论都建立在 `⌈log_{t+1}N⌉` 上。写成代码，习惯的写法是 `math.ceil(math.log(n) / math.log(t + 1))`。这个写法在边界上会出错。

```python
import math

def ceil_int_log(n, base):
    x, p = 0, 1
    while p < n:
        p *= base
        x += 1
    return x

bad = []
for n in range(2, 20000):
    for t in range(1, 6):
        f = math.ceil(math.log(n) / math.log(t + 1))
        e = ceil_int_log(n, t + 1)
        if f != e:
            bad.append((n, t, f, e))
print(f"扫 N=2..19999 × t=1..5 共 {19998 * 5} 组，浮点与整数版不一致 {len(bad)} 组")
print("前 5 组 (N, t, 浮点, 整数):", bad[:5])
```

```text
扫 N=2..19999 × t=1..5 共 99990 组，浮点与整数版不一致 3 组
前 5 组 (N, t, 浮点, 整数): [(125, 4, 4, 3), (216, 5, 4, 3), (15625, 4, 7, 6)]
```

十万组里差三组。看第一组：N=125、t=4，底数是 5，而 `5³ = 125` 恰好够，正确答案是 3 头，浮点版给的是 4。

原因不难猜。`math.log(125) / math.log(5)` 理论上等于 3，实际算出来是 `3.0000000000000004`——除法在最后一位上偏了，`ceil` 一看到比 3 大一点点就进位到 4。这类误差只在真值**恰好是整数**时才致命；差得远的时候，那点误差早被上取整吸收了。三个反例的共同形状都是这样：N 恰好是 `(t+1)` 的整数次幂，`5³=125`、`6³=216`、`5⁶=15625`。

修法是用整数循环代替对数：反复乘 `base` 直到不小于 `n`，乘了几次就是答案。上面的 `ceil_int_log` 就是它，复杂度 `O(log N)`，没有浮点参与，边界永远准。

另一个常见写法是 `ceil(log(n)/log(base) - 1e-9)`，把结果往下压一点再取整——能用，但 `1e-9` 这个数是凑出来的，换个量级未必还灵。这不是 458 会判错的坑（它的用例没卡在这些点上），但它说明「公式对」和「代码对」是两件事。

## 八、三个理想假设，各自破在哪

前面的推导全程没提误差，因为模型假设了三件事，每一条在现实里都会松。

**假设一：测试完全可靠，没有假阳性假阴性。** 一旦有误判，状态向量就被打错一位，解码出来是隔壁桶。要修得引入纠错编码：设计喂食矩阵时让任意两种可区分状态的最小汉明距离大于 1，用冗余换容错。

**假设二：毒药唯一且必然存在。** 如果阳性样本可能有多桶、或者可能一桶都没有，问题就从「识别一个」变成「识别至多 d 个」，答案换成分离集与可调矩阵那一套，组合数从 `N` 变成 `C(N, d)`，猪数会明显上升。

**假设三：轮次严格分隔，观察无误。** 现实里猪的死亡时间有抖动，第 2 轮和第 3 轮可能分不清。轮次一糊，`t+1` 个结局就退化成更少的几档。

还有一个代码层的边界，比这三条更容易踩。原文公式在 `minutesToTest < minutesToDie` 时除零崩溃：`t = 0`，`log(t+1) = log(1) = 0`，直接抛 `ZeroDivisionError`。语义上它也对——一轮都跑不完，状态向量永远只有一个取值，信息量为零，多少头猪都没用，所以正确做法是返回无穷而不是让程序崩。

同一段代码里还有一处反直觉的边界：`buckets = 4, t = 4` 只需要 1 头猪。一头猪只有 5 种结局，怎么区分 4 个桶？让它第 1、2、3 轮各喝一桶，第 4 轮什么都不喝，四种死亡轮次对上四个桶——这就是「一头猪带 5 个符号」的最小实例。

## 九、搬到现实：三个能用的地方

这套编码能落地，前提是测试单元**有记忆**——同一单元在不同轮次的状态能区分开。猪会死，所以有记忆；一次性试纸没有，同一张试纸谈不上「第几轮变色」。

**池检测。** 大规模筛查里把多个拭子混管检测就是群组测试。如果对同一批样本换不同引物分组重测，那几组结果就构成不同「轮次」；编码的位不再由猪承担，而是由「第几次分组」承担。省的是试剂和通量，加的是周转时间。

**高通量药物筛选。** 把 N 种化合物当桶、几株细胞系当猪：毒性在不同时间点显现，观察时间点就是轮次。用少数几株细胞系在有限观测窗口内筛更多化合物，靠的正是「第几天开始异常」这个多值结局。

**硬件故障定位。** 注入特定测试信号，看某模块在第几个时钟周期后响应异常，用最少的探针定位坏单元。这里的轮次是时钟周期，猪是探针。

三处的共同点：单元贵、轮次相对便宜、且单元能保留跨轮状态。三个条件缺一个，`(t+1)` 就退化回 2，问题退回二进制编码。

## 十、小结

- **底数 `t+1` 不是凑的**：一头猪跨轮存活，结局有「第 1 轮死」到「第 t 轮死」外加「全程存活」，共 `t+1` 种，所以它是个 `t+1` 值变量。
- **下界 = ⌈log_{t+1}N⌉**，来自 `(t+1)^x ≥ N`；换成信息论说法是「`log₂N` 比特 ÷ 每头 `log₂(t+1)` 比特」，两条路同一个答案。
- **构造就是把桶号写成 `(t+1)` 进制**：第 i 头猪管第 i 位，第 k 轮喝该位等于 k 的桶；死在第几轮就是那一位的数值。喂食表在测试前全部定死（非自适应），所以能并行准备——这是它能用于池检测的关键，不是实现细节。
- **省下的猪是拿时间换的**：`t=3` 时一头猪带 2 比特顶两头用，但测试要跑满三个周期；而且轮次加成是阶梯，`t=3` 与 `t=4` 都是 5 头，别按线性外推。
- **`ceil(log(n)/log(base))` 在 99990 组里错 3 组**，全是 N 恰为整数次幂的边界（125/4、216/5、15625/4）；改用整数循环乘，边界永远准。
- **`t=0` 会让公式除零**，语义上答案是无解——一轮跑不完，信息量为零。
