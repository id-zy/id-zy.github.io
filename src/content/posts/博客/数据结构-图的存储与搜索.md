# 图的存储与搜索：从邻接表到拓扑排序

图和树最大的区别不是「有没有环」，而是**边数不再受顶点数约束**。一棵 n 个结点的树恰好 n−1 条边，而一张 n 个顶点的图可以有 0 到 n(n−1)/2 条边，跨越四个数量级。

这一点直接决定了图为什么没有「唯一正确」的存法：同样是存一张图，稠密图和稀疏图的最优选择差了 45 倍。选错存法，后面所有算法的常数都会跟着走样。

这篇文章按「先存、再走、最后组合成算法」的顺序展开，并且把每一步的代价都用实测量化——因为图算法里「理论复杂度」和「实测快多少」的偏差，比前面几篇都大。

## 一、图的两个存法，决定了后面所有算法的形状

先把复杂度账摆出来（V 是顶点数，E 是边数）：

| 存储结构 | 空间 | 添加边 | 删除边 | 判断 u 与 v 相邻 | 遍历 v 的邻居 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 邻接矩阵 | O(V²) | O(1) | O(1) | **O(1)** | O(V) |
| 邻接表 | O(V + E) | O(1) | O(E) | O(degree) | O(degree) |

四个格子对得上，但陷阱在最后两列：**邻接矩阵判邻接是 O(1)，代价是遍历邻居要 O(V)**；邻接表正好反过来。所以「哪个更好」完全取决于你要频繁做哪种操作。

常见图算法的需求是「遍历邻居」——DFS、BFS、Dijkstra、拓扑排序全都要反复扫一个点的所有邻边。这就是为什么**邻接表是默认选择**，邻接矩阵只在稠密图或需要频繁判邻接时才划算。

## 二、空间账与查询账

先看空间。同一张图分别用两种结构建出来，实测峰值内存：

| V | E | 邻接矩阵 | 邻接表 | 内存比 |
| ---: | ---: | ---: | ---: | ---: |
| 200 | 400 | 320.8 KB | 17.0 KB | **18.9 倍** |
| 200 | 4,000 | 320.8 KB | 78.4 KB | 4.1 倍 |
| 500 | 1,000 | 1,980.3 KB | 49.2 KB | **40.3 倍** |

矩阵那一列只跟 V 有关（V²），跟边数完全无关；邻接表跟 E 成正比。所以图的边越稀疏（E 越接近 V 而不是 V²），矩阵浪费得越多。

再看查询。20 万次「u 与 v 相邻吗」，V 固定 1000，只改平均度：

| 平均度 | 邻接矩阵 | 邻接表 | 矩阵优势 |
| ---: | ---: | ---: | ---: |
| 4 | 8.10 ms | 12.21 ms | 1.5 倍 |
| 8 | 7.28 ms | 17.53 ms | 2.4 倍 |
| 30 | 6.74 ms | 45.86 ms | 6.8 倍 |
| 100 | 7.69 ms | 140.08 ms | 18.2 倍 |
| 300 | 8.62 ms | 390.52 ms | **45.3 倍** |

矩阵那一行几乎不动（O(1)），邻接表随度数线性上涨（O(degree)）——这就是复杂度表里那两列的真实形状。

但矩阵的常数也不是免费的。固定平均度 8、只放大 V，能看到缓存的代价：

| V | 矩阵格数 | 邻接矩阵 | 邻接表 | 矩阵优势 |
| ---: | ---: | ---: | ---: | ---: |
| 200 | 40,000 | 4.81 ms | 11.26 ms | 2.3 倍 |
| 1,000 | 1,000,000 | 6.98 ms | 17.33 ms | 2.5 倍 |
| 4,000 | 16,000,000 | 12.05 ms | 15.49 ms | **1.3 倍** |

V 从 200 涨到 4000，矩阵的优势从 2.3 倍缩到 1.3 倍，而邻接表基本持平。原因很直接：矩阵是 V 个长度 V 的列表，`matrix[u][v]` 要跳两次，第二次跳转的位置随 V 线性变远，缓存命中率下降。**O(1) 指的是访问次数，不是访问代价**。

两种结构的建法都很短，差别全在数据结构本身：

```python
def build_matrix(V, edges):
    """邻接矩阵：V 个长度 V 的列表，空格子也要占位"""
    m = [[0] * V for _ in range(V)]
    for u, v in edges:
        m[u][v] = 1
        m[v][u] = 1        # 无向图要对称；有向图去掉这句
    return m

def build_adjlist(V, edges):
    """邻接表：只存真实存在的边，空间跟 E 走"""
    adj = [[] for _ in range(V)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    return adj

def has_edge_matrix(m, u, v):
    return bool(m[u][v])          # O(1)：不论度数多少，都是两次索引

def has_edge_adjlist(adj, u, v):
    return v in adj[u]            # O(degree)：度数越大扫得越久
```

## 三、DFS 与 BFS：走法不同，代价几乎一样

两种遍历都从起点出发、每个顶点只访问一次，差别只在「先深还是先广」：

```python
from collections import defaultdict, deque

class Graph:
    def __init__(self, directed=False):
        self.adj = defaultdict(list)
        self.directed = directed

    def add_edge(self, u, v):
        self.adj[u].append(v)
        if not self.directed:
            self.adj[v].append(u)

    def dfs(self, start):
        """递归版：一条路走到黑，走不动再回溯"""
        visited = set()
        order = []

        def go(v):
            visited.add(v)
            order.append(v)
            for w in self.adj[v]:
                if w not in visited:
                    go(w)

        go(start)
        return order

    def bfs(self, start):
        """队列版：像水面波纹，一圈一圈往外扩"""
        visited = {start}
        q = deque([start])
        order = [start]
        while q:
            v = q.popleft()
            for w in self.adj[v]:
                if w not in visited:
                    visited.add(w)
                    order.append(w)
                    q.append(w)
        return order
```

实测一张 10 万顶点、平均度 4 的连通图（单位 ms）：

| V | DFS 递归 | DFS 迭代 | BFS |
| ---: | ---: | ---: | ---: |
| 10,000 | 2.16 | 2.07 | 1.43 |
| 100,000 | 30.99 | 27.14 | 27.92 |

三者几乎打平。这跟「递归慢」的直觉不符，但和前一篇测二叉树遍历的结论一致：**CPython 的函数调用开销和 `while` 循环里的 `append`/`pop` 开销被拉平了**。BFS 在小图上略快，是因为 `deque` 的出入队比递归调用便宜一点点；到 10 万顶点时这点差异被边的遍历淹没。

所以选 DFS 还是 BFS，看的是**顺序需求**而不是速度：要最短路径（边权相同时）用 BFS，要连通分量、拓扑排序、回溯搜索用 DFS。

DFS 还带一个 BFS 做不到的能力：**染色**。判断二分图就是用两个颜色交替标记，一旦相邻两点同色就说明有奇环：

```python
def is_bipartite(adj, V):
    """DFS 染色：相邻点必须异色；撞到同色说明有奇环"""
    color = [-1] * V
    for start in range(V):
        if color[start] != -1:
            continue
        color[start] = 0
        stack = [start]
        while stack:
            v = stack.pop()
            for w in adj[v]:
                if color[w] == -1:
                    color[w] = color[v] ^ 1
                    stack.append(w)
                elif color[w] == color[v]:
                    return False
    return True
```

这里把递归换成了显式栈，避免上一节要说的深度问题；`^ 1` 是在 0 和 1 之间翻转的写法。

## 四、DFS 的递归版在 1500 个结点就崩

真正的分水岭不是速度，是深度。把递归上限设回 Python 默认的 1000，拿一条链（最坏情况：每个点只有一个后继）试：

| 链长 | DFS 递归 | DFS 迭代 |
| ---: | :--- | :--- |
| 500 | 成功 | 成功 |
| 900 | 成功 | 成功 |
| 1,500 | **抛 RecursionError** | 成功 |
| 5,000 | **抛 RecursionError** | 成功 |

1500 个结点——这在图里是个微不足道的规模。但 DFS 的递归深度等于**当前路径长度**，链状图里路径长度就等于 V。所以：

**只要输入规模可能上千，DFS 就必须写迭代版。** 迭代版把「系统调用栈」换成显式的 `list`，深度不再受限制：

```python
def dfs_iterative(adj, start):
    visited = bytearray(len(adj))
    order = []
    stack = [start]
    while stack:
        v = stack.pop()
        if visited[v]:
            continue
        visited[v] = 1
        order.append(v)
        for w in reversed(adj[v]):     # 逆序压栈，弹出顺序才与递归一致
            if not visited[w]:
                stack.append(w)
    return order
```

两个细节容易漏：一是**出栈时判重**（而不是入栈时），因为同一个点可能被多次压入；二是 `reversed`——正序压栈、弹出顺序就反了，虽然结果仍是合法 DFS，但和递归版的顺序不再一致，调试时会误以为写错了。

## 五、枚举：先数清解空间，再决定写不写

枚举常被当成「没办法时的办法」，其实它是**所有算法的地面真值**。写高效算法时先写一个暴力版做对照，是最省时间的正确性保障——前面几篇里我验证排序、字符串匹配、双指针都是这么干的。

它的代价可以精确计算。n 个元素的子集有 2^n 个，n 个城市的路径有 (n−1)! 条。这两个数字增长得比直觉快得多：

| n | 2^n 子集 | (n−1)! 条路径 |
| ---: | ---: | ---: |
| 10 | 1,024 | 362,880 |
| 15 | 32,768 | 87,178,291,200 |
| 20 | 1,048,576 | 1.2 × 10¹⁷ |
| 30 | 1,073,741,824 | 8.8 × 10³⁰ |

所以「能不能枚举」是个算术问题，不是判断力问题。先算出解空间大小，再乘上单个解的验证代价，就知道会不会超时——这一步花 30 秒，能省掉一次白写。

最直白的枚举写法是位掩码，用整数的每一位表示「取不取第 i 个元素」：

```python
def count_subsets_all(nums, target):
    """位掩码全枚举：2^n 个子集，一个不漏也一个不省"""
    n = len(nums)
    found = 0
    for mask in range(1 << n):
        s = 0
        for i in range(n):
            if mask >> i & 1:
                s += nums[i]
        if s == target:
            found += 1
    return found
```

它的好处是「正确性无需论证」——所有组合都试过了，错不了。代价同样无需论证：内层循环固定跑 n 次，所以总代价恰好是 n·2^n，跟着指数走。

## 六、剪枝：把 2^n 砍成几万个结点

枚举真正的价值不在于「全试一遍」，而在于「试的时候能提前退出」。子集和是个干净的例子：找到和等于 target 的子集，排序后一旦累加和超过 target，后面的数更大，整条分支可以直接砍掉。

```python
def count_subsets_pruned(nums, target):
    """排序后 DFS 枚举子集；和已超 target 就剪枝"""
    nums = sorted(nums)
    n = len(nums)
    found = 0
    nodes = 0

    def go(i, s):
        nonlocal found, nodes
        nodes += 1
        if s == target:
            found += 1
            return
        if s > target or i == n:
            return
        for k in range(i, n):
            if s + nums[k] > target:
                break              # 后面的数更大，整段都不用试
            go(k + 1, s + nums[k])

    go(0, 0)
    return found, nodes
```

和「按位掩码全枚举 2^n 个子集」对比（数组元素为 1~30 的随机数，target 取总和的 1/3，两边结果逐个核对一致）：

| n | 2^n | 全枚举耗时 | 剪枝 DFS 耗时 | 剪枝访问结点 | 加速 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 14 | 16,384 | 8.49 ms | 0.339 ms | 2,412 | 25 倍 |
| 16 | 65,536 | 37.99 ms | 1.335 ms | 9,157 | 28 倍 |
| 18 | 262,144 | 166.12 ms | 3.464 ms | 24,899 | 48 倍 |
| 20 | 1,048,576 | 733.77 ms | 13.894 ms | 97,440 | **53 倍** |

n=20 时，104 万个候选被砍到 9.7 万个结点，快 53 倍。**剪枝不是常数优化，它改变的是增长曲线的斜率**——注意剪枝访问的结点数随 n 涨得很慢（1.5 倍 n 只涨 4 倍结点），而 2^n 是指数。

这也解释了为什么回溯法（N 皇后、数独、全排列）在实践中能跑：它们的解空间同样是天文数字，但绝大部分分支在很早的位置就被判死。

## 七、枚举的天花板：TSP 的 11! 与 1.6 秒

旅行商问题是最干脆的标尺——它没有剪枝的余地（必须走完全部城市才知道总长），所以耗时纯粹跟着 (n−1)! 走：

| 城市数 n | 路径数 (n−1)! | 耗时 |
| ---: | ---: | ---: |
| 7 | 720 | 0.22 ms |
| 8 | 5,040 | 1.59 ms |
| 9 | 40,320 | 13.14 ms |
| 10 | 362,880 | 131.42 ms |
| 11 | 3,628,800 | **1,583.84 ms** |

n 每加 1，耗时乘以 n−1：n 从 10 到 11 是 ×12，从 11 到 12 就是 ×12 再乘 11。所以枚举法解 TSP 的现实上限是 **n≈12（约 20 秒）**，再往上不是「慢一点」而是「跑不完」——n=15 需要 87 万亿条路径。

这也正是 TSP 成为算法史经典案例的原因：它逼出了动态规划（Held-Karp，O(n²·2^n)）和启发式算法（模拟退火、遗传算法）。**枚举给出的不是答案，是一条「此路不通」的精确边界**。

TSP 的暴力版短得有点可怜，代价全在 `permutations` 上：

```python
from itertools import permutations

def tsp_brute(dist, n):
    """固定从 0 出发，枚举其余 n-1 个城市的全部排列"""
    best = float("inf")
    for perm in permutations(range(1, n)):
        cost = dist[0][perm[0]]
        for i in range(len(perm) - 1):
            cost += dist[perm[i]][perm[i + 1]]
        cost += dist[perm[-1]][0]          # 回到起点
        best = min(best, cost)
    return best
```

固定起点省掉了一个 n 的因子（环形路径的起点无关紧要），所以是 (n−1)! 而不是 n!。这个优化很重要——它把上限从 11 城推到 12 城。

## 八、拓扑排序：DFS 后序 vs Kahn 入度法

拓扑排序是把有向无环图（DAG）压成一个线性序，保证每条边都从前往后指。两种经典实现，思路完全不同：

- **DFS 后序逆序**：深度优先遍历，一个点所有后继都处理完了才把自己加入结果，最后整体反转
- **Kahn 入度法**：反复取出入度为 0 的点，删掉它的出边，重复直到取不出点

```python
from collections import deque

def topo_kahn(adj, V):
    """Kahn：入度为 0 的先出队；出队数不足 V 说明有环"""
    indeg = [0] * V
    for u in range(V):
        for w in adj[u]:
            indeg[w] += 1
    q = deque(v for v in range(V) if indeg[v] == 0)
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for w in adj[u]:
            indeg[w] -= 1
            if indeg[w] == 0:
                q.append(w)
    return len(order) == V, order

def topo_dfs(adj, V):
    """DFS 后序逆序：三色标记顺带检测环"""
    state = bytearray(V)        # 0 未访问 / 1 在栈上 / 2 已完成
    order = []
    ok = True

    def go(v):
        nonlocal ok
        state[v] = 1
        for w in adj[v]:
            if state[w] == 1:      # 撞到还在栈上的点 -> 有环
                ok = False
            elif state[w] == 0:
                go(w)
        state[v] = 2
        order.append(v)

    for v in range(V):
        if state[v] == 0:
            go(v)
    return ok, order[::-1]
```

实测（每个点连向后方的两条边，天然无环）：

| V | DFS 后序 | Kahn |
| ---: | ---: | ---: |
| 20,000 | 3.73 ms | 4.04 ms |
| 100,000 | **抛 RecursionError** | 21.08 ms |
| 300,000 | **抛 RecursionError** | 139.56 ms |

小图上两者打平，DFS 还略快一点。但 10 万顶点时 DFS 版直接崩——**又一次撞上递归深度**。这不是「优化一下就好」的问题，而是「换个算法」。

所以工程上的默认选择是 **Kahn**：它天生是迭代的、不需要递归栈，而且「出队数不足 V 就有环」这个判据比 DFS 的三色标记更不容易写错。

## 九、四个容易写错的地方

**一、`visited` 标记的时机。** BFS 必须在**入队时**标记，否则同一个点会被多个邻居重复入队，队列爆炸；DFS 迭代版在**出栈时**标记更稳妥（入栈时标记也行，但要保证不重复压）。这两处的正确做法是相反的，别记混。

**二、`reversed` 与遍历顺序。** 想让迭代 DFS 的输出顺序和递归版一致，压栈时必须逆序。不加 `reversed` 结果依然合法，但两次跑出来的序不同，会误判成随机性 bug。

**三、邻接表存有向图时只加一条边。** `add_edge(u, v)` 里那句 `if not self.directed` 漏了，无向图会变成「单边图」，DFS 只能走一半。

**四、Kahn 的「有环」判据是数量，不是布尔。** 看到队列空了就返回 True 是错的——要比较 `len(order) == V`。有环时队列早早空掉，剩下的点永远等不到入度归零。

## 十、小结：为什么先学枚举，再学图

回头看这三块内容，它们其实是一条线：

**存法决定常数**：邻接矩阵省查询、邻接表省空间，选错方向差 45 倍；矩阵的 O(1) 还会随 V 变大而变贵。

**走法决定顺序**：DFS 和 BFS 的耗时几乎一样（10 万顶点都是 27~31 ms），真正的差别是递归深度——1500 个结点的链就能把递归 DFS 打崩。**这是本篇最该记住的一条**，因为它跟直觉相反，而且和前面遍历二叉树那篇的结论完全一致。

**枚举决定边界**：2^n 和 (n−1)! 是硬墙，剪枝能把墙往后推（2^20 压到 9.7 万结点），但推不动 TSP 的 12 城上限。知道墙在哪，才知道什么时候该换算法而不是换实现。

一句话总结：**图算法的门槛不在「想不到」，而在「常数在哪」和「栈有多深」**。前者影响你选哪种存法，后者影响你敢不敢写递归。
