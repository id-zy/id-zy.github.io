# 分布式系统为什么难：从没有统一时钟说起

分布式系统的教材通常从定义讲起，然后列一堆挑战。但那些挑战不是并列关系，它们几乎全部从定义里的两个词长出来：

> 多个通过**网络互连**的**独立自治**计算节点，基于**消息传递**协作。

**独立自治**意味着每个节点有自己的 CPU 和**自己的时钟**——没有一个全局的「现在几点」。**消息传递**意味着节点之间没有共享内存——你看到的别人的状态，永远是过时的快照。

后面所有麻烦，都是这两个前提的推论。

## 一、五类架构：控制权怎么分散

在谈难点之前，先看这些节点怎么组织。五种典型架构可以用一根轴串起来——**控制权越来越分散**：

```text
C/S 单点控制 → 主从（一主多从）→ 三层（分工分层）→ 总线（匿名松耦）→ P2P（完全对等）
```

- **客户端-服务器**：客户端发请求、运算轻、生命周期短；服务器完成运算、重、生命周期长。
- **三层 Client-Cluster**：表示层管用户视图，应用层管业务逻辑，数据层管存储。分层的价值是层间接口解耦，改一层不动其他层。
- **主从模式**：Master 分解任务、分发、监控、失败重调度；Slave 执行子任务。
- **总线模式**：节点通过虚拟总线相连，发送者和接收者不必互相知道，异步通信，松耦合。
- **对等模式 P2P**：节点分工完全对等、软件完全相同，只有初始化参数不同。结构化 P2P 的交互遵循固定规律，非结构化的不遵循。

一个常被问到的区别：总线模式和 P2P 差在哪？答案是**分工**——总线模式里节点做不同的事（各自提供不同功能），P2P 里节点做同一件事（软件都一样）。

## 二、三大不确定性，和建模它们的方式

| 维度 | 分类 | 含义 |
|---|---|---|
| 交互模式 | 同步 | 按周期收发，假设物理时钟同步、延迟有上限 |
| | 异步 | 任意时刻收发，不做时间假设 |
| 节点故障 | 失效停止 | 挂了就安静不出声 |
| | 拜占庭 | 挂了之后可能做任意动作，包括说谎 |
| 信道故障 | 丢失 / 乱序 / 延迟 | 消息可能丢、可能乱序、可能迟到 |

这个分类表的价值在于：它把「不确定」变成了可以分析的对象。后面所有的算法，都是在某个具体组合下讨论「能做到什么」——比如 Paxos 假设失效停止、PBFT 假设拜占庭、FLP 定理说的是异步模型下连一个节点失效都达不成共识。

## 三、物理时钟：Cristian 算法能对到多准

最朴素的想法是找一台时间服务器对时。Cristian 算法就这么干，但要求四个时间戳：

```python
T1, T2, T3, T4 = 0, 5, 7, 11
rtt = (T4 - T1) - (T3 - T2)
one_way = rtt / 2
client_set = T3 + one_way
print(f"  T1={T1} T2={T2} T3={T3} T4={T4}")
print(f"  往返延迟 = ({T4}-{T1}) - ({T3}-{T2}) = {rtt}")
print(f"  单向延迟 = {rtt}/2 = {one_way}")
print(f"  客户端校时 = T3 + 单向 = {T3} + {one_way} = {client_set}")
```

```text
  T1=0 T2=5 T3=7 T4=11
  往返延迟 = (11-0) - (7-5) = 9
  单向延迟 = 9/2 = 4.5
  客户端校时 = T3 + 单向 = 7 + 4.5 = 11.5
```

`T1` 客户端发送、`T2` 服务器收到、`T3` 服务器回发、`T4` 客户端收到。总往返时间里，服务器自己处理掉了 `T3-T2 = 2`，剩下 9 才是网络来回，所以单程 4.5，客户端把时间设成 `T3 + 4.5`。

这套算法的软肋在「来回对称」这个假设。网络一来一回如果不等长（去 2 回 7），算出的单程就是错的，误差全部转嫁到时钟上。物理时钟只能逼近，做不到共识。

## 四、逻辑时钟：Lamport 排得出什么

既然物理时钟靠不住，就换个思路——不问「几点」，只问「谁先谁后」。

Lamport 时钟的规则很简洁：每个节点维护一个整数，本地每发生一个事件加一；发消息时把当前值带上；收到消息时取 `1 + max(本地值, 消息值)`。

它保证一件事：**若 `a → b`（a 因果先于 b），则 `C(a) < C(b)`。**

注意这是个单向蕴含。它没说的是反过来成不成立——而问题恰恰出在这里。

## 五、Lamport 排不出的东西：并发

造一个最小场景：三个节点，N1 发生 `a1`、`a2`（`a2` 给 N2 发消息），N2 收到后发生 `b1`、`b2`，N3 自己发生 `c1`、`c2`，全程不和别人通信。

```python
nodes = ["N1", "N2", "N3"]
L = {n: 0 for n in nodes}
V = {n: [0, 0, 0] for n in nodes}

def idx(n):
    return nodes.index(n)

def local(n):
    L[n] += 1
    V[n][idx(n)] += 1
    return L[n], list(V[n])

def recv(n, msg):
    lam, vec = msg
    L[n] = 1 + max(L[n], lam)
    V[n] = [max(a, b) for a, b in zip(V[n], vec)]
    V[n][idx(n)] += 1
    return L[n], list(V[n])

events = []
lam, vec = local("N1");   events.append(("a1", "N1", lam, vec))
lam, vec = local("N1");   events.append(("a2", "N1", lam, vec))
lam, vec = recv("N2", (2, [2, 0, 0])); events.append(("b1", "N2", lam, vec))
lam, vec = local("N2");   events.append(("b2", "N2", lam, vec))
lam, vec = local("N3");   events.append(("c1", "N3", lam, vec))
lam, vec = local("N3");   events.append(("c2", "N3", lam, vec))

print(f"  {'事件':<4}{'Lamport':>8}   向量")
for name, n, lam, vec in events:
    print(f"  {name:<5}{lam:>7}   {vec}")

causal = {("a1", "a2"), ("a1", "b1"), ("a1", "b2"), ("a2", "b1"), ("a2", "b2"), ("b1", "b2"), ("c1", "c2")}
d = {e[0]: (e[2], e[3]) for e in events}

def vec_lt(u, v):
    return all(a <= b for a, b in zip(u, v)) and u != v

mis = 0
print(f"  {'事件对':<12}{'真实':<7}{'Lamport':<10}{'向量'}")
for i, a in enumerate(d):
    for b in list(d)[i + 1:]:
        la, va = d[a]
        lb, vb = d[b]
        truth = "a→b" if (a, b) in causal else "并发"
        lam_say = "a 先" if la < lb else ("b 先" if lb < la else "同时")
        vec_say = "a→b" if vec_lt(va, vb) else ("b→a" if vec_lt(vb, va) else "并发")
        if truth == "并发" and lam_say != "同时":
            mis += 1
        print(f"  {a} / {b:<9}{truth:<8}{lam_say:<11}{vec_say}")
print(f"  Lamport 把 {mis} 组并发判成了有先后")
```

```text
  事件   Lamport   向量
  a1         1   [1, 0, 0]
  a2         2   [2, 0, 0]
  b1         3   [2, 1, 0]
  b2         4   [2, 2, 0]
  c1         1   [0, 0, 1]
  c2         2   [0, 0, 2]
  事件对         真实     Lamport   向量
  a1 / a2       a→b     a 先        a→b
  a1 / b1       a→b     a 先        a→b
  a1 / b2       a→b     a 先        a→b
  a1 / c1       并发      同时         并发
  a1 / c2       并发      a 先        并发
  a2 / b1       a→b     a 先        a→b
  a2 / b2       a→b     a 先        a→b
  a2 / c1       并发      b 先        并发
  a2 / c2       并发      同时         并发
  b1 / b2       a→b     a 先        a→b
  b1 / c1       并发      b 先        并发
  b1 / c2       并发      b 先        并发
  b2 / c1       并发      b 先        并发
  b2 / c2       并发      b 先        并发
  c1 / c2       a→b     a 先        a→b
  Lamport 把 6 组并发判成了有先后
```

N3 从头到尾没和谁通信，所以 `c1`、`c2` 和 N1、N2 的所有事件都是**并发**的。但 Lamport 给出了明确的先后：`a1` 的 1 小于 `c2` 的 2，看起来像 `a1` 先发生；`b2` 的 4 又大于 `c2` 的 2，看起来像 `c2` 先。**这些「先后」全部是假的。**

更麻烦的是 `a2` 和 `c2` 的 Lamport 值都是 2。相等的时候我们只能说「不比」，什么都不代表——可一旦有人拿它当「同时发生」用，就错了。

Lamport 时钟能给一个**一致的**全序（加上节点 ID 打破平局），这对「所有节点按同一顺序处理消息」是够用的。但它分不出并发，所以任何需要「这两个更新是否冲突」的判断，它都答不了。

## 六、向量时钟：不可比就是并发

向量时钟的办法是让每个节点记一整排数：第 `i` 个位置是自己已知的「节点 i 发生过多少事件」。收消息时逐位取 max，再把本地那位加一。

判断规则只有三条：

- `Va ≤ Vb`：每一位都不大于
- `Va < Vb`：`Va ≤ Vb` 且至少一位严格小于
- 两者**互不可比**（各有大小），则两个事件**并发**

同一串事件里，`a2` 的向量是 `[2,0,0]`、`c2` 是 `[0,0,2]`——前者第一维大、后者第三维大，不可比，判为并发。上面那 6 组误判全部被纠正。

代价是空间。每条消息都要带上整个向量：

```text
节点数 n = 3   → 每条消息带 3 个整数
节点数 n = 100 → 每条消息带 100 个整数
节点数 n = 1000 → 每条消息带 1000 个整数
```

节点规模一上去，元数据就超过消息本身了。所以真实系统里常见两种取舍：限制参与跟踪的节点数（分片、分组），或者干脆不用精确的因果追踪，改用业务上可接受的近似（比如版本号、逻辑分区）。

## 七、CAP 与共识：n/2 和 n/3 这条线怎么来的

CAP 说的是 C（一致性）、A（可用性）、P（分区容忍）三者不能兼得。工程上 P 基本不可放弃（网络一定会断），所以真正的选择发生在 C 和 A 之间。

共识协议解决的是另一个问题：一群节点如何在「有人会挂」的前提下对同一件事达成一致。它要满足三条——终止性（有限时间内给出决策）、共识性（最终决策相同）、合法性（结果必须是某个节点的提案）。

差别全在**容忍什么样的故障**：

| 协议 | 容忍 | 边界 |
|---|---|---|
| Paxos / Raft | 失效停止 | 最多 `n/2` |
| PBFT | 拜占庭 | 最多 `n/3` |
| PoW（比特币） | 公开链 | 靠算力竞争 |

为什么差这么多？因为「安静挂掉」的节点不投票，你只需要活着的多数压倒挂掉的；而拜占庭节点会投**错误的票**，你要让诚实节点的多数压倒「挂掉的 + 说谎的」，就必须 `2f+1` 个诚实节点对抗 `f` 个坏节点，总数 `3f+1` 才够，于是 `f ≤ n/3`。7 个节点能容忍 2 个拜占庭故障，就是这个式子。

还有一条绕不开的结论：**FLP 不可能定理**——在完全异步的模型下，只要有一个节点可能失效，就不存在既保证终止又保证一致的确定性共识算法。原因是异步模型里你分不清「节点挂了」和「消息还在路上」。所以现实中的协议都不严格保证终止，它们靠超时和随机化在「大多数时候」收敛。

## 八、2PL：为什么必须拿到半数以上

两段锁协议用在分布式数据库里，规则是：客户端向所有服务器请求锁，拿到**半数以上**才发 Update，否则释放已拿到的锁、随机等待重试。

为什么是半数以上？因为它保证**任意两个客户端的锁集合必然相交**，交集中的那台服务器就成了天然的分歧点——两个客户端不可能同时通过。

```python
n_srv = 5
need = n_srv // 2 + 1
print(f"  {n_srv} 台服务器，每个客户端需要 {need} 把锁")

def disjoint_count(k):
    cnt = 0
    example = None
    for ma in range(1 << n_srv):
        sa = {i for i in range(n_srv) if ma >> i & 1}
        if len(sa) != k:
            continue
        for mb in range(1 << n_srv):
            sb = {i for i in range(n_srv) if mb >> i & 1}
            if len(sb) == k and not (sa & sb):
                cnt += 1
                if example is None:
                    example = (sorted(sa), sorted(sb))
    return cnt, example

for k in (3, 2):
    cnt, eg = disjoint_count(k)
    tag = "过半" if k >= need else "不过半"
    print(f"  只拿 {k} 把（{tag}）：不相交组合 {cnt} 组" + (f"，例如 {eg}" if eg else ""))
```

```text
  5 台服务器，每个客户端需要 3 把锁
  只拿 3 把（过半）：不相交组合 0 组
  只拿 2 把（不过半）：不相交组合 30 组，例如 ([0, 1], [2, 3])
```

5 台里拿 3 把，穷举所有组合，**找不到任何一对不相交的**；只拿 2 把，就有 30 组不相交，比如一个拿 `{0,1}`、另一个拿 `{2,3}`，各改各的，谁也不挡谁。

还有一个细节容易漏：拿不到半数时必须**主动释放已拿到的锁**。不释放就会形成互相等待——A 拿了 3 把等第 4 把，B 拿了另外 2 把等第 3 把，谁也不放，死锁。

## 九、通信层：四个抽象各解决什么

节点之间靠消息协作，但「发消息」这个动作被抽象了好几层，每层解决一个问题：

```text
Socket（传输层接口）
  → RPC / RMI（像调本地函数）
    → MOM（异步、解耦、削峰）
      → 中间件（屏蔽异构与复杂性）
```

**Socket** 是传输层给应用层的编程接口，一个连接由五元组标识 `<源IP, 源端口, 目标IP, 目标端口, 协议>`。流式（TCP）面向连接、保证顺序；数据报（UDP）无连接、不保证顺序。服务器上有两个 socket：监听 socket 负责 accept，通信 socket 负责收发。并发处理的方式取决于阻塞在哪——计算密集用线程池（CPU 忙），IO 密集用事件驱动（一个线程盯多个连接，避免干等）。

**RPC** 把远程调用伪装成本地调用，靠一对代理：调用者侧的 Stub、服务端的 Skeleton。Stub 把参数序列化成字节流发出去，Skeleton 反序列化、执行、再把结果序列化回来。所以「远程调用的参数必须可序列化」不是限制，是这套机制的必然要求。RMI 是它的面向对象版本，额外支持传远程对象引用和分布式垃圾回收。

**MOM** 把同步调用改成异步消息，换来三件事：解耦（收发双方不直接依赖）、削峰（流量高时先堆在队列里）、可靠递交。两种模式的区别在消费关系——Queue 是一对一，一条消息只被一个消费者拿走；Topic 是一对多，广播给所有订阅者。

**中间件**是对上面这些的统一抽象，目的是让程序员感觉在调本地函数，实际在调远程服务。

至于请求该落到哪台机器，那是负载均衡的事。七种策略里最值得记的是 IP 哈希，因为它的价值不在「均匀」而在**会话保持**：同一个源 IP 永远映射到同一台服务器，无状态服务器上的 session 问题就解了。而它叫「一致性」哈希，是因为某台机器挂掉时只有落在那台的 key 需要重新映射，其余不受影响。

## 十、小结

- **两个词定下全部麻烦**：独立自治 → 没有统一时钟；消息传递 → 没有共享内存，只有过时快照。
- **物理时钟只能逼近**：Cristian 靠「往返对称」这个假设，去回不等长时误差全落到时钟上。
- **Lamport 只保证单向蕴含**：`a → b ⇒ C(a) < C(b)`，反过来不成立。同一个场景里它把 6 组并发判成有先后，`a2` 和 `c2` 甚至给出相同的值。
- **向量时钟用空间换并发检测**：不可比即并发。代价是每条消息带 n 个整数，节点一多就撑不住。
- **容错线差在故障类型**：失效停止最多容忍 `n/2`（Paxos/Raft），拜占庭最多 `n/3`（PBFT），因为说谎的节点要 `3f+1` 才压得住。异步模型下 FLP 说连一个都不行。
- **2PL 的半数不是拍脑袋**：5 台拿 3 把，穷举后找不到一对不相交的锁集；只拿 2 把就有 30 组。拿不到要主动释放，否则死锁。
- **四层通信抽象各管一段**：Socket 管接口、RPC 管调用形式、MOM 管异步解耦、中间件管异构。IP 哈希管的是会话保持，不是均匀。
