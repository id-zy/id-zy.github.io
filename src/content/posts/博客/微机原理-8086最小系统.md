# 8086 最小系统：地址和数据怎么挤在十六根线上

1978 年的 8086 只有 40 个引脚，却要给外部 20 根地址线（寻址 1MB）和 16 根数据线。脚位不够，工程师的办法是**让它们分时共用**：AD0~AD15 在总线周期开头当地址，后半段当数据。

复用省了引脚，代价全推给外部电路：地址必须被锁住、数据方向必须被指明、控制信号还得按单处理器还是多处理器分两套。所谓「8086 最小系统」，本质就是**围绕这组复用引脚配齐的三件外设**。

看懂 8086 不用背 40 个脚的名字，只要抓住一条主线：**一根线上跑两种信息，就得有一个信号告诉外部「现在跑的是哪种」**。ALE、BHE、DEN、DT/R 全都是这句话的产物。

## 一、1978 年的十六位

8086 是 Intel 第一代 16 位微处理器，四个第一值得记：第一次把指令级流水线引入微处理器；第一次引入存储器分段管理，把寻址空间扩到 1MB；只有整数运算指令，浮点要另配 8087 数值协处理器；I/O 忙不过来时配 8089 I/O 协处理器。

内部按功能切成两块，这是后来所有 x86 的结构原型：

- **总线接口单元 BIU**：管段寄存器、指令指针、地址加法器、指令队列，负责和存储器、I/O 打交道。
- **执行单元 EU**：管 ALU、通用寄存器、标志寄存器，只负责算。

两块能并行的原因是指令队列：BIU 提前把指令取进 6 字节的队列，EU 从队首取来执行，取指和译码不再互相等待。传统 CPU 串行工作，取指时总线忙、执行时总线闲，队列把这个空档填掉了。

1979 年的 8088 是它的降本版：内部还是 16 位，外部数据总线砍到 8 位，指令队列缩到 4 字节，好跟当时便宜的 8 位外设配套。IBM PC 用的就是 8088，所以「8086 家族」里真正跑遍世界的是那个 8 位总线的版本。

四个段寄存器和 20 位地址的关系是这套设计的核心：CS 管代码、DS 与 ES 管数据、SS 管堆栈，段基址左移 4 位再加 16 位偏移，凑出 20 位物理地址。所以一个段最大 64KB，同一块内存可以有多种「段:偏移」写法。

## 二、40 个引脚装不下 20 加 16

如果地址和数据各占一套线，40 个脚连一半都不够。8086 的解法是把低 16 位地址 AD0~AD15 与数据总线合并，高位地址 A16~A19 单独引出。

问题立刻来了：总线上的信号是先地址后数据，外部存储器怎么知道这一刻该收地址还是收数据？靠 **ALE 地址锁存使能**。

ALE 在 T1 状态给一个高电平，含义是「现在总线上是地址，快锁」。外接一片锁存器（74LS373、8282 之类）在 ALE 的下降沿把 AD0~AD15 抓走，输出成稳定的 A0~A15；等 T2 之后总线上换成数据，锁存器里的地址仍然不变，存储器就有完整的地址可用了。

一个 1978 年的取舍就此定型：**用时间换引脚**。同一组线在两个时刻承载两种信息，靠一个控制信号切成两半，外部用一片几毛钱的锁存器把切走的那半存住。

顺带解释了一个常见困惑：为什么 8086 的地址线叫 A0~A19 却有 1MB 空间。$2^{20} = 1048576$ 字节，正好 1024KB，一根线一位，不多不少。

## 三、复用总线的代价：三件外设

把「复用引脚需要外部配合」这件事摊开，最小系统至少要有三类器件，它们的分工按引脚特性的四个维度就能理清：**功能、方向、有效电平、三态能力**。

| 器件 | 作用 | 代表型号 | 关键特征 |
| :--- | :--- | :--- | :--- |
| 锁存器 | 抓住 T1 的地址，输出稳定 A0~A15 | 74LS373、74LS374、8282、8283 | 带三态输出，ALE 触发 |
| 收发器 | 双向数据总线的方向控制与驱动 | 74LS245、8286、8287 | 双向，DT/R 定方向、DEN 使能 |
| 单向驱动器 | 单向控制信号的驱动 | 74LS244 | 单向三态 |

三态能力是这里的关键。总线上同一时刻只能有一个源在驱动，其余必须进高阻——锁存器和收发器都带三态输出，才敢并到同一组线上。

**方向**同样重要：锁存器只从 CPU 取地址往外送，是单向；收发器要在读周期接收、写周期发送，必须双向。分不清方向就会把两个输出接在一起，那是硬件级别的短路。

看器件的方法也就这四问：这个脚干什么、信号往哪走、什么电平算有效、有没有第三态。问完这四句，任何一片 74 系列或 82 系列都能读懂，不用记型号。

## 四、BHE 与 A0：一个字还是半个字

8086 的数据总线是 16 位，但存储器是按字节编址的，一个 16 位字可能落在偶地址（对齐）也可能落在奇地址（不对齐）。为此它多引出一个 $\overline{BHE}$（高字节使能，低有效），跟 A0 组成四个组合：

| $\overline{BHE}$ | A0 | 操作 | 使用的数据线 |
| :--- | :--- | :--- | :--- |
| 0 | 0 | 从偶地址读/写一个字 | AD15~AD0 |
| 0 | 1 | 从奇地址读/写一个字节（高字节） | AD15~AD8 |
| 1 | 0 | 从偶地址读/写一个字节（低字节） | AD7~AD0 |
| 1 | 1 | 无效 | 无 |

两个都为 1 的组合是无效的——高字节和低字节都不使能，等于告诉存储器「这次不算数」。把这张表写成映射跑一遍，四种组合与数据线的对应关系就不会记混：

```python
decode = {(0, 0): ("读/写一个字", "AD15~AD0"),
          (0, 1): ("读/写高字节", "AD15~AD8"),
          (1, 0): ("读/写低字节", "AD7~AD0"),
          (1, 1): ("无效", "无")}

for bhe in (0, 1):
    for a0 in (0, 1):
        op, lines = decode[(bhe, a0)]
        print(f"BHE={bhe}  A0={a0}  ->  {op:<12}  走 {lines}")
```

```text
BHE=0  A0=0  ->  读/写一个字        走 AD15~AD0
BHE=0  A0=1  ->  读/写高字节        走 AD15~AD8
BHE=1  A0=0  ->  读/写低字节        走 AD7~AD0
BHE=1  A0=1  ->  无效            走 无
```

注意 BHE 为 0 才使能高字节，这跟 $\overline{WR}$、$\overline{RD}$ 一样是低有效——名字上带横线的引脚，0 才是「开」。

这也是 8088 与 8086 的一处接口差异：8088 外部只有 8 位数据线，不存在高低字节选择，$\overline{BHE}$ 这根脚被改成了 SS0 状态输出。同一家族的两颗芯片，脚位兼容但语义不同，写汇编时的寻址习惯也得跟着变。

最常用的判定还是段地址换算，顺手把 1MB 边界也验了：

```python
def phys(seg, off):
    return ((seg << 4) + off) & 0xFFFFF        # 20 位地址，溢出即回绕

print(f"DS=1000H, SI=2345H -> {phys(0x1000, 0x2345):05X}H")
print(f"CS=FFFFH, IP=0000H -> {phys(0xFFFF, 0x0000):05X}H")
print(f"CS=FFFFH, IP=0010H -> {phys(0xFFFF, 0x0010):05X}H")
```

```text
DS=1000H, SI=2345H -> 12345H
CS=FFFFH, IP=0000H -> FFFF0H
CS=FFFFH, IP=0010H -> 00000H
```

第一行就是教材总线时序里那个例子：`MOV AL,[SI]` 读的是 12345H 单元里的 78H。第二行是复位后的取指地址——复位把 CS 置成 FFFFH、IP 清成 0000H，于是从 FFFF0H 开始执行。第三行越过了 1MB，8086 只有 20 根地址线，第 21 位直接被丢掉，地址回绕到 0。

## 五、最小模式：控制信号自己发

最小模式就是单处理器系统：控制信号少，CPU 直接对外发，不必接总线控制器。要读写的方向、要不要锁地址、给不给中断应答，全由它自己那几根脚决定。

| 引脚 | 方向 | 有效电平 | 管什么 |
| :--- | :--- | :--- | :--- |
| M/$\overline{IO}$ | 出 | 1 存储器 / 0 I/O | 这次访问的是内存还是端口 |
| $\overline{WR}$ | 出 | 低 | 写 |
| $\overline{RD}$ | 出 | 低 | 读 |
| DT/$\overline{R}$ | 出 | 1 发送 / 0 接收 | 数据往哪个方向走 |
| $\overline{DEN}$ | 出 | 低 | 数据使能，告诉收发器此刻数据有效 |
| ALE | 出 | 高 | T1 状态把地址锁进锁存器 |

这几根脚的配合关系值得推一遍：M/$\overline{IO}$ 说是内存还是端口，$\overline{RD}$ 与 $\overline{WR}$ 说读还是写，DT/$\overline{R}$ 说数据方向，$\overline{DEN}$ 说数据什么时候有效。**四个信号合起来才唯一确定一次总线操作**，缺一个外部电路就只能猜。

总线的占有权也能交出去。DMA 控制器要直接搬内存时，拉高 HOLD 请求，CPU 在当前总线周期结束时让出总线并回 HLDA。这是一个「请求/允许」的握手，不是抢占。

中断则走另一条路：可屏蔽中断 INTR 受标志位 IF 控制，IF 为 0 时 CPU 不理；非屏蔽中断 NMI 不受 IF 管，只要有请求就必须响应。响应时 $\overline{INTA}$ 发出两个负脉冲，第一个通知中断源「你的请求被接受了」，第二个让中断源把中断类型码送上数据总线。

## 六、最大模式：把控制交给 8288

多处理器系统里，控制信号不能由一个 CPU 独占——还有协处理器、DMA 控制器要共享总线。8086 的做法是把「要做什么」编码成三个状态位，让外部译码器去生成具体命令。

于是最大模式下 M/$\overline{IO}$、$\overline{RD}$、$\overline{WR}$ 这些脚集体消失，换成了 $\overline{S_2}$、$\overline{S_1}$、$\overline{S_0}$，由总线控制器 8288 译码：

| $\overline{S_2}$ | $\overline{S_1}$ | $\overline{S_0}$ | 操作 |
| :--- | :--- | :--- | :--- |
| 0 | 0 | 0 | 中断响应 |
| 0 | 0 | 1 | 读 I/O 端口 |
| 0 | 1 | 0 | 写 I/O 端口 |
| 0 | 1 | 1 | 暂停 |
| 1 | 0 | 0 | 取指 |
| 1 | 0 | 1 | 读存储器 |
| 1 | 1 | 0 | 写存储器 |
| 1 | 1 | 1 | 无作用 |

三根线八种状态，正好把「取指、读内存、写内存、读端口、写端口、中断响应、暂停、无操作」全编进去。**取指单独占一个编码**，因为它和读内存在硬件层面要区分——这也侧面说明了指令预取确实是 BIU 独立发起的。

总线请求的接法也跟着变：最小模式是 HOLD/HLDA 两根独立的脚，最大模式合成双向的 $\overline{RQ}/\overline{GT_0}$、$\overline{RQ}/\overline{GT_1}$，同一根线既发请求也收应答，靠时序阶段区分；$\overline{GT_0}$ 的优先级高于 $\overline{GT_1}$。

另外两根辅助信号在最大模式才有意义：$\overline{LOCK}$ 拉低后封锁总线，别的设备拿不到控制权，用于「读-改-写」这类不能被打断的操作；QS1、QS0 把内部指令队列的状态吐出来，00 表示无操作、01 表示取到第一个字节、10 表示队列被清空、11 表示取后续字节，给外部的在线仿真器用。

最小模式与最大模式还有一个容易记反的差别：$\overline{DEN}$ 在最小模式低电平有效，到了最大模式由 8288 发出、变成高电平有效。同一根信号线，换了主人就换了极性。

## 七、总线周期：读为什么要高阻，写不要

一次总线操作至少占四个时钟周期：T1 送地址，T2 到 T4 传数据。外设来不及就插等待周期 $T_W$（插在 T3 之后），CPU 没活干就是空闲周期 $T_i$。指令周期则由若干个总线周期拼成。

读周期和写周期前半段一样、后半段不一样，差别恰好落在方向切换上：

| 状态 | 读周期 | 写周期 |
| :--- | :--- | :--- |
| T1 | 送地址，ALE 高有效锁存 | 送地址，ALE 高有效锁存 |
| T2 | $\overline{RD}$ 有效，**总线置高阻** | $\overline{WR}$ 有效，数据立即送上总线 |
| T3 | 数据从总线读入 | 数据保持 |
| T4 | 撤销 $\overline{RD}$，$\overline{DEN}$ 随之无效 | 撤销 $\overline{WR}$ 与 $\overline{DEN}$ |

读周期在 T2 必须先把总线置成高阻，因为方向要反了：T1 是 CPU 往外送地址，T2 之后数据要从外往里进，同一条线上两个驱动源不能同时开。写周期不用这一步，地址和数据都是 CPU 往外送，方向一致，直接接上就行。

$\overline{DEN}$ 在这两个周期里都跟着读写信号走，作用是告诉收发器「现在总线上的数据是真的」。撤销之后数据还要保持一小段时间，那是给存储器留的采样余量。

时间尺度算一下就很具体。5MHz 主频时一个时钟周期 200ns，四个状态 800ns；一个总线周期最多搬 2 字节，理论峰值 2.5MB/s：

```python
T = 1 / 5e6
print(f"时钟周期 T = {T*1e9:.0f} ns")
print(f"一个总线周期（4T）= {4*T*1e9:.0f} ns")
print(f"峰值带宽 ≈ {2/(4*T)/1e6:.2f} MB/s")
```

```text
时钟周期 T = 200 ns
一个总线周期（4T）= 800 ns
峰值带宽 ≈ 2.50 MB/s
```

这个数字解释了当年为什么要加等待周期、为什么 8086-2（8MHz）会被当成升级卖点：主频一涨，整条总线的节拍都跟着涨。

## 八、中断响应为什么占两个周期

中断响应的条件只有两条：INTR 为高、IF 为 1。满足之后，CPU 在**两个**总线周期里完成交接，少一个都不行。

第一个总线周期发 ALE 锁地址，同时 $\overline{INTA}$ 拉低——这一下是通知中断源「请求被接受了」，同时把地址总线和数据总线置成悬空，避免总线上残留的信号被误读。

第二个总线周期，被响应的那个外设把一字节的中断类型码送上数据总线，CPU 读走，拿它去中断向量表里查入口地址，然后跳过去执行中断服务程序。

两段的分工很清楚：**第一个周期解决「谁被选中」，第二个周期解决「跳到哪里」**。只发一个脉冲的话，CPU 知道有人中断，但不知道是哪一个。

## 九、从引脚回到程序

前面全是硬件，最后落回代码只需要三个寄存器组合：指令地址是 CS×16+IP，堆栈地址是 SS×16+SP，数据地址看 DS 或 ES 配偏移。IP 每取一个指令字节自动加 1，CS 变是段间转移，只有 IP 变是段内转移。

标志寄存器里两个和溢出有关的位也常被拿来问：无符号运算看 CF，有符号运算看 OF。同一个加法，两个视角两套判据，混用就会得出「溢出但结果正确」这种自相矛盾的结论。

软件编程要依据的三样东西，正好对应前面读过的所有内容：电路原理图里的引脚连接关系（谁接谁）、器件控制时序（什么时候有效）、题目的功能要求（做什么）。缺第一样不知道能不能接，缺第二样不知道什么时候动，缺第三样做出来的东西不对。

## 十、小结

- **复用的根源是引脚数**：20 位地址 + 16 位数据 + 控制 + 电源，40 个脚装不下，于是 AD0~AD15 分时两用，靠 ALE 在 T1 切开。
- **代价推给外部三件套**：锁存器抓地址（373/8282）、收发器控方向（245/8286）、驱动管控制信号（244）。三态能力是它们能并到同一组线上的前提。
- **$\overline{BHE}$ 与 A0 一起决定走哪几根数据线**，两个都为 1 是无效组合；8088 因为没有高字节，这根脚改成了 SS0。
- **最小模式四个信号才唯一确定一次操作**：M/$\overline{IO}$ 定空间、$\overline{RD}$/$\overline{WR}$ 定方向、DT/$\overline{R}$ 定数据流向、$\overline{DEN}$ 定有效时刻。
- **最大模式把控制编码出去**：$\overline{S_2}\overline{S_1}\overline{S_0}$ 八种状态交 8288 译码，取指单占一个编码；总线请求合成双向的 $\overline{RQ}/\overline{GT}$。
- **读周期 T2 必须高阻**，因为地址往外、数据往里，方向要反；写周期同向，直接给数据。
- **中断响应占两个总线周期**：第一个通知中断源并悬空总线，第二个收中断类型码。
- **地址换算是段基址乘 16 加偏移，20 位截断**：FFFF:0000 是复位后的 FFFF0H，FFFF:0010 越过 1MB 回绕到 00000H。
