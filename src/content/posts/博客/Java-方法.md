# Java 方法：四种形态、值传递与重载决议

方法大概是 Java 里最不需要解释的语法：写个名字、加个括号、里面塞几行。但真正会出问题的地方都在细节上——`void` 和「不写返回类型」是不是一回事？为什么 `swap(a, b)` 什么也没换？`k(1)` 明明有 `k(Integer)` 重载，为什么走的是 `k(long)`？

这篇按「怎么写 → 参数怎么传 → 同名怎么挑 → 工程里怎么分层」的顺序讲。

## 一、方法是五个部分拼起来的

```java
public static int sum(int a, int b) {
    return a + b;
}
```

| 组成 | 含义 |
| :--- | :--- |
| 修饰符 | `public`（外部可调）+ `static`（属于类，不用 `new`） |
| 返回值类型 | 交回的结果类型；**没有返回值写 `void`，不是不写** |
| 方法名 | 小驼峰、动词开头 |
| 参数列表 | `数据类型 变量名`，逗号分隔，可以为空 |
| `return` | 交回结果；`void` 方法里可以写 `return;` 提前结束 |

两个容易混的点：

- `void` 是「有返回值类型，只是这个类型叫 void」；完全省略返回类型编译不过。
- 形参（定义处的占位符，作用域只在方法体内）和实参（调用处的表达式，先求值再传）是两回事。

## 二、四种形态，以及两种调用法

按「有没有参数 × 有没有返回值」两两组合，正好四种：

| 形态 | 例子 | 特点 |
| :--- | :--- | :--- |
| 无参无返回 | `sayHi()` | 纯副作用 |
| 有参无返回 | `printSum(3, 5)` | 结果打印了，但调用处拿不到 |
| 无参有返回 | `returnTwenty()` | 结果可复用 |
| 有参有返回 | `sum(1, 2)` | 最常见 |

有返回值的两种调用法，差别很大：

```java
System.out.println(returnTwenty());   // 打印调用：结果被消费掉
int x = returnTwenty();               // 赋值调用：结果能继续参与运算
```

**能赋值就别打印。** 打印调用把结果直接交给输出流，后面想再算一步时已经没有数据可用了；这在调试时改起来最烦——一行 `println` 得拆成两行才能接着用。

方法存在的理由有三层：复用、可读（主流程只留「做什么」）、**可测**——不能单独测试的逻辑，等于不能改的逻辑。

## 三、Java 只有值传递

这是被误解最多的一个知识点。先看结论：**基本类型传值的副本，引用类型传「引用的副本」。** 于是：

| 实参类型 | 传过去什么 | 改形参，调用方看得到吗 |
| :--- | :--- | :--- |
| 基本类型 | 值的副本 | 看不到 |
| 引用类型 | 引用的副本（两个引用指向同一个对象） | 改**内容**看得到；改**指向**看不到 |

一段代码把两种结果都演示出来：

```java
static void change(int[] arr) {
    arr[0] = 99;                 // 改同一数组的内容 → 调用方看得到
    arr = new int[]{1, 2};       // 形参改指向 → 调用方看不到
    System.out.println("inside: " + arr[0]);
}

int[] p = {1, 2, 3};
change(p);
System.out.println("after change p[0]=" + p[0]);
```

实测输出：

```text
inside: 1
after change p[0]=99
```

方法内部把 `arr` 指向了新数组，所以打印的是新数组的 `1`；但调用方的 `p` 指向没变，`p[0]` 仍是刚才被改的 `99`。

所以「Java 传对象是引用传递」这句话是错的，准确说法是**传引用的副本**。最直观的验证是 `swap`：

```java
static void swap(int a, int b) { int t = a; a = b; b = t; }

int x = 1, y = 2;
swap(x, y);
// x=1  y=2  —— 换的是副本
```

想真正「换」，只有两条路：返回包装对象或数组；或者把逻辑挪进对象内部，直接改字段。

## 四、重载看什么算签名

**重载 = 同一个类里方法名相同、参数列表不同。** 签名只看「方法名 + 参数列表」，下面这些**都不算**：返回值、参数名、修饰符、抛出的异常。

参数列表不同有三种形式：个数不同、类型不同、顺序不同。顺序不同算合法重载，但项目里尽量别写——读代码时得回头数类型。

只改返回值，编译器认成重复定义：

```text
A.java:1: error: method f(int) is already defined in class A
```

原因很直接：调 `f(1)` 时，编译器只看到「名字 `f` + 参数 `(int)`」，返回值是之后才用到的东西，没法拿它来区分。

**重载和重写是两件不同的事**：

| | 重载 Overload | 重写 Override |
| :--- | :--- | :--- |
| 发生位置 | 同一个类内 | 父子类之间 |
| 决定时机 | **编译期**（看声明类型） | **运行期**（看实际类型） |
| 与多态 | 无关 | 是多态的实现方式 |

一句话：重载是「同名不同参，编译期挑」，重写是「同签名，运行期换」。

`System.out.println` 本身就是一组重载：`println(int)`、`println(String)`、`println(char[])`……写 `println(1)` 和 `println("1")` 走的是完全不同的方法。

## 五、重载决议：编译器按四个阶段挑

当多个重载都能接受同一组实参时，编译器按顺序找：

1. **精确匹配**（类型完全一致）
2. **自动类型提升**（`int → long → float → double`）
3. **装箱 / 拆箱**（`int → Integer`）
4. **可变参数**（`int...`）

实测（同一份代码里的五个调用）：

```text
f(1)     → f(long)      int 无精确匹配，提升；long 比 double 更「近」
f(1L)    → f(long)      精确匹配
f(1.0f)  → f(double)    float 无对应重载，继续提升
g(1)     → g(int)       精确优先于装箱
h()      → h(int...) len=0
```

真正反直觉的是这个组合：

```java
static void k(Integer x) { ... }
static void k(long x)    { ... }

k(1);   // 输出 k(long)
```

直觉会说走 `k(Integer)`，但**阶段 2（类型提升）在阶段 3（装箱）之前**，编译器先找「不装箱就能匹配」的版本，`int → long` 正好命中。这条规则的实际意义很直接：**别同时提供 `long` 和 `Integer` 两个重载**，调用方永远猜不到自己走哪条。

另外两种编译期报错：

- 只改返回值 → `is already defined`（见上一节）。
- `t(null)` 同时有 `t(String)` 和 `t(Integer)`：

```text
B.java:4: error: reference to t is ambiguous
  both method t(String) in B and method t(Integer) in B match
```

`null` 两个都能接，编译器无法判断优先级，直接拒绝。

泛型擦除也会撞车：`f(List<String>)` 与 `f(List<Integer>)` 擦除后签名相同，编译不过（`name clash`）。

## 六、真实项目里的方法分层

一个 Web 请求穿过三层，每层方法的职责完全不同：

| 层 | 干什么 | 进 | 出 |
| :--- | :--- | :--- | :--- |
| Controller | 接请求、校验格式、调业务、封装响应 | 请求参数 → **DTO** | **VO** |
| Service | 业务规则、事务边界、编排多个 DAO | DTO / Entity | **Entity** |
| Mapper / DAO | 只做对象 ↔ SQL 结果集 | Entity | **PO** |

```text
JSON ──> DTO ──> (Service 内转 Entity) ──> PO ──> SQL
JSON <── VO  <── Entity <── PO <── 结果集
```

**为什么不一个类传到底**：表加一列，前端不该被迫改版；`password`、`is_deleted` 这种字段绝不能出现在 VO 里；每层只依赖自己要的信息，写测试时不用造一个全字段对象。

五条分层纪律，都是踩过才知道的：

- **依赖单向**：Controller → Service → Mapper。反过来调就是穿透。
- **事务加在 Service**：一个业务动作常常调 3 个 Mapper，事务放 DAO 层会变成三个独立事务。
- **格式校验在 Controller**（`@Valid`），业务校验在 Service。
- **异常不要层层 catch**：中间层 `catch` 后只 `printStackTrace`，会让事务**静默不回滚**。
- **方法签名只收本层要的参数**：`getById(Long id)`，而不是 `getById(UserPO po)`。

两个可以自查的信号：Service 里出现 `HttpServletRequest`、Mapper 里写业务判断——都是分层被穿透了。

## 小结

- 方法由修饰符、返回值类型、名字、参数列表、方法体组成；`void` 是有返回类型，省略返回类型编译不过。
- 四种形态按「有无参数 × 有无返回值」组合，有返回值时**能赋值就别打印**。
- Java **只有值传递**：基本类型传值副本，引用类型传引用副本——改内容看得到，改指向看不到，所以 `swap` 永远换不了。
- 重载只看「名字 + 参数列表」，返回值、参数名、修饰符都不算；只改返回值报 `is already defined`。
- 重载决议顺序是**精确 → 提升 → 装箱 → 可变参数**，装箱排在提升之后，所以 `k(1)` 走 `k(long)`，别同时写这两个重载。
- 工程里方法按 Controller / Service / Mapper 分层，配 DTO / VO / PO 三种对象，依赖单向、事务在 Service。
