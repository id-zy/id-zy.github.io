# 和为 K 的子数组

> **难度**：中等 | **题号**：560 | **链接**：https://leetcode.cn/problems/subarray-sum-equals-k/ | **数据结构**：前缀和 / 哈希表

## 🎯 问题描述

**描述**：
给你一个整数数组 `nums` 和一个整数 `k`，请你统计并返回该数组中和为 `k` 的子数组的个数。
子数组是数组中元素的**连续非空序列**。

**示例 1**：

```text
输入：nums = [1,1,1], k = 2
输出：2
```

**示例 2**：

```text
输入：nums = [1,2,3], k = 3
输出：2
```

**提示**：
- `1 <= nums.length <= 2 * 10^4`
- `-1000 <= nums[i] <= 1000`
- `-10^7 <= k <= 10^7`

## 💻 解题思路

### 思路 1：前缀和 + 哈希表（一次遍历）

#### 核心逻辑

设 `prefix[j] = nums[0] + ... + nums[j]`，则以 `j` 结尾、和为 `k` 的子数组满足：

```text
prefix[j] - prefix[i] == k   →   prefix[i] == prefix[j] - k
```

也就是说：**遍历到 `j` 时，只要数一下「在此之前出现过多少次前缀和等于 `prefix[j] - k`」，就知道有多少个以 `j` 结尾的合法子数组。**

- 用哈希表 `prefix_sum_count` 记录**每个前缀和出现的次数**（注意不是下标——同一个前缀和可能出现多次，每次都是一个不同的起点）。
- 初始化 `prefix_sum_count[0] = 1`：代表「空前缀和为 0」（下标 -1），这样从下标 `0` 开始、和恰好为 `k` 的子数组才会被计入。
- 循环体内**先查后存**：先累加答案，再把当前前缀和计入哈希表，保证不会把当前下标自己当成起点（子数组非空）。

> 为什么不用滑动窗口？因为数组里**存在负数**，右移指针时窗口和不是单调递增的，无法用「大了就收缩左指针」的套路。

#### 代码实现

```python
class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        prefix_sum_count = defaultdict(int)
        prefix_sum_count[0] = 1          # 空前缀，和为 0

        ans = 0
        current_sum = 0
        for num in nums:
            current_sum += num
            # 之前有 count 个前缀和等于 current_sum - k，就有 count 个以当前元素结尾的合法子数组
            ans += prefix_sum_count.get(current_sum - k, 0)
            prefix_sum_count[current_sum] += 1

        return ans
```

#### 📊 性能分析

- 时间复杂度：$O(n)$ —— 只遍历一次数组，哈希表的查找与插入均摊 $O(1)$。
- 空间复杂度：$O(n)$ —— 最坏情况下有 $n$ 个互不相同的前缀和。

#### 思考

1. **为什么初始化 `{0: 1}` 而不是 `{0: 0}`？** 「空前缀和为 0」是一个真实存在的前缀（下标 -1）。少了它，那些「从下标 0 开始、和恰好为 k」的子数组会被漏掉。
2. **哈希表存「次数」而非「下标」**：本题求子数组**个数**，同一个前缀和出现几次就要累加几次。对比 两数之和——那里只需知道「是否存在」，存下标即可。
3. **为什么不能滑动窗口**：负数破坏了「窗口和随右指针单调」的性质。带负数求子数组和 → 前缀和 + 哈希表。
4. **先查后存**：等价于强制「起点下标 < 终点下标」，避免同一个元素被当成起点和终点。

## 📝 总结

**「子数组求和」套路的升级版。** 见到「连续子数组 + 求和 = 目标值」且**元素可能为负**，第一反应就是「前缀和 + 哈希表计数」：把 `prefix[i] == prefix[j] - k` 的配对问题用哈希表从 $O(n^2)$ 压到 $O(n)$。两个易错细节——**初始化 `{0:1}`**、**先查后存**。
