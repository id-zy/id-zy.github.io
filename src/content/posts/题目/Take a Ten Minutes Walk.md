# Take a Ten Minutes Walk

> **难度**：6 kyu | **平台**：Codewars | **链接**：[Take a Ten Minutes Walk](https://www.codewars.com/kata/54da539698b8a2ad76000228) | **数据结构**：数组 / 模拟

## 🎯 问题描述

**描述**：

你住在 Cartesia 城，街道是**完美的方格网**。你被朋友约出去，十分钟后要回到酒店——你随身带着计步器，它只记录方向（`n` 北 / `s` 南 / `e` 东 / `w` 西）。

写一个函数 `isValid(char[] walk)`：给定一串步行方向，判断这次散步**是否恰好走了十分钟（即 10 步）且最终回到了起点**。

- 走满 10 步且回到原点 → `true`
- 步数不是 10，或走了 10 步没回到原点 → `false`

**示例 1**：

```text
输入：{'n','s','n','s','n','s','n','s','n','s'}
输出：true
解释：10 步，南北各 5 步互相抵消，回到起点。
```

**示例 2**：

```text
输入：{'w'}
输出：false
解释：只走了 1 步，不足十分钟。
```

**示例 3**：

```text
输入：{'n','n','n','s','n','s','n','s','n','s'}
输出：false
解释：10 步，但北 5 南 4，净位移偏北 1 格，没回起点。
```

**提示**：
- 输入保证只含 `'n'`、`'s'`、`'e'`、`'w'` 四种字符；
- **两个条件必须同时满足**：总步数 ` == 10`、净位移为 0。

## 💻 解题思路

### 思路 1：长度闸门 + 双轴计数

#### 核心逻辑

1. **先卡长度**：`walk.length != 10` 直接 `false`——同时解决了"十分钟"和"步数"两个约束；
2. 用两个计数器表示坐标：南北方向加减小 `j`，东西方向加减 `i`；
3. 遍历一遍累加；
4. 最后 `i == 0 && j == 0` 才算回到原点。

关键在于：**同一个方向的正负要成对**（`n` 加、`s` 减，`e` 加、`w` 减）。只要成对，净位移为 0 就等价于"南北步数相等且东西步数相等"。

#### 代码实现

```java
public class TenMinWalk {
    public static boolean isValid(char[] walk) {
        // 条件一：必须恰好 10 步
        if (walk.length != 10) {
            return false;
        }

        int i = 0;   // 东西位移：e +1，w -1
        int j = 0;   // 南北位移：n +1，s -1

        for (char s : walk) {
            if (s == 'n') {
                j++;
            } else if (s == 's') {
                j--;
            } else if (s == 'w') {
                i--;
            } else if (s == 'e') {
                i++;
            } else {
                return false;   // 非法方向，防御性处理
            }
        }

        // 条件二：回到起点
        return i == 0 && j == 0;
    }
}
```

#### 📊 性能分析

- 时间复杂度：$O(n)$，$n$ = 步数；因为 `n` 被长度闸门限定为 10，实际是 $O(1)$。
- 空间复杂度：$O(1)$，只用两个计数器。

#### 思考

- **长度判断必须在最前面**。如果先遍历再判长度，`{'n'}` 这种一步输入会因为"净位移为 0"被误判成 `true`——**"回到原点"和"走了十分钟"是两个独立条件，缺一不可**。
- 不用 `Map` 统计四个字母的频次：固定四个方向、固定 10 步，**四个 `if` 的双轴计数比 `HashMap` 快一个数量级，也更好读**。用 Map 属于"通用解法的惯性"，不是本题的最优解。
- `else { return false; }` 是防御性代码：题面保证只有四个方向，但真跑线上数据时，多一个分支的成本远小于"静默算错"的成本——非法输入被当成"没走"是最难查的 bug。
- `last else` 里 `return false` 和最后 `return i == 0 && j == 0` 不冲突：前者在**遍历中途**退出，后者只在**全部合法走完**后才可能取到。
- 变量名 `i` / `j` 在二维坐标语义下容易和"下标"混（本题里没有下标），叫 `dx` / `dy` 或 `x` / `y` 更准确——**这不是风格问题，是回看代码时少一次误读**。

## 📝 总结

1. 两个约束（步数 10 + 回到原点）都要查，**长度闸门放最前面**。
2. 网格位移用两个计数器累加，正负成对即可，不需要真的模拟坐标数组。
3. 固定枚举量（4 个方向）就别上 `Map`——`if` 链更快也更清楚。
