# 存在重复元素

> **难度**：简单 | **题号**：217 | **链接**：[217. 存在重复元素](https://leetcode.cn/problems/contains-duplicate/) | **数据结构**：哈希表

## 🎯 问题描述

**描述**：
给你一个整数数组 `nums` 。如果任一值在数组中出现 **至少两次** ，返回 `true` ；如果数组中每个元素互不相同，返回 `false` 。

**说明**：
- `1 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

**示例**：

- 示例 1：

```text
输入：nums = [1,2,3,1]

输出：true

解释：

元素 1 在下标 0 和 3 出现。
```

- 示例 2：

```text
输入：nums = [1,2,3,4]

输出：false

解释：

所有元素都不同。
```

**提示**：
- 判断「有没有重复」不需要记录次数，只需要知道「这个值之前见过没有」——集合语义就够，哈希表是超集方案。

## 💻 解题思路

### 思路1：哈希表计数

#### 代码实现

```python
class Solution:
    def containsDuplicate(self, nums: List[int]) -> bool:
        result={}
        for num in nums:
            if num in result:
                return True
            else:
                result[num]=1
        return False
```

#### 📊 性能分析

##### 提交结果
- **运行时间**：19ms击败39.09%
- **内存消耗**：35.58MB击败14.62%
##### 复杂度验证
- 时间复杂度：$O(N)$
- 空间复杂度：$O(N)$

### 思路2：Java Stream 一行解

#### 代码实现

```java
class Solution {

    public boolean containsDuplicate(int[] nums) {

        return nums.length != Arrays.stream(nums)

                                    .distinct()

                                    .count();

    }

}
```

#### 思考

- **Stream 一行解的代价**：`distinct()` 内部会先把整个数组过一遍建去重集合再 `count()`，**不能像思路 1 那样发现重复就提前返回**——最坏都是 $O(N)$，但平均下来多扫了数组；换来的是一行声明式的可读性。流的特性（惰性、一次性、不存数据）见 Java-Stream三条铁律。
- **计数 vs 存在性**：本题只问「存在与否」，`result[num]=1` 里的 `1` 并没有用上——用 `set`（Python 集合）语义更贴切；哈希表的价值在同类题 存在重复元素II（还要求下标距离）里才真正体现。
- **排序替代法**：先 `sort` 再扫相邻元素是否相等，$O(N \log N)$ 时间、$O(1)$ 额外空间——空间紧张时的备选。

## 📝 总结

一句话：**「判重」用哈希集合，$O(N)$ 时间换 $O(N)$ 空间；发现重复立即返回的短路写法比先整体去重再数数更省**。

Stream 一行解（`distinct().count()`）适合当「会写」的储备，但要知道它放弃了短路——数据量大且重复靠前时，朴素哈希循环反而更快。
