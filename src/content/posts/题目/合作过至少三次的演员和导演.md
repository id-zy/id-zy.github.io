# 1050. 合作过至少三次的演员和导演

> **难度**：简单 | **题号**：1050 | **链接**：[1050. 合作过至少三次的演员和导演 - 力扣（LeetCode）](https://leetcode.cn/problems/actors-and-directors-who-cooperated-at-least-three-times/) | **数据结构**：SQL
>
> 关联：买下所有产品的客户（同为「分组计数 + HAVING」）· 超过五名学生的课（HAVING 过滤分组）· 订单最多的用户（分组统计）

## 🎯 问题描述

**描述**：编写解决方案，找出**合作过至少三次**的演员和导演的 id 对 `(actor_id, director_id)`。

**表：ActorDirector**

```text
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| actor_id    | int     |
| director_id | int     |
| timestamp   | int     |
+-------------+---------+
timestamp 是这张表的主键（具有唯一值的列）。
```

**示例 1**：

```text
输入：
ActorDirector 表：
+----------+-------------+-----------+
| actor_id | director_id | timestamp |
+----------+-------------+-----------+
| 1        | 1           | 0         |
| 1        | 1           | 1         |
| 1        | 1           | 2         |
| 1        | 2           | 3         |
| 1        | 2           | 4         |
| 2        | 1           | 5         |
| 2        | 1           | 6         |
+----------+-------------+-----------+

输出：
+----------+-------------+
| actor_id | director_id |
+----------+-------------+
| 1        | 1           |
+----------+-------------+
解释：
唯一的 id 对是 (1, 1)，他们恰好合作了 3 次。
```

**提示**：
- 「一对」是两个字段一起确定的，分组必须同时按 `actor_id` 和 `director_id`；
- `timestamp` 是主键，同一对的时间戳不会重复，所以计数不用去重；
- 返回顺序不作要求。

## 💻 解题思路

### 思路 1：双列分组 + HAVING 计数

#### 核心逻辑

「演员 A 和导演 D 合作了几次」= 表中 `(A, D)` 这一组合出现了几行。所以：

1. `GROUP BY actor_id, director_id` —— 把每一对合作者归到一组；
2. `COUNT(*)` 数每组的行数，就是合作次数；
3. `HAVING COUNT(*) >= 3` 筛出至少三次的组合。

`WHERE` 在分组前逐行过滤、拿不到聚合值，所以条件只能写在 `HAVING` 里。

#### 代码实现

```sql
# Write your MySQL query statement below
SELECT actor_id, director_id
FROM ActorDirector
GROUP BY actor_id, director_id
HAVING COUNT(*) >= 3;
```

#### 📊 性能分析

- 时间复杂度：$O(n)$（全表扫一遍，配合 `(actor_id, director_id)` 上的索引可直接有序扫描，省掉排序/临时表）。
- 空间复杂度：$O(g)$，$g$ = 不同的 (actor_id, director_id) 组合数，用于分组的哈希表或排序缓冲。
- 若表上有 `(actor_id, director_id)` 复合索引，这个查询可以是**索引覆盖**的：只读索引不回表，`EXPLAIN` 里能看到 `Using index`。

#### 思考

- **最容易错的是只 `GROUP BY actor_id`**：那样统计的是「这个演员总共演了几次」，把不同导演的合作混在一起。凡是「组合 / 配对」类问题，分组的列数必须等于配对的字段数。
- `COUNT(*)`、`COUNT(actor_id)`、`COUNT(timestamp)` 在这里等价——`timestamp` 是主键非空，组内每行都能数到。真正有区别的是「某列可能为 NULL 时 `COUNT(列)` 会漏行」，本题不涉及。
- **不需要 `DISTINCT`**：`timestamp` 是主键，同一对不可能出现两行相同时刻。换成「合作过至少三次**不同的电影**」这种表结构，就得改成 `COUNT(DISTINCT movie_id)`——先看清主键约束再决定要不要去重。
- `COUNT(*) > 2` 与 `COUNT(*) >= 3` 完全等价；写 `>= 3` 是为了让条件和题面「至少三次」逐字对应，回看时少一次心算。
- 若题目要求「按合作次数降序、同次数按 actor_id 升序」才需要 `ORDER BY`；本题明确「顺序任意」，加了反而是多余开销。

## 📝 总结

「组合出现次数」这一类题的标准骨架就是三行：

1. `GROUP BY` 把配对字段**一起**列上；
2. `COUNT(*)` 当计数；
3. `HAVING` 卡阈值（不能是 `WHERE`）。

核心坑点：分组漏列 → 统计口径悄悄变宽；无脑加 `DISTINCT` → 白白多一次去重；把阈值条件写进 `WHERE` → 直接语法报错。
