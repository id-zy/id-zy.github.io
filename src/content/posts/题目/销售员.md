# 销售员

> **难度**：简单 | **题号**：607 | **链接**：[607. 销售员](https://leetcode.cn/problems/sales-person/) | **数据结构**：sql

## 🎯 问题描述

**描述**：

给出三张表：`SalesPerson`（销售员）、`Company`（公司）、`Orders`（订单）。请找出**没有向公司 'RED' 销售任何东西**的销售员的姓名。

**表结构**：

```sql
SalesPerson: sales_id（主键）, name, salary
Company:     com_id（主键）, name, city
Orders:      order_id（主键）, order_date, com_id（外键→Company）, sales_id（外键→SalesPerson）, amount
```

**示例 1**：

```text
输入：
SalesPerson 表：
+----------+------+--------+
| sales_id | name | salary |
+----------+------+--------+
| 1        | John | 100000 |
| 2        | Amy  | 12000  |
| 3        | Mark | 65000  |
| 4        | Pam  | 25000  |
| 5        | Alex | 5000   |
+----------+------+--------+
Company 表：
+--------+--------+----------+
| com_id | name   | city     |
+--------+--------+----------+
| 1      | RED    | Boston   |
| 2      | ORANGE | New York |
| 3      | GREEN  | Boston   |
+--------+--------+----------+
Orders 表：
+----------+------------+--------+----------+--------+
| order_id | order_date | com_id | sales_id | amount |
+----------+------------+--------+----------+--------+
| 1        | 1/1/2014   | 3      | 4        | 10000  |
| 2        | 2/1/2014   | 4      | 5        | 5000   |
| 3        | 3/1/2014   | 1      | 1        | 50000  |
| 4        | 4/1/2014   | 1      | 1        | 25000  |
| 5        | 5/1/2014   | 4      | 2        | 20000  |
| 6        | 6/2/2014   | 2      | 3        | 2000   |
+----------+------------+--------+----------+--------+

输出：
+------+
| name |
+------+
| Amy  |
| Mark |
| Alex |
+------+
解释：John（sales_id=1）和 Pam（sales_id=4）曾向 RED 公司（com_id=1）下单，其余三人没有。
```

**提示**：
- 「没有向 RED 销售过」是**反向集合问题**：先算出「向 RED 卖过的人」，再用补集。
- 注意 `com_id` 判断公司名时要先 `join Company`——`Orders` 表里只有公司 id，没有名字。

## 💻 解题思路

### 思路 1：CTE 圈出「向 RED 卖过的人」+ `NOT IN`

#### 核心逻辑

1. CTE `t1`：`Orders` 左连 `Company`，筛 `c.name = 'RED'`，取出这些订单的 `sales_id`——即「碰过 RED 的销售员」集合；
2. 主查询：`SalesPerson` 中 `sales_id NOT IN (t1)` 的人，就是答案。

#### 代码实现

```sql
# Write your MySQL query statement below
with t1 as (
    select o.sales_id
    from Orders o
    left join Company c on c.com_id = o.com_id
    where c.name = 'RED'
)
select name
from SalesPerson
where sales_id not in (select sales_id from t1);
```

#### 📊 性能分析

- 时间复杂度：$O(m + n)$（集合构建 + 反查，实际由索引决定；`com_id`/`sales_id` 建索引后为索引查找）。
- 空间复杂度：$O(m)$，`t1` 需暂存向 RED 卖过的人集合。

#### 思考

- **`NOT IN` 的 NULL 陷阱（本题最大的考点）**：如果子查询结果里出现 `NULL`，`NOT IN` 会让**整个主查询返回空集**——因为 `x NOT IN (1, 2, NULL)` 对任何 `x` 都无法判定为真（`x <> NULL` 是 `UNKNOWN`）。本题 `t1` 只取了 `Orders.sales_id`（非空列），所以安全；但如果子查询是 `left join` 产出的列就可能带 NULL，届时必须用 `where sales_id is not null` 先过滤，或改用 `NOT EXISTS`。
- **这里 `left join` 其实可以退化成 `join`**：`where c.name = 'RED'` 会把不匹配的行过滤掉，`left` 与否结果一样。写 `left join` 不算错，但语义上 `inner join` 更诚实。

### 思路 2：`NOT EXISTS` 关联子查询

#### 核心逻辑

对每个销售员，直接问一句：「存在一条他的订单，其公司是 RED 吗？」——不存在才保留。逻辑与题面「没有向 RED 销售**任何**东西」逐字对应。

#### 代码实现

```sql
# Write your MySQL query statement below
with t1 as (
    select o.sales_id
    from Orders o
    left join Company c on c.com_id = o.com_id
    where c.name = 'RED'
)
select name
from SalesPerson
where not exists (
    select t1.sales_id from t1
    where t1.sales_id = SalesPerson.sales_id
);
```

#### 📊 性能分析

- 时间复杂度：$O(n \times \log m)$（每个销售员在 `t1` 上做一次索引探测）；对 `NOT IN` 版本没有绝对优劣，取决于优化器改写能力。
- 空间复杂度：$O(m)$（CTE 仍需物化/暂存）。

#### 思考

- **`NOT EXISTS` 对 NULL 免疫**：它问的是「行是否存在」，`NULL` 参与与否不影响存在性判断，所以是反向查询的**默认更稳写法**；`NOT IN` 只有在确认子查询列非空时才放心用。
- **不用 CTE 的等价写法**：把 `t1` 内联进 `NOT EXISTS` 的子查询里（`Orders join Company` 后关联 `sales_id`），一步到位，同样清晰。
- 与 从不订购的用户 是同一道「反向补集」题的镜像：那题找「没下过单的客户」，本题找「没向特定公司卖过的销售员」，套路完全一致。

## 📝 总结

一句话：**「没做过 X」= 先圈「做过 X 的人」，再取补集——补集优先用 `NOT EXISTS`**。

`NOT IN` 能用，但心里要有一根弦：子查询一旦可能出 `NULL`，结果会静默变空集。这属于「结果不报错、但悄悄错了」的最危险一类 bug，反查场景把 `NOT EXISTS` 当默认选择更安全。
