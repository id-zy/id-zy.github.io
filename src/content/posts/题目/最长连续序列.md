# 最长连续序列

> **难度**：中等 | **题号**：128 | **链接**：https://leetcode.cn/problems/longest-consecutive-sequence/ | **数据结构**：哈希表 / 数组

## 🎯 问题描述

**描述**：
给定一个未排序的整数数组 `nums`，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。
请你设计并实现时间复杂度为 $O(n)$ 的算法解决此问题。

**示例 1**：

```text
输入：nums = [100,4,200,1,3,2]
输出：4
解释：最长数字连续序列是 [1, 2, 3, 4]，它的长度为 4。
```

**示例 2**：

```text
输入：nums = [0,3,7,2,5,8,4,6,0,1]
输出：9
```

**示例 3**：

```text
输入：nums = []
输出：0
```

**提示**：
- `0 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`

## 💻 解题思路

### 思路 1：哈希集合 + 只从「序列起点」扩张

#### 核心逻辑

排序需要 $O(n \log n)$，不满足 $O(n)$。正确做法是利用集合的 $O(1)$ 查找：

1. 把所有数放进 `set`（顺带**去重**）。
2. 遍历集合里的每个数 `num`：**若 `num - 1` 也在集合中，说明 `num` 不是某段连续序列的起点，直接跳过**。
3. 只从真正的起点（`num - 1` 不存在）出发，用 `while` 一路向后数 `num+1, num+2, ...`，得到该段长度并更新答案。

**为什么是 $O(n)$？** 因为只有当 `num` 是起点时才会启动内层 `while`。每段连续序列只会被「从起点完整扫描一次」，每个元素最多被访问 2 次（一次判起点、一次被扫描），总代价线性。

#### 代码实现

```python
class Solution:
    def longestConsecutive(self, nums: list[int]) -> int:
        ans = 0
        st = set(nums)
        for num in st:
            if num - 1 in st:          # 不是起点，跳过
                continue
            next_num = num + 1
            while next_num in st:      # 从起点一路向后数
                next_num += 1
            ans = max(ans, next_num - num)
        return ans
```

#### 📊 性能分析

- 时间复杂度：$O(n)$ —— 每个元素至多被访问 2 次。
- 空间复杂度：$O(m)$ —— $m$ 为去重后的元素个数（集合的开销）。

#### 思考

1. **「只从起点扩张」是 $O(n)$ 的关键**：如果对每个数都向后扫，遇到 `[1,2,3,...,n]` 会退化成 $O(n^2)$。加上 `num - 1 not in st` 这道闸门后，每个元素只被完整扫描一次。
2. **遍历 `set(nums)` 而非 `nums`**：集合天然去重，避免重复元素导致重复启动（虽然加了起点判断也不会错，但去重更干净）。
3. **边界**：空数组 → 返回 0；单元素 → 返回 1（`next_num - num == 1`）。
4. **变体**：并查集（把相邻的 `x` 与 `x+1` `union` 起来）也能做，思路是把「连续性」变成「连通性」，但常数更大，本题哈希集合法更优。

## 📝 总结

**「哈希集合 + 起点闸门」把看似要排序的题压到 $O(n)$。** 核心两句话：① 集合负责 $O(1)$ 判断「下一个数在不在」；② 只从「没有前驱」的起点开始数，保证每段连续序列只被扫一遍。哈希表不仅能「查存在」，还能用来**构造线性扫描的起点集合**。
