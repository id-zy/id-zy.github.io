# 网格图中最小异或路径

> **难度**：中等（实际难度约 1771，属"想到状态就赢"的题） | **题号**：[3882. Minimum XOR Path in a Grid](https://leetcode.cn/problems/minimum-xor-path-in-a-grid/) | **数据结构**：动态规划 / 位运算

## 🎯 问题描述

**描述**：

给你一个大小为 `m * n` 的二维整数数组 `grid`。你从**左上角** `(0, 0)` 出发，要到达**右下角** `(m - 1, n - 1)`。每一步只能向**右**或向**下**移动。

路径的**代价**定义为该路径上所有单元格（**包括起点和终点**）的值的**按位异或**。返回所有有效路径中**最小**的可能异或值。

**示例 1**：

```text
输入：grid = [[1,2],[3,4]]
输出：6
解释：
路径 (0,0)→(0,1)→(1,1)：1 XOR 2 XOR 4 = 7
路径 (0,0)→(1,0)→(1,1)：1 XOR 3 XOR 4 = 6
最小值 = 6
```

**示例 2**：

```text
输入：grid = [[6,7],[5,8]]
输出：9
解释：
路径 (0,0)→(0,1)→(1,1)：6 XOR 7 XOR 8 = 9
路径 (0,0)→(1,0)→(1,1)：6 XOR 5 XOR 8 = 11
最小值 = 9
```

**示例 3**：

```text
输入：grid = [[2,7,5]]
输出：0
解释：只有一条路径 (0,0)→(0,1)→(0,2)：2 XOR 7 XOR 5 = 0
```

**提示**：
- `1 <= m == grid.length <= 1000`
- `1 <= n == grid[i].length <= 1000`
- `m * n <= 1000`
- `0 <= grid[i][j] <= 1023` ← **这条是解法的钥匙**

## 💻 解题思路

### 思路 0：为什么普通 DP 直接死

普通"最小路径和"是 `dp[i][j] = min(dp[i-1][j], dp[i][j-1]) + grid[i][j]`——它成立的前提是**加法有单调性**：前面的和越小，后面加同一个数结果就越小。

**异或没有这个性质**：

```text
7 ^ 8 = 15        小值 7 异或后变大
3 ^ 8 = 11        大值 3 反而变小
```

所以「到 `(i,j)` 的最小异或」**不能推出**「到终点能取到最小异或」——一个当下更大的异或值，后面可能一路变小反超。

> **结论：最优子结构按"值"不成立，只能按"值域"建立状态。** 状态必须记住「到达某格时所有可能出现的异或值」，而不是只留最优的那个。这就是提示里 `0 <= grid[i][j] <= 1023` 的意义：**异或结果必然落在 `[0, 1024)`，值域只有 1024 个**，状态数可控。

### 思路 1：DFS + 记忆化（把当前异或值放进 key）

#### 核心逻辑

`dfs(i, j, cur)` = 从 `(i, j)` 出发走到终点、在「已积累异或值 `cur`」的条件下能得到的最小异或。

- 越界 → 返回 `+inf`（这条路径作废）；
- 走到终点 `(n-1, m-1)` → 返回 `cur ^ grid[i][j]`（含终点本身）；
- 否则把 `cur ^ grid[i][j]` 传给下、右两个方向，取较小者；
- 用 `(i, j, cur)` 做记忆化——**三元组缺一不可**，只记 `(i, j)` 就退化成普通 DP，答案会错。

#### 代码实现

```python
class Solution:
    def minCost(self, grid: list[list[int]]) -> int:
        n, m = len(grid), len(grid[0])
        memo = {}

        def dfs(i, j, current_xor):
            if i >= n or j >= m:
                return float('inf')
            if i == n - 1 and j == m - 1:
                return current_xor ^ grid[i][j]   # 计算到终点的异或值

            if (i, j, current_xor) in memo:
                return memo[(i, j, current_xor)]

            next_xor = current_xor ^ grid[i][j]
            down = dfs(i + 1, j, next_xor)
            right = dfs(i, j + 1, next_xor)

            memo[(i, j, current_xor)] = min(down, right)
            return memo[(i, j, current_xor)]

        return dfs(0, 0, 0)
```

#### 📊 性能分析

- 时间复杂度：$O(m \cdot n \cdot 1024)$——每格最多 1024 种异或值，每个状态 $O(1)$ 转移。$m \cdot n \le 1000$，上限约 $10^6$。
- 空间复杂度：$O(m \cdot n \cdot 1024)$（记忆化表）+ $O(m+n)$（递归栈）。

#### 思考

**这段代码的逻辑是对的，但有两个工程隐患**：

1. **递归深度**：路径长度 = `m + n - 1`。`1 × 1000` 的网格深度正好 **1000**，而 Python 默认递归上限也是 1000 → 边缘数据会 `RecursionError`。要么 `sys.setrecursionlimit(10000)`，要么改用思路 2 的迭代版。
2. 终点判断写在越界判断之后、memo 查找之前，导致终点状态不进 memo——这是对的（终点没有子问题），但**读代码的人容易以为漏了**，可加一行注释说明。

### 思路 2：逐格集合 DP（推荐，无递归）

#### 核心逻辑

`dp[i][j]` 存一个**集合**：走到 `(i,j)` 时所有可能的异或值。

- 初始化 `dp[0][0] = {grid[0][0]}`；
- 转移：`dp[i][j] = {x ^ grid[i][j] for x in dp[i-1][j]} ∪ {x ^ grid[i][j] for x in dp[i][j-1]}`；
- 答案是 `min(dp[m-1][n-1])`。

集合天然去重——**多条路径算出同一个异或值只占一个状态**，这也是复杂度能被压到 $O(mn \cdot 1024)$ 的原因。

#### 代码实现

```python
class Solution:
    def minCost(self, grid: list[list[int]]) -> int:
        m, n = len(grid), len(grid[0])
        dp = [[set() for _ in range(n)] for _ in range(m)]
        dp[0][0] = {grid[0][0]}

        for i in range(m):
            for j in range(n):
                if i == 0 and j == 0:
                    continue
                cur = set()
                if i > 0:
                    cur.update(x ^ grid[i][j] for x in dp[i - 1][j])
                if j > 0:
                    cur.update(x ^ grid[i][j] for x in dp[i][j - 1])
                dp[i][j] = cur

        return min(dp[m - 1][n - 1])
```

同一思路的「倒着搜 + 提前剪枝」写法（从终点回到起点，`ans` 一旦为 0 立即收工）：

```python
class Solution:
    def minCost(self, grid: list[list[int]]) -> int:
        memo = set()
        ans = float('inf')          # ← 原稿写的是 inf，未定义，会 NameError

        def dfs(i, j, values):
            nonlocal ans
            if ans == 0 or i < 0 or j < 0 or (i, j, values) in memo:
                return
            memo.add((i, j, values))
            values ^= grid[i][j]
            if i == 0 and j == 0:
                ans = min(ans, values)
                return
            dfs(i - 1, j, values)
            dfs(i, j - 1, values)

        dfs(len(grid) - 1, len(grid[0]) - 1, 0)
        return ans
```

> `ans == 0` 的提前退出是本写法唯一的优势：**异或最小值不可能小于 0**，一旦取到 0 就没有更好的解了。

#### 📊 性能分析

- 时间复杂度：$O(m \cdot n \cdot 1024)$，与思路 1 同阶，但没有递归常数与栈风险。
- 空间复杂度：$O(m \cdot n \cdot 1024)$；实际上只需要「上一行 + 当前行」，可滚动压到 $O(n \cdot 1024)$。

#### 思考

- **同一题写出两个方向（正推集合 / 逆搜记忆化）说明状态设计已经想通了**——两者 memo 的 key 都是 `(i, j, xor)`，只是遍历顺序不同。
- 逆搜版还多一个隐式好处：`ans` 是全局变量，天然可以剪枝（`ans == 0` 直接全停）；正推版要剪枝得逐格比较，反而麻烦。
- 但逆搜版多了两个易错点：`nonlocal` 别漏、`float('inf')` 别写成 `inf`。**原稿这段代码就是漏了 import/定义，直接 `NameError`。**

## 📝 总结

1. **异或不满足单调性**，所以「最小路径和」的 DP 模板搬不过来——这是本题唯一的难点。
2. 破局点在值域：`grid[i][j] <= 1023` ⇒ 异或结果 < 1024 ⇒ 状态可以按「值」展开，`dp[i][j]` 存**可达异或值集合**。
3. 记忆化的 key 必须是 `(i, j, 当前异或值)`，少了第三维就是错的。
4. 工程上：深度可能到 1000 的 DFS 要留意递归上限；迭代集合 DP 更稳。
