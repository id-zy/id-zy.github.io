```text
a a a b b c

```

**提示**：

- 输出格式是「**单词 空格 次数**」，注意次数在**第二列** —— 而 `uniq -c` 输出的顺序恰好相反（`次数 单词`），最后要换列。
- `uniq -c` **只能对已经排好序的输入**去重计数，前面必须有 `sort`，否则相同单词不相邻就会被算成多组。
- 行内是「一个或多个空格」，`tr -s ' ' '\n'` 的 `-s`（squeeze）用来把连续空格压成一个，避免产生空行/空词。
- 题目保证**没有词频相同的单词**，所以不必考虑并列时的次序。

## 💻 解题思路

### 思路 1：tr → sort → uniq -c → sort → awk（用户解法）

#### 核心逻辑

一条管道五个阶段，每段只做一件事：

1. `cat words.txt` —— 读入；
2. `tr -s ' ' '\n'` —— **切词**：连续空格压成一个，再替换成换行，把「一行多词」变成「一行一词」；
3. `sort` —— 让相同单词相邻（`uniq` 的前置条件）；
4. `uniq -c` —— 相邻去重并计数，输出 `  4 the`；
5. `sort -r` —— 按整行字符串降序（次数在行首，等效按次数降序）；
6. `awk '{print $2,$1}'` —— 把 `次数 单词` 换成 `单词 次数`。

#### 代码实现

```bash
cat words.txt | tr -s ' ' '\n' | sort | uniq -c | sort -r | awk '{print $2,$1}'
```

#### 📊 性能分析

- 时间复杂度：$O(n \log n)$（两轮排序是主导项，$n$ = 单词数）。
- 空间复杂度：$O(n)$（`sort` 与 `uniq` 都要把数据落到临时文件/内存）。
- 生产环境可换 `tr ... | sort | uniq -c | sort -k1,1nr`，或直接 `awk` 一趟哈希计数（思路 2），省掉一次全量排序。

#### 思考

- **`sort -r` 的隐性 bug（重要）**：`sort -r` 是按**整行字符串**降序，`uniq -c` 的输出行首是带空格填充的次数。当次数出现**位数不同**时（如 ` 9` 与 ` 10`），字典序会把 `9` 排在 `10` 前面 —— 结果就错了。本题示例最大次数为 4，恰好不触发；换成大文件就会翻车。稳妥写法是 **`sort -k1,1nr`**（按第 1 列数值降序）：
  ```bash
  tr -s ' ' '\n' < words.txt | sort | uniq -c | sort -k1,1nr | awk '{print $2, $1}'
  ```
- **`cat |` 是多余的**：`tr -s ' ' '\n' < words.txt` 少起一个进程（UUOC — Useless Use Of Cat）。可读性上二者都行，但面试提一句是加分点。
- **`-s` 不能省**：若写成 `tr ' ' '\n'`，`the  day`（两个空格）会变成 `the`、空行、`day`，多出一个空词参与计数。
- **`uniq -c` 依赖排序**：如果漏掉第一个 `sort`，`a b a` 会被算成两组 `a`，各自计数 1 —— 这是 Shell 词频最经典的坑。
- `awk '{print $2,$1}'` 里逗号分隔的输出默认用 `OFS`（空格），正好符合题面格式；写成 `print $2" "$1` 等价。

### 思路 2：awk 一趟哈希计数

#### 核心逻辑

用一个关联数组 `c[]` 累加词频，`END` 阶段一次性输出并按数值降序排列。不落临时文件、不做两次全量排序。

#### 代码实现

```bash
awk '{for (i = 1; i <= NF; i++) c[$i]++} END {for (w in c) print w, c[w] | "sort -k2,2nr"}' words.txt
```

#### 📊 性能分析

- 时间复杂度：$O(n + k \log k)$，$k$ = 不同单词数（只对去重后的字典排序，通常远小于 $n$）。
- 空间复杂度：$O(n + k)$。
- 比思路 1 少了"对全部单词排序"这一步，在单词重复率高时优势明显。

#### 思考

- `NF` 是当前行字段数，awk 默认按空白（含连续空格）分列，所以**天然处理了多空格**，不需要 `tr -s`。
- 若不想依赖外部 `sort`，可在 `END` 里手工冒泡/插入排序后输出；但 `k` 大时不划算，交给 `sort` 更实际。
- 与 SQL 的心智模型一一对应：`for` 累加 ≈ `GROUP BY`，`print` ≈ `SELECT`，`sort -k2,2nr` ≈ `ORDER BY COUNT(*) DESC`。

## 📝 总结

Shell 词频/计数题的固定管道：**切分（`tr`/`awk`）→ 排序（`sort`）→ 计数（`uniq -c`）→ 再排序（`sort -k1,1nr`）→ 换列输出（`awk`）**。

核心坑点：① `uniq -c` 前必须 `sort`；② `tr` 要带 `-s` 压空格；③ `uniq -c` 的输出是「次数在前」，必须换列；④ `sort -r` 是字符串序，位数不同就错，**一律用 `sort -k1,1nr`**。

> 一句话：**管道每一段只解决一个问题，坑都藏在「段的边界」上**（`uniq` 假设已排序、`tr -s` 决定切词质量、`sort` 的键决定正确性）。
