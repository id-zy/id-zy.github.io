# 197. 上升的温度

> **难度**：简单 | **题号**：197 | **链接**：[197. 上升的温度 - 力扣（LeetCode）](https://leetcode.cn/problems/rising-temperature/description/)
>
> 关联：游戏玩法分析 IV 同类「日期比较」题，可对照 SQL-窗口函数（LAG/窗口函数）。

## 🎯 问题描述

**描述**：找出与**昨天**相比温度更高的所有日期的 `id`。

**表：Weather**

```text
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| id            | int     |
| recordDate    | date    |
| temperature   | int     |
+---------------+---------+
id 是该表具有唯一值的列。
没有具有相同 recordDate 的不同行。
```

**示例 1**：

```text
输入：
Weather 表：
+----+------------+-------------+
| id | recordDate | Temperature |
+----+------------+-------------+
| 1  | 2015-01-01 | 10          |
| 2  | 2015-01-02 | 25          |
| 3  | 2015-01-03 | 20          |
| 4  | 2015-01-04 | 30          |
+----+------------+-------------+
输出：
+----+
| id |
+----+
| 2  |
| 4  |
+----+
解释：
2015-01-02 的温度比前一天高（10 -> 25）
2015-01-04 的温度比前一天高（20 -> 30）
```

**提示**：

- 返回结果**无顺序要求**。
- ⚠️ 日期**不一定连续**，必须用 `DATEDIFF = -1 / 1` 判断"恰好相邻一天"，不能只比大小。

## 💻 解题思路

### 思路1：自连接 + DATEDIFF（用户解法）

#### 核心逻辑

把同一张表当成"昨天(t1)"和"今天(t2)"两份：`DATEDIFF(t1.recordDate, t2.recordDate) = -1` 表示 t1 正好是 t2 的前一天；再筛 `t2 温度 > t1 温度`，返回 `t2.id`。

> ⚠️ 原文写的是 `CROSS JOIN Weather t2 ON ...`，**`CROSS JOIN` 不能带 `ON`**（会语法报错），应改成普通 `JOIN`（即 INNER JOIN）。

#### 代码实现

```sql
SELECT t2.id AS Id
FROM Weather t1
JOIN Weather t2
  ON DATEDIFF(t1.recordDate, t2.recordDate) = -1
WHERE t2.Temperature > t1.Temperature;
```

### 思路2：窗口函数 LAG（一次扫描）

#### 核心逻辑

按 `recordDate` 排序，用 `LAG` 取上一行的温度和日期；只要"当前温度 > 上一行温度"且"两天正好差 1 天"即为答案。

#### 代码实现

```sql
WITH t AS (
    SELECT
        id,
        recordDate,
        temperature,
        LAG(temperature, 1) OVER (ORDER BY recordDate) AS last_temperature,
        LAG(recordDate,  1) OVER (ORDER BY recordDate) AS last_recordDate
    FROM Weather
)
SELECT id
FROM t
WHERE temperature > last_temperature
  AND DATEDIFF(recordDate, last_recordDate) = 1;
```

#### 📊 性能分析

- 思路1：$O(n^2)$（自连接笛卡尔积后再过滤；有索引时可走 Nested Loop）。
- 思路2：$O(n \log n)$（排序主导），只扫一遍表，更优。

#### 思考

- `LAG` 只看"上一行"，如果日期断档（如 1/1、1/3），`last_recordDate` 是 1/1 而 `recordDate` 是 1/3，`DATEDIFF = 2`，**必须靠 ` = 1` 的守卫排除**，否则会误判。
- 自连接写法的 `DATEDIFF = -1` 已经隐含"相邻"，反而不用额外守卫。

## 📝 总结

「和前一天比较」模板：**自连接 + `DATEDIFF = ±1`** 或 **`LAG` + `DATEDIFF = 1` 守卫**。核心坑点是日期不连续时不能只比大小。
