# 608. 树节点

> **难度**：中等 | **题号**：608 | **链接**：[608. 树节点 - 力扣（LeetCode）](https://leetcode.cn/problems/tree-node/description/)
>
> 关联：SQL-CTE与递归CTE（递归 CTE 遍历树）· 游戏玩法分析 IV 同为 `CASE WHEN` 多分支题型。

## 🎯 问题描述

**描述**：表 `Tree` 描述一棵有效树，报告每个节点的类型：

- **Root**：`p_id` 为空（根节点）。
- **Leaf**：没有孩子（不是任何节点的父节点）。
- **Inner**：既不是叶子也不是根（有父节点也有孩子）。

**表：Tree**

```text
+-------------+------+
| Column Name | Type |
+-------------+------+
| id          | int  |
| p_id        | int  |
+-------------+------+
id 是唯一值；p_id 是父节点 id（根节点为 null）。
```

**示例 1**：

```text
输入：
+----+------+
| id | p_id |
+----+------+
| 1  | null |
| 2  | 1    |
| 3  | 1    |
| 4  | 2    |
| 5  | 2    |
+----+------+
输出：
+----+-------+
| id | type  |
+----+-------+
| 1  | Root  |
| 2  | Inner |
| 3  | Leaf  |
| 4  | Leaf  |
| 5  | Leaf  |
+----+-------+
```

**示例 2**：只有 `id=1` 一行时，输出该节点为 `Root`。

**提示**：

- 判断顺序很重要：先判 Root，再判是否出现在 `p_id` 集合里（Inner），否则 Leaf。
- ⚠️ **`NOT IN` + `NULL` 陷阱**：`p_id` 含 `NULL` 时 `NOT IN` 会失效（详见下文）。

## 💻 解题思路

### 思路1：CASE WHEN + 子查询（用户解法）

#### 核心逻辑

三层判断：

1. `p_id IS NULL` → **Root**；
2. `id` 出现在 `p_id` 集合里（说明它有孩子）→ **Inner**；
3. 其余 → **Leaf**。

#### 代码实现

```sql
SELECT
    id,
    CASE
        WHEN tree.id = (SELECT atree.id FROM tree atree WHERE atree.p_id IS NULL)
            THEN 'Root'
        WHEN tree.id IN (SELECT atree.p_id FROM tree atree)
            THEN 'Inner'
        ELSE 'Leaf'
    END AS Type
FROM tree
ORDER BY id;
```

### 思路2：调整判断顺序（更稳、可读）

先 Root，再 Inner（用 `IN`），`ELSE` 兜底 Leaf —— 与思路1等价，但顺序更清晰：

```sql
SELECT
    id,
    CASE
        WHEN p_id IS NULL THEN 'Root'
        WHEN id IN (SELECT p_id FROM tree) THEN 'Inner'
        ELSE 'Leaf'
    END AS type
FROM tree;
```

#### 📊 性能分析

- 时间复杂度：$O(n^2)$（每行一次子查询；表大且无索引时偏慢）。
- 空间复杂度：$O(1)$（思路2）。

#### 思考 —— 本题最大的坑：`NOT IN` 遇到 `NULL` 会整体失效

很多人会写：

```sql
-- ❌ 永远返回不了 Leaf
CASE WHEN p_id IS NULL THEN 'Root'
     WHEN id NOT IN (SELECT p_id FROM tree) THEN 'Leaf'
     ELSE 'Inner' END
```

原因：`a NOT IN (集合)` 等价于 `a != 集合里每一个值` 的**逻辑与（AND）**。而 `p_id` 含有 `NULL`，任何值与 `NULL` 做 `!=` 都得到 `UNKNOWN`（三值逻辑），整个 `AND` 结果就永远不可能是 `TRUE`，于是 `Leaf` 分支永远进不去。

**两种修法**：

```sql
-- 修法1：先过滤掉 NULL
WHEN id NOT IN (SELECT p_id FROM tree WHERE p_id IS NOT NULL) THEN 'Leaf'

-- 修法2（更推荐）：改用正向 IN 判 Inner，让 ELSE 兜底 Leaf
WHEN id IN (SELECT p_id FROM tree) THEN 'Inner' ... ELSE 'Leaf'
```

> 记忆点：**能用 `IN` 判"存在"，就别用 `NOT IN` 判"不存在"** —— 只要子查询里可能有 `NULL`，`NOT IN` 就会静默出错。也可以用 `NOT EXISTS` 规避。

## 📝 总结

树节点类型 = `CASE WHEN` 多分支，顺序是 **Root（`p_id IS NULL`）→ Inner（`id IN (p_id)`）→ Leaf（兜底）**。附带一个高频面试点：`NOT IN` 与 `NULL` 的三值逻辑陷阱。
