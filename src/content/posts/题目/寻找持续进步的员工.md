# 3580. 寻找持续进步的员工

> **难度**：中等 | **题号**：3580 | **链接**：[3580. 寻找持续进步的员工 - 力扣（LeetCode）](https://leetcode.cn/problems/find-consistently-improving-employees/description/)
>
> 关联：2016年的投资 · SQL-TopN查询（TopN 的 `ROW_NUMBER` / `MAX(CASE WHEN)` 套路）。

## 🎯 问题描述

**描述**：找出**过去三次评估中持续提高绩效**的员工。

规则：

- 员工**至少需要 3 次**评估才能被考虑；
- 过去 3 次评估（按 `review_date` 取最近 3 次）评分必须**严格递增**；
- **进步分数** = 最近 3 次中最后一次评分 − 最早一次评分；
- 结果按**进步分数降序**，再按**名字升序**排序。

**表：employees**

```text
+-------------+---------+
| Column Name | Type    |
+-------------+---------+
| employee_id | int     |  -- 主键
| name        | varchar |
+-------------+---------+
```

**表：performance_reviews**

```text
+-------------+------+
| Column Name | Type |
+-------------+------+
| review_id   | int  |  -- 主键
| employee_id | int  |
| review_date | date |
| rating      | int  |  -- 1~5，5 最好
+-------------+------+
```

**示例**：

```text
输入：
employees 表：employee_id=1..5（1 Alice Johnson / 2 Bob Smith / 3 Carol Davis / 4 David Wilson / 5 Emma Brown）
performance_reviews 表：
+-----------+-------------+------------+--------+
| review_id | employee_id | review_date| rating |
+-----------+-------------+------------+--------+
| 1         | 1           | 2023-01-15 | 2      |
| 2         | 1           | 2023-04-15 | 3      |
| 3         | 1           | 2023-07-15 | 4      |
| 4         | 1           | 2023-10-15 | 5      |
| 5         | 2           | 2023-02-01 | 3      |
| 6         | 2           | 2023-05-01 | 2      |
| 7         | 2           | 2023-08-01 | 4      |
| 8         | 2           | 2023-11-01 | 5      |
| 9         | 3           | 2023-03-10 | 1      |
| 10        | 3           | 2023-06-10 | 2      |
| 11        | 3           | 2023-09-10 | 3      |
| 12        | 3           | 2023-12-10 | 4      |
| 13        | 4           | 2023-01-20 | 4      |
| 14        | 4           | 2023-04-20 | 4      |
| 15        | 4           | 2023-07-20 | 4      |
| 16        | 5           | 2023-02-15 | 3      |
| 17        | 5           | 2023-05-15 | 2      |
+-----------+-------------+------------+--------+

输出：
+-------------+----------------+-------------------+
| employee_id | name           | improvement_score |
+-------------+----------------+-------------------+
| 2           | Bob Smith      | 3                 |
| 1           | Alice Johnson  | 2                 |
| 3           | Carol Davis    | 2                 |
+-------------+----------------+-------------------+
解释：
员工1 最近3次 3→4→5，递增，进步分 5-3=2；
员工3 最近3次 2→3→4，递增，进步分 4-2=2；
员工2 最近3次 2→4→5，递增，进步分 5-2=3；
员工4 最近3次都是 4（无进步）→ 排除；员工5 只有 2 次评估 → 排除。
```

**提示**：

- 核心是「**取每组最近 3 条 + 判断严格递增**」，`ROW_NUMBER()` 按日期降序打号即可定位最近 3 次。

## 💻 解题思路

### 思路1：ROW_NUMBER 打号 + MAX(CASE WHEN) 转列（用户解法）

#### 核心逻辑

① 按 `employee_id` 分组、`review_date DESC` 用 `ROW_NUMBER()` 打号，`rn=1` 是**最近一次**、`rn=3` 是**三次前**；
② 用 `MAX(CASE WHEN rn=1/2/3 THEN rating END)` 把最近三次评分**转成三列**；
③ `HAVING COUNT(*) = 3` 保证评估次数够 3 次；
④ `WHERE r3 > r2 > r1` 判断严格递增；进步分 = `r3 - r1`；最后 JOIN `employees` 取名字并排序。

> ⚠️ **变量名易混**：这里 `r1 = rn=3`（三次前、最早），`r3 = rn=1`（最近、最新），命名是"反"的。递增条件 `r3 > r2 > r1` 对应的正是"最新 > 中间 > 最早"，逻辑没错，但建议改成 `r_new / r_mid / r_old` 更不易读错。

#### 代码实现

```sql
WITH t AS (
    SELECT
        employee_id,
        review_date,
        rating,
        ROW_NUMBER() OVER (
            PARTITION BY employee_id
            ORDER BY review_date DESC
        ) AS rn
    FROM performance_reviews
),
t2 AS (
    SELECT
        employee_id,
        MAX(CASE WHEN rn = 3 THEN rating END) AS r1,   -- 三次前（最早）
        MAX(CASE WHEN rn = 2 THEN rating END) AS r2,   -- 中间
        MAX(CASE WHEN rn = 1 THEN rating END) AS r3    -- 最近（最新）
    FROM t
    WHERE rn <= 3
    GROUP BY employee_id
    HAVING COUNT(*) = 3
)
SELECT
    e.employee_id,
    e.name,
    (t2.r3 - t2.r1) AS improvement_score
FROM t2
JOIN employees e
  ON e.employee_id = t2.employee_id
WHERE t2.r3 > t2.r2 AND t2.r2 > t2.r1
ORDER BY improvement_score DESC, e.name ASC;
```

### 思路2：LAG 直接取前两次（更省一层聚合）

用 `LAG(rating,1/2)` 拿前一次、前两次评分，直接比较：

```sql
WITH t AS (
    SELECT
        employee_id,
        rating,
        ROW_NUMBER() OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS rn,
        LAG(rating, 1) OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS r_mid,
        LAG(rating, 2) OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS r_old
    FROM performance_reviews
)
SELECT e.employee_id, e.name, t.rating - t.r_old AS improvement_score
FROM t
JOIN employees e ON e.employee_id = t.employee_id
WHERE t.rn = 1
  AND t.rating > t.r_mid
  AND t.r_mid > t.r_old
ORDER BY improvement_score DESC, e.name ASC;
```

#### 📊 性能分析

- 时间复杂度：$O(n \log n)$（窗口函数排序主导）。
- 空间复杂度：$O(n)$。

#### 思考

- `HAVING COUNT(*) = 3` 与 `WHERE rn <= 3` 配合：不足 3 次的员工会被 `COUNT(*) < 3` 过滤掉，比先查"评估次数 ≥ 3"子查询更简洁。
- 若存在同一员工**同一天多条评估**，需在 `ORDER BY` 里加 `review_id` 作为稳定次序（题目保证 `review_id` 唯一，实际数据可能要看业务定义）。

## 📝 总结

**「取每组最近 N 条 + 判断单调」模板**：`ROW_NUMBER() ... DESC` 打号 → `rn <= N` → 用 `MAX(CASE WHEN rn=k)` 转列（或 `LAG`），再比较单调性、算差值，最后 `ORDER BY` 输出。
