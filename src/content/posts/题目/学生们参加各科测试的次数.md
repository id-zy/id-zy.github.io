## 🎯 问题描述

**描述**：查询出**每个学生参加每一门科目测试的次数**，结果按 `student_id` 和 `subject_name` 排序。

关键约束：**学生表里的一个学生修读科目表里的每一门科目** —— 所以哪怕某学生某科一次都没考，也要输出一行 `0`，不能因为 `Examinations` 里没记录就整行消失。

**表：Students**

```text
+---------------+---------+
| Column Name   | Type    |
+---------------+---------+
| student_id    | int     |
| student_name  | varchar |
+---------------+---------+
在 SQL 中，主键为 student_id（学生 ID）。
该表内的每一行都记录有学校一名学生的信息。
```

**表：Subjects**

```text
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| subject_name | varchar |
+--------------+---------+
在 SQL 中，主键为 subject_name（科目名称）。
每一行记录学校的一门科目名称。
```

**表：Examinations**

```text
+--------------+---------+
| Column Name  | Type    |
+--------------+---------+
| student_id   | int     |
| subject_name | varchar |
+--------------+---------+
这个表可能包含重复数据（换句话说，在 SQL 中，这个表没有主键）。
这张考试表的每一行记录就表示学生表里的某个学生参加了一次科目表里某门科目的测试。
```

**示例 1**：

```text
输入：
Students 表：
+------------+--------------+
| student_id | student_name |
+------------+--------------+
| 1          | Alice        |
| 2          | Bob          |
| 13         | John         |
| 6          | Alex         |
+------------+--------------+
Subjects 表：
+--------------+
| subject_name |
+--------------+
| Math         |
| Physics      |
| Programming  |
+--------------+
Examinations 表：
+------------+--------------+
| student_id | subject_name |
+------------+--------------+
| 1          | Math         |
| 1          | Physics      |
| 1          | Programming  |
| 2          | Programming  |
| 1          | Physics      |
| 1          | Math         |
| 13         | Math         |
| 13         | Programming  |
| 13         | Physics      |
| 2          | Math         |
| 6          | Math         |
| 6          | Math         |
+------------+--------------+
输出：
+------------+--------------+--------------+----------------+
| student_id | student_name | subject_name | attended_exams |
+------------+--------------+--------------+----------------+
| 1          | Alice        | Math         | 3              |
| 1          | Alice        | Physics      | 2              |
| 1          | Alice        | Programming  | 1              |
| 2          | Bob          | Math         | 1              |
| 2          | Bob          | Physics      | 0              |
| 2          | Bob          | Programming  | 1              |
| 6          | Alex         | Math         | 2              |
| 6          | Alex         | Physics      | 0              |
| 6          | Alex         | Programming  | 0              |
| 13         | John         | Math         | 1              |
| 13         | John         | Physics      | 1              |
| 13         | John         | Programming  | 1              |
+------------+--------------+--------------+----------------+
解释：
学生 1 的 Math 考了 3 次（重复行要算次数）、Physics 2 次、Programming 1 次；
学生 2 没考过 Physics，但因为是"修读全部科目"，仍需输出一行 0；
学生 6 只考过 Math。
```

**提示**：

- **行数必须是「学生数 × 科目数」**（示例 4 × 3 = 12 行）—— 先想到「把两个维度做笛卡尔积」。
- `Examinations` **没有主键、可能重复**：同一次考试可能被记了多行，题目要求按其行数计次（示例中学生 6 的 Math 出现两次 → 2 次），所以这里 `COUNT(*)`/`COUNT(列)` **不要**加 `DISTINCT`。
- 计数要用 `COUNT(e.subject_name)` 而非 `COUNT(*)`：没考时左连接补的是 `NULL`，`COUNT(列)` 不计 `NULL` 才能得到 0；`COUNT(*)` 会数到 1。

## 💻 解题思路

### 思路 1：CROSS JOIN 补全维度 + LEFT JOIN 挂明细（用户解法）

#### 核心逻辑

三步：① `Students CROSS JOIN Subjects` 造出「学生 × 科目」的完整骨架（每格都要有）；② `LEFT JOIN Examinations` 把考试记录挂到对应格子上，**连接条件必须同时包含 `student_id` 和 `subject_name`**；③ `GROUP BY` 三列 `COUNT` 计数。

#### 代码实现

```sql
SELECT
    s.student_id,
    s.student_name,
    su.subject_name,
    COUNT(e.subject_name) AS attended_exams
FROM Students s
CROSS JOIN Subjects su
LEFT JOIN Examinations e ON
    s.student_id = e.student_id
    AND su.subject_name = e.subject_name
GROUP BY
    s.student_id,
    s.student_name,
    su.subject_name
ORDER BY
    s.student_id,
    su.subject_name;
```

#### 📊 性能分析

- 时间复杂度：$O(S \times B + E)$，其中 $S$ 学生数、$B$ 科目数、$E$ 考试行数 —— 笛卡尔积必然会生成 $S \times B$ 行的中间结果，这是本题无法绕开的成本。
- 空间复杂度：$O(S \times B)$（中间结果 + 分组哈希表）。
- ⚠️ 笛卡尔积在真实业务里是**危险操作**：学生上万、科目上百时会炸成百万行。生产写法通常是"先聚合再补零"（见思路 2）。

#### 思考

- **`COUNT(*)` vs `COUNT(e.subject_name)`**：`LEFT JOIN` 未命中时右表列补 `NULL`，但整行仍然存在，所以 `COUNT(*)` 会返回 **1**（错），`COUNT(具体列)` 跳过 `NULL` 返回 **0**（对）。这是本题最经典的坑。
- **连接条件要写两列，而且要写在 `ON` 里**：只写 `student_id` 会让「学生 1 的 Math 记录」被错误匹配到「学生 1 的 Physics 格子」上；把 `su.subject_name = e.subject_name` 挪到 `WHERE` 又会把 `NULL` 行整行过滤掉（`LEFT JOIN` 退化成 `INNER JOIN`），两处都错。
- **`ORDER BY` 用 `student_id` 而非 `student_name`**：题面要求按 id 排；示例输出里 6 排在 13 之前，正是数值序而非字典序的证明。

### 思路 2：先聚合再补零（生产写法）

#### 核心逻辑

先只在 `Examinations` 内部按「学生 + 科目」聚合（数据量小得多），再 `LEFT JOIN` 回「学生 × 科目」骨架，用 `IFNULL` 把没考过的补 0。

#### 代码实现

```sql
SELECT
    s.student_id,
    s.student_name,
    su.subject_name,
    IFNULL(x.cnt, 0) AS attended_exams
FROM Students s
CROSS JOIN Subjects su
LEFT JOIN (
    SELECT student_id, subject_name, COUNT(*) AS cnt
    FROM Examinations
    GROUP BY student_id, subject_name
) AS x
    ON x.student_id = s.student_id
   AND x.subject_name = su.subject_name
ORDER BY s.student_id, su.subject_name;
```

#### 📊 性能分析

- 时间复杂度：$O(E + S \times B)$ —— 聚合阶段只处理 $E$ 行，比思路 1 把 $E$ 行摊到 $S \times B$ 个格子上去 `COUNT` 更省。
- 空间复杂度：$O(E + S \times B)$。
- 差别在**聚合的输入规模**：思路 1 是对 $S \times B$ 行做 `COUNT`，思路 2 只对 $E$ 行做 `COUNT`。笛卡尔积本身省不掉，但"计数"这一步轻了。

#### 思考

- `IFNULL`（MySQL）等价于标准 SQL 的 `COALESCE`，跨库可移植时用后者。
- 两者的 `attended_exams` 语义完全一致，区别只在执行路径 —— 面试时能说出「先聚合再 join」这一层，比只写对答案更有价值。

## 📝 总结

「**补维度（每格都要有，没有记 0）**」的固定三步：

1. 两个维度表 **`CROSS JOIN`** 造骨架；
2. 事实表 **`LEFT JOIN`** 挂上去，复合关联条件全部写在 `ON` 里；
3. 计数用 **`COUNT(右表列)`**（不是 `COUNT(*)`），或先聚合再用 `IFNULL/COALESCE` 补 0。

核心坑点：① `COUNT(*)` 让 0 变成 1；② 关联条件只写一半 / 挪去 `WHERE` 导致左连接失效；③ 无关重复行时误加 `DISTINCT`（本题重复行就是多次考试，必须计数）；④ 忘记按 `student_id` 数值排序。

> 提交结果（2025-12-07 首次）：运行时间 **1599 ms**，击败 42.89%。若想提速，把思路 1 换成思路 2，或给 `Examinations(student_id, subject_name)` 建联合索引。
