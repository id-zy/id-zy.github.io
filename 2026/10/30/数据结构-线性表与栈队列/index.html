线性表、栈与队列：顺序存储和链式存储到底怎么选

学数据结构时最容易混的一件事：「线性表」是逻辑结构，「数组」和「链表」是存储方式。前者说的是「元素排成一条线、有前驱后继」，后者说的是「这条线在内存里怎么摆」。

这句话听起来像背诵题，但它决定了后面所有的复杂度结论。这篇从「逻辑 vs 存储」这个分界出发，把顺序表、链表、栈、队列讲成一条线，代码统一用 Python（能实跑，输出都是真实结果）。

一、先分清逻辑结构和存储结构

任何一个数据结构都可以从三个角度描述：

要素 问什么 线性表的答案
逻辑结构 元素之间什么关系 线性：除首尾外，每个元素有唯一前驱和唯一后继
存储结构 在内存里怎么放 顺序存储（连续）或链式存储（分散 + 指针）
数据的运算 能对它做什么 增删查改，各自的代价由存储结构决定

关键点：逻辑结构和存储结构是独立的两层。所以「线性表」不是一个具体的数据结构，而是一类；顺序表和链表是它的两种实现。

这也解释了为什么栈和队列要单独讲：它们的逻辑结构仍是线性（元素还是一条线），只是运算被限制了——栈只允许在一端进出，队列只允许一端进另一端出。所以「栈」和「队列」限制的是操作，不是存储，两者都可以用顺序或链式实现。

二、数组不是顺序表

这两个词经常被混用，但它们不在同一层：

数组 顺序表
是什么 一种存储方式（连续内存 + 下标访问） 一种数据结构（线性表 + 顺序存储 + 一组运算）
关注点 内存布局与寻址 增删查改的完整操作集
谁包含谁 数组是顺序表的底层实现手段 顺序表用数组来实现

一句话：数组偏「怎么存」，顺序表偏「能怎么用」。教材说「顺序表是用一组地址连续的存储单元依次存储线性表的数据元素」，这句话把两者绑在了一起——顺序表一定是数组实现的，但数组本身不一定是顺序表（比如二维数组、稀疏矩阵的压缩存储）。

三、顺序表：O(n) 的 n 到底在哪

顺序表的插入和删除是 O(n)，但很多人说不清「n 是什么」。它不是表的长度，而是需要搬动的元素个数。

这个 O(n) 在真实代码里有多疼

理论说 O(n)，实感要靠计时。同样插入 5 万次，一次从尾部插、一次从头部插：

117 倍。Python 的 list.insert(0, x) 底层是内存搬移（memmove，已经非常快），但搬 5 万次累计就是 12.5 亿次元素移动，这个量级跑不掉。

这解释了一个工程直觉：能用 append 就别用 insert(0)。需要「先进先出」时用 collections.deque，它在两端插入都是 O(1)——本质上是用双向链表补上了顺序表的短板。

四、链表：把「搬元素」换成「改指针」

链表的思路是彻底放弃连续性：元素散落在内存各处，每个节点额外存一个指针指向下一个节点。

于是插入变成三次指针赋值，与表长无关：

代价是失去了随机访问：想找第 k 个元素，只能从头一个个走，O(n)。

所以两种存储是彻底的交换关系：

操作 顺序表 链表
按位置访问 get(k) O(1) O(n)
在已知位置后插入 O(n)（要搬） O(1)（改指针）
在已知位置删除 O(n) O(1)
按值查找 O(n) O(n)
内存占用 紧凑，只有数据 每个节点多一个指针
扩容 要重新申请 + 复制 天然可增长

头结点那个「多余」的节点有什么用

教材里的链表常带一个不存数据的头结点（dummy head）。它的价值是消除边界特判：

  • 没有头结点时，在表头插入/删除要单独写一套代码（要改头指针本身）。
  • 有头结点时，表头和其他位置的操作完全一样（都是「改前一个节点的 next」）。

这是一个典型的「用一点空间换代码简洁」的设计。写链表题时加一个 dummy 头，能省掉大量 if head is None 的判断。

一个常被写错的地方

链表操作有两个高频 bug：

  1. 丢失后继：node.next = new 写在 new.next = node.next 之前，原来的后继就找不回来了。必须先连新节点的 next，再改前驱的 next。
  2. 删除时没释放：在 C 里忘记 free 是内存泄漏；在 Python 里没有这个问题，但逻辑上仍要先把节点摘下来（prev.next = node.next），不能只改值。

五、栈：只在一端进出

栈的限制是只在栈顶操作，先进后出（LIFO）。它的逻辑结构还是线性，只是运算被砍掉了一半。

「栈」在编程里到处都在，只是你没意识到：

  • 函数调用栈（递归的本质）
  • 括号匹配、表达式求值
  • 浏览器后退、编辑器的撤销
  • DFS 的非递归实现

两种实现：

顺序栈 链栈
底层 数组 + 栈顶指针 top 链表 + 头指针
入栈/出栈 O(1) O(1)
判满 需要（容量固定） 不需要（除非内存耗尽）
空间 预分配，可能浪费 按需分配，但每节点多一个指针

顺序栈的判空最容易写错：top 初始化为 -1 表示空栈，判空条件必须是 top == -1。写成 top == 1 或 top == 0 都不会报错，但逻辑全错——这类 bug 编译器不管，只在运行时表现成「栈永远非空」或「第一个元素丢失」。

Python 里栈直接用 list：append 入栈、pop 出栈，两端操作都是 O(1)。这也是为什么「用 list 当栈」是对的，而「用 list 当队列」是错的——pop(0) 是 O(n)。

六、队列：假溢出与循环队列

队列是先进先出（FIFO），一端进（队尾 rear）、一端出（队头 front）。

注意 size=5 而容量标称 5：循环队列牺牲了一个格子用来区分「队空」和「队满」。

为什么必须牺牲一格？因为如果用 front == rear 表示空，那「满」的时候 rear 绕一圈也会等于 front，两种状态没法区分。所以要么牺牲一格（(rear+1) % cap == front 判满），要么额外维护一个 size 变量。教材用前者，工程代码常用后者（Python 的 deque 就不需要）。

七、单调栈：把 O(n²) 压成 O(n)

单调栈是栈的一种特殊用法：栈内元素保持单调，用来在 O(n) 内找「某个元素左边/右边第一个更大（或更小）的元素」。

以「右边第一个更大的数」为例。核心动作是：新元素进栈前，先把栈顶那些「比它小的」全部弹掉——因为对这些被弹掉的元素来说，新元素就是它们右边第一个更大的数。

逐个验证：下标 0 的 2，右边第一个更大的是 4；下标 1 的 1，是 2；下标 3 的 4 右边没有更大的，所以是 -1。

为什么内层有 while 还是 O(n)

这是单调栈最容易被质疑的点。答案：每个下标最多进栈一次、出栈一次。while 循环的总执行次数受「入栈次数」约束，所以整体是 O(n)，而不是 O(n²)。

实测规模上去以后耗时基本线性：

数据量涨 1 万倍（10 → 100000），耗时涨约 4500 倍，接近线性但略优于线性（小规模时有固定开销）。

递增栈还是递减栈

这里最容易混。判据是**「栈里留下的是还没找到答案的元素」**：

  • 求「右边第一个更大」→ 栈内从栈底到栈顶递减（遇到更大的就把小的弹掉）
  • 求「右边第一个更小」→ 栈内递增

换个说法：你要找什么，就让栈保持相反的单调性。因为栈里留下的都是「还在等答案」的元素，一旦来了满足条件的，就把它们结算掉。

八、选型对照：先看「哪种操作最多」

把四种结构放在一起看：

结构 逻辑 存储 优势操作 典型用途
顺序表（数组） 线性 连续 随机访问 O(1) 下标访问、批量遍历、缓存友好
链表 线性 分散 + 指针 已知位置增删 O(1) 频繁插删、长度不定
栈 线性（受限） 两者皆可 栈顶增删 O(1) 括号匹配、递归、撤销、单调栈
队列 线性（受限） 顺序需循环、链式天然 队尾进队头出 O(1) BFS、任务调度、缓冲

选型的实际判据不是「哪个高级」，而是统计各操作的调用频次：

  • 读多写少、以遍历和下标访问为主 → 顺序表（还有缓存友好的隐性优势）。
  • 频繁在中间插删、长度变化大 → 链表。
  • 只在一端进出 → 栈；两端各进出一端 → 队列（顺序实现记得循环，链式实现天然合适）。
  • 需要「找最近的一个更大/更小」→ 单调栈，别写双重循环。

一个工程提醒：Python 的 list 是顺序表，collections.deque 是双向链表。所以「用 list 当栈」对（尾操作 O(1)），「用 list 当队列」错（pop(0) 是 O(n)）。

小结

  • 逻辑结构和存储结构是两层：「线性表」讲逻辑，「顺序/链式」讲存储。栈和队列是运算受限的线性表，不是新的逻辑结构。
  • 数组 ≠ 顺序表：数组是存储手段，顺序表是「数组 + 一组运算」的完整数据结构。
  • 顺序表插入删除 O(n)，那个 n 是要搬动的元素个数：表头搬 n 个、表尾搬 0 个、平均 n/2（实测 11 个位置共 55 个，平均正好 5.0）。
  • 实操感受：5 万次头插比尾插慢 117 倍（203.5 ms vs 1.7 ms）。需要 FIFO 就用 deque，别用 list.pop(0)。
  • 链表用改指针换掉搬元素：已知位置的增删 O(1)，但失去随机访问（O(n)）。加 dummy 头结点可以消掉表头的边界特判。
  • 顺序队列的假溢出是「rear 撞墙但前面有空位」；循环队列用取模复用空间，代价是牺牲一格来区分空和满（或额外维护 size）。
  • 单调栈在 O(n) 内找「右边第一个更大/更小」：每个下标只进栈出栈各一次，所以内层 while 不影响总复杂度。判据是「要求更大就让栈递减」，因为栈里留的都是还在等答案的元素。
