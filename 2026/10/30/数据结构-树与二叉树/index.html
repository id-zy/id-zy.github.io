树与二叉树：五条性质不是背的，是推的

数组和链表都是「一对一对」的关系：每个元素有一个前驱、一个后继。一旦数据变成一对多——目录里放文件、文件里放段落、段落里放字符——线性结构就装不下了。

树就是为「一对多 + 有层次」准备的。这篇从术语和存储讲到五条核心性质，再落到二叉搜索树和「用遍历序列还原一棵树」。所有性质都给了推导，代码都实跑验证过。

一、树：把一对多关系装进内存

递归定义：

树是 n（n ≥ 0）个结点的有限集合。n = 0 时是空树；n > 0 时，有且仅有一个根，其余结点可分成 m（m > 0）个互不相交的有限集，每个集合本身又是一棵树，称为根的子树。

两个词要盯住：

  • 有且仅有一个根——不能有两个，否则不是树
  • 互不相交——一个结点不能同时属于两棵子树，否则就成图了

「互不相交」这条排除了什么？排除了「一个孩子有两个父亲」。这也是树和图的根本区别：树 = 连通且无回路的图，n 个结点的树恰好有 n−1 条边。

二、术语不是背诵题，是后面所有公式的单位

术语 定义 后面用在哪
结点的度 该结点的子树个数 性质 3（n₀ = n₂ + 1）的核心变量
树的度 各结点度的最大值 判断是几叉树
叶子（终端结点） 度为 0 的结点 性质 3、哈夫曼树
分支结点 度 > 0 的结点 —
孩子 / 双亲 子树的根 / 其上层结点 三种存储结构全围绕它
兄弟 同一双亲的孩子 孩子兄弟表示法
层次 根为第 1 层，往下递增 性质 1、2、4
深度（高度） 结点的最大层次数 性质 2、4、平衡因子
森林 m 棵互不相交的树的集合 树 ↔ 二叉树转换

⚠️ 教材里「深度」和「高度」常常混用。本篇统一：根为第 1 层，空树深度为 0。有的书根算第 0 层，那样所有公式都要整体平移一位——先确认教材口径，再套公式，这是最常见的失分点。

三、三种存储结构：没有一种全能

1. 双亲表示法：一根数组搞定

每个结点只存「我的双亲在哪」。

  • 擅长：找双亲 O(1)——这正是并查集需要的（查根、合并集合，全是往上找）
  • 不擅长：找孩子要扫全表 O(n)

2. 孩子表示法：数组 + 链表

数组存结点，每个结点挂一条链表存自己所有孩子。

  • 擅长：找孩子 O(度)
  • 不擅长：找双亲要扫全表

3. 孩子兄弟表示法：把树变成二叉树

每个结点两个指针：左指针指第一个孩子，右指针指下一个兄弟。

这招的价值不在「存树」，而在存成二叉树后能直接复用所有二叉树算法——深度、遍历、查找，全套照抄。

对比

存储方式 找双亲 找孩子 空间 典型用途
双亲表示法 O(1) O(n) 紧凑 并查集
孩子表示法 O(n) O(度) 有链表开销 一般树的遍历
孩子兄弟表示法 要遍历 O(1) 找第一个孩子 较高 树 ↔ 二叉树转换

工程里还有第四种：左孩子右兄弟 + 双亲指针（三叉链表），三种能力全都要时就用它，代价是多一个指针。

树 → 二叉树 的转换规则

  1. 每个结点：左指针指第一个孩子，右指针指原树里的下一个兄弟；
  2. 根结点没有兄弟，所以转换后的二叉树根没有右子树；
  3. 森林转二叉树：各棵树的根依次当「右兄弟」串起来。

转换后的二叉树长这样：任何结点的右孩子，都是它原来那个兄弟。所以「森林」在二叉链表里就是「根 + 一串右链」。

四、二叉树：为什么要单独定义

二叉树不是「度最多为 2 的树」，它是一个独立概念：

一般树 二叉树
最大度数 无限制 2
子树顺序 可以有序也可以无序 严格区分左右
只有一个孩子时 不分左右 必须说明是左还是右
可以为空 可以 可以

最后两行是本质区别。一般树里「只有一个孩子」没有左右之分；二叉树里 只有左孩子 和 只有右孩子 是两棵不同的树。所以「二叉树有 5 种基本形态」：空、只有根、只有左、只有右、左右都有。

这个「必须分左右」的严格性带来一个好处：二叉树可以递归定义——二叉树 = 根 + 左二叉树 + 右二叉树，空树也是二叉树。递归定义让所有二叉树算法都能写成三行：

五、五条性质：逐条给证明

以下默认根为第 1 层，且讨论非空二叉树。

性质 1：第 i 层最多 2^(i−1) 个结点

证明（数学归纳）：第 1 层只有根，1 = 2⁰，成立。设第 i−1 层最多 2^(i−2) 个，每个结点最多两个孩子，所以第 i 层最多 2 × 2^(i−2) = 2^(i−1)。∎

性质 2：深度为 h 的二叉树最多 2^h − 1 个结点

证明：把各层最大值加起来，等比数列求和：

取等号时就是满二叉树。

性质 3：n₀ = n₂ + 1（叶子数 = 度为 2 的结点数 + 1）

这是最常考、也最容易「只背不推」的一条。证明用「数边」：

设度为 0、1、2 的结点数分别是 n₀、n₁、n₂，总结点 n = n₀ + n₁ + n₂。

从边的角度数：除根以外每个结点都恰好有一条边指向它，所以边数 B = n − 1。
从出度角度数：度 1 的结点出 1 条边，度 2 的出 2 条，叶子出 0 条，所以 B = n₁ + 2n₂。

两式相等：n₀ + n₁ + n₂ − 1 = n₁ + 2n₂，消项得 n₀ = n₂ + 1。∎

顺带验证了另一条常考结论：n 个结点的二叉链表有 n+1 个空指针域。推导同样简单：总共 2n 个指针槽，非空指针 n−1 个（每条边一个），所以空的是 2n − (n−1) = n+1。这条结论是线索二叉树的动机——空着浪费，不如拿来存遍历的前驱后继。

性质 4：n 个结点的完全二叉树深度为 ⌊log₂n⌋ + 1

证明：深度 h 的二叉树最多 2^h − 1 个结点，最少（因为是完全二叉树，前 h−1 层是满的）2^(h−1) 个。所以

取以 2 为底的对数：h−1 ≤ log₂n < h，即 h ≤ log₂n + 1 < h + 1，故 h = ⌊log₂n⌋ + 1。∎

性质 5：完全二叉树的编号关系

按层序从 1 开始编号，对结点 i：

关系 公式 前提
双亲 ⌊i/2⌋ i > 1
左孩子 2i 2i ≤ n
右孩子 2i+1 2i+1 ≤ n

为什么成立：层序编号就是「一层一层从左往右数」，第 1 层占 1 个编号，第 2 层占 2 个，第 k 层占 2^(k−1) 个。所以编号 i 的结点之后，它的两个孩子的编号必然紧邻着是 2i 和 2i+1——这是编号方式决定的，不是巧合。

这条性质就是数组存储完全二叉树的全部理论基础：不用存指针，父子关系靠算。

0-based 数组（Python、C 都这么写）公式换成：双亲 (i−1)//2，左孩子 2i+1，右孩子 2i+2。别把两套混用。

六、特殊二叉树：满、完全、斜

类型 定义 高度 h 时结点数
满二叉树 每个分支结点都有左右孩子，叶子全在同一层 恰好 2^h − 1
完全二叉树 与同高度满二叉树的编号 1…n 一一对应 落在 [2^(h−1), 2^h − 1]
斜树 所有结点只有左（或只有右）孩子 恰好 h

三者的关系：满二叉树一定是完全二叉树，反之不成立。

完全二叉树的三个常用结论

  1. 叶子只出现在最后两层；
  2. 度为 1 的结点最多一个，且它只有左孩子（因为编号必须连续靠左）；
  3. n 个结点时，叶子数 = ⌈n/2⌉——由性质 3 和「度 1 结点至多一个」推得。

完全二叉树为什么是堆的地基

堆要求「结构性」：一棵完全二叉树，用数组存一点空间都不浪费（编号 1…n 连续，数组刚好 n 格），而且父子关系 O(1) 算出来。

如果堆用一般二叉树，就退化成链式存储——指针跳来跳去，缓存全不命中，堆排序的常数项会难看很多。

七、顺序存储 vs 链式存储：什么时候别用数组

顺序存储（数组） 链式存储（二叉链表）
适用 完全 / 满二叉树 任意二叉树
找孩子 O(1)（算下标） O(1)（读指针）
找双亲 O(1)（i//2） O(h)（要遍历）或加 parent 指针
空间 紧凑，但非完全二叉树浪费 每结点 2 个指针
典型 堆 一般二叉树、BST、AVL

浪费有多严重？ 右斜树（每个结点只有右孩子）是最坏情况：深度 h 需要 2^h − 1 个槽位，实际只存 h 个。

高度 20 就该用 104 万个格子存 20 个结点——指数级浪费。所以判据很干脆：

  • 形态能保证接近完全（堆）→ 数组，省指针、缓存友好
  • 形态不可控（BST、表达式树）→ 二叉链表
  • 要频繁找父结点（AVL 旋转、并查集式回溯）→ 三叉链表，多一个 parent

八、二叉搜索树：把「翻字典」变成结构

定义与一句话价值

对任意结点，左子树所有值 < 它 < 右子树所有值，且左右子树也是 BST。

这条约束的副产品是：中序遍历 BST 得到递增序列。所以 BST = 「有序表 + 对数级查找」的组合，而数组的有序表插入要 O(n) 挪元素，BST 插入只要 O(h) 改指针。

查找与插入

查找的平均成本是树的平均深度，不是 log n——这个区别决定了 BST 的成败。

删除：三种情况，只有第三种麻烦

  1. 叶子：直接删，父结点指针置空；
  2. 只有一个孩子：用孩子顶替自己；
  3. 两个孩子：不能直接删。做法是用中序后继（右子树最小值）替换值，再递归删掉那个后继结点——后继最多只有一个右孩子，问题归约成情况 2。

选「中序后继」而不是「中序前驱」都行，但必须始终选同一边，否则删完的树形态不稳定。

BST 的复杂度是 O(h)，而 h 取决于插入顺序，不是结点数。实测 n = 1000：

九、二叉树的还原：为什么前序 + 中序能唯一确定

核心逻辑：根在哪 + 左右怎么分

  • 前序 [根][左子树全部][右子树全部]：第一个一定是根；
  • 中序 [左子树全部][根][右子树全部]：根的位置把序列切成左右两段；
  • 拿到「左右各几个」之后，前序里也能切出对应的两段——于是递归。

以前序 [3, 9, 20, 15, 7]、中序 [9, 3, 15, 20, 7] 为例：

哪些组合能唯一确定

组合 能否唯一还原 原因
前序 + 中序 ✅ 前序定根，中序分左右
后序 + 中序 ✅ 后序最后一个定根，同样分左右
层序 + 中序 ✅ 层序第一个定根
前序 + 后序 ❌（一般不行） 只能定根，分不清「只有一个孩子时它在左还是右」

前序 + 后序唯一的情况是每个结点都是 0 或 2 个孩子（真二叉树）——这时不存在「单孩子」的歧义。

十、小结

  • 树是「一对多 + 有层次 + 子树互不相交」。n 个结点的树有 n−1 条边，这是所有计数的起点。
  • 三种存储各缺一角：双亲擅长往上找（并查集），孩子擅长往下找，孩子兄弟表示法的价值是把树变成二叉树，从而复用二叉树全部算法。
  • 二叉树的本质是「有序」：单孩子必须分左右，所以能递归定义，所以算法都写成三行。
  • 五条性质都能推：性质 3 用「数边」两式联立（n₀ = n₂ + 1），性质 4 用 log 夹逼，性质 5 是编号方式决定的。附带结论：n 个结点的二叉链表有 n+1 个空指针域（线索二叉树的动机）。
  • 顺序存储只在「接近完全」时划算：右斜树高度 20 要 104 万个格子存 20 个结点。堆能省，是因为完全二叉树不浪费。
  • BST 的复杂度是 O(h) 不是 O(log n)：实测 n=1000 时随机插入高度 23、有序插入高度 1000，查找总步数 12493 vs 500500。这就是 AVL / 红黑树存在的理由。
  • 前序 + 中序能唯一还原，前序 + 后序不能。把「找根」换成哈希表，最坏情况从 O(n²) 降到 O(n)（n=2000 快 34.5 倍）。
