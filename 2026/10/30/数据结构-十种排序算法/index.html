十种排序算法：复杂度表之外的四个真相

排序是算法课的第一章，也是最容易被「背复杂度表」糊弄过去的一章。但真到选型时会发现，那张表几乎不足以做决定：

  • 冒泡和插入都是 O(n²)，实测差 2 倍；
  • 选择排序的「最佳」和「最坏」完全一样，因为它压根不看数据长什么样；
  • 计数排序理论上是 O(n+k) 的线性算法，实测比快排慢 3 倍——因为 k 才是瓶颈；
  • 堆排是 O(n log n) + O(1) 空间的完美组合，实测却比快排慢 2.4 倍。

这篇把十种排序放在一起，用同一台机器、同一批数据跑一遍，再解释每个数字背后「表上看不到」的原因。所有数据都是本机 Python 实跑的输出。

一、先看总表

算法 最好 平均 最坏 额外空间 稳定性 一句话
冒泡 O(n) O(n²) O(n²) O(1) ✅ 教学用，实际不用
插入 O(n) O(n²) O(n²) O(1) ✅ 小数组/基本有序的最优解
选择 O(n²) O(n²) O(n²) O(1) ❌ 交换次数最少（≤n−1 次）
希尔 O(n) ~O(n^1.3) O(n²) O(1) ❌ 插入排序的加速版
归并 O(n log n) O(n log n) O(n log n) O(n) ✅ 稳定 + 可外部排序
快排 O(n log n) O(n log n) O(n²) O(log n) ❌ 实践最快，但怕最坏
堆排 O(n log n) O(n log n) O(n log n) O(1) ❌ 最坏也能保证，缓存不友好
计数 O(n+k) O(n+k) O(n+k) O(k) ✅ 非比较，k 是值域
基数 O(n·d) O(n·d) O(n·d) O(n+k) ✅ 非比较，d 是位数
桶 O(n) O(n+k) O(n²) O(n+k) ✅ 依赖分布均匀

三处容易被表骗的地方，后面逐条实测：

  1. 「最好/最坏」不是摆设：插入排序最好 O(n)、最坏 O(n²)，差 n 倍；选择排序三栏一样，说明它对输入完全无感。
  2. 空间那一列的 O(n) 是真金白银：归并要复制整个数组，n=10⁷ 的 int 就是几十 MB。
  3. 非比较排序的复杂度里藏着一个 k：k 是值域不是元素个数，k 大起来能把线性算法拖死。

二、O(n²) 三种：为什么只有插入常用

冒泡：相邻交换，一趟定一个最大值

两个细节决定它是 O(n) 还是 O(n²)：

  • 内层 range(n-1-i)：已经排好的尾部不用再比。写成 range(n-1) 也能排对，但白做了 n(n-1)/2 次冗余比较。
  • swapped 标志：已有序时一趟就退出，最好情况 O(n)。去掉这个标志，冒泡在任何输入下都是 O(n²)。

插入：像打扑克摸牌

  • 写 a[j-1] > t 而不是 >= t——用 > 才能保持稳定（相等的元素不会被越过）。
  • 全程只做「赋值」不做「交换」，一次移动代替三次赋值（交换要临时变量），这是它比冒泡快的直接原因。

选择：每趟选最小，交换次数最少

选择排序的唯一优势是交换次数：无论数组多长，最多交换 n−1 次。如果「交换」本身很贵（比如元素是几百字节的大结构体），选择排序反而有竞争力。

四个读数：

  1. 已有序时冒泡 0.09 ms、插入 0.13 ms——都是 O(n)，一趟扫完就结束。冒泡甚至比插入还快一点点，因为 swapped 判断比赋值还便宜。
  2. 选择排序四行都是 90~97 ms——这是「最佳 = 最坏 = 平均」的实证。它永远要做 n(n−1)/2 次比较，数据长什么样都不影响。这也意味着选择排序完全无法利用输入的有序性。
  3. 插入比冒泡稳定地快约 2 倍（120 vs 220）。原因就是上面说的：插入用「赋值挪位」，冒泡用「三次赋值的交换」。
  4. 大量重复数据时插入 103 ms，比随机的 120 ms 还快——因为重复值不会触发挪动（> 不成立），挪动次数少了。

结论：这三种都别用在生产里。但如果面试要求手写，写插入——它代码最短、常数最好、还稳定，而且它是后面希尔和 Timsort 的地基。

三、希尔排序：给插入排序装个加速器

插入排序有个致命弱点：如果最小值在末尾，它要一路挪过整个数组（O(n) 次移动）。数据「越乱、越远」越慢。

希尔的思路：先按大间隔做插入排序，让元素大步跳到大致位置，再逐步缩小间隔做精细调整。

为什么这么快？ 因为 gap 大的时候每个子序列很短（只有 n/gap 个元素），插入排序在小数组上本来就快；gap 缩小时数组已经「大致有序」，插入排序在基本有序的数据上是接近 O(n) 的。两个优势叠在一起。

代价：希尔是不稳定的——元素按 gap 跨组跳跃，同组内的相对顺序被打乱，跨组之间更没有保证。

复杂度取决于间隔序列

间隔序列 最坏复杂度
n/2, n/4, ..., 1（Shell 原始） O(n²)
2^k − 1（Hibbard） O(n^1.5)
3h + 1（Knuth） O(n^1.5)
Sedgewick 序列 约 O(n^1.3)

gap //= 2 是最常见也最容易写的，但它是最差的一种——小间隔之间互为倍数时会重复比较同一批元素。真要优化就换 Knuth 的 3h+1（1, 4, 13, 40, 121, ...）。

四、归并排序：稳定 + O(n) 空间

分治：拆到单元素（天然有序），再两两合并。

三个要点：

  1. <= 而不是 <：相等时优先取左边的，左半边本来就排在前面，于是稳定性成立。这一个符号就是归并「稳定」的全部秘密。
  2. 必须新开数组：合并结果没有地方放（原地合并是另一套算法，复杂得多），所以空间 O(n)。
  3. 复杂度与输入无关：不管有序还是逆序，永远 log n 层、每层 n 次合并，所以最好=最坏=平均。这是优点（可预测）也是缺点（已有序时白干活）。

归并的真正主场

  • 外部排序：数据大到装不进内存时，只能「读一块、排一块、写回磁盘、再归并」，归并是唯一天然适配这个流程的算法。
  • 链表排序：链表合并只要改指针、不需要额外空间，归并就成了 O(1) 空间的最优解。
  • 求逆序对：合并时「右边先出」的次数就是跨区间的逆序对数，归并顺手就能统计。

五、快速排序：实践最快，但怕最坏

分区：选一个基准，把小于它的扔左边、大于它的扔右边，基准就位，然后递归两边。

为什么必须随机化

固定取第一个元素当基准时：输入已经有序 → 每次分区都把数组切成「1 个 + n−1 个」→ 递归 n 层 → O(n²)。

这在现实里不是理论问题：对着「已按时间排好序的日志」再按时间排一次，是最常见的输入。随机化把「最坏输入」变成「概率极小的随机事件」，期望复杂度回到 O(n log n)。

四个优化，都要知道

优化 做法 解决什么
随机基准 / 三数取中 随机选或取首中尾的中位数 避免有序输入退化
小数组切插入排序 长度 < 16 时直接插入排序 递归到小数组时函数调用开销大于比较开销
三路分区（荷兰国旗） 分成 < = > 三段 大量重复元素时避免重复递归相等段
尾递归优化 只对较短的一边递归，长的一边循环 把栈深度压到 O(log n)

三路分区值得单独说：两路分区遇到「全是同一个值」的数组时，每次分区都只切掉一个元素（其他都等于基准），退化成 O(n²)。三路分区一次就把所有相等元素归位，直接规避。

六、堆排序：最坏也有保证，但缓存不友好

堆排序的独特价值：唯一同时具备 O(n log n) 最坏复杂度和 O(1) 额外空间的比较排序。

  • 归并：O(n log n) 但要 O(n) 空间；
  • 快排：O(1) 空间但最坏 O(n²)；
  • 堆排：两个都要，代价是常数项大。

「常数项大」有多大？实测 n=200000：快排 234.9 ms、堆排 561.1 ms，堆排慢 2.4 倍。原因是堆的访问模式是「i → 2i+1 → 4i+3」这种跳跃，CPU 缓存几乎全部不命中；快排是顺序扫，缓存命中率高。

所以工程上：内存不是极限时用快排；内存卡死（嵌入式、内核栈）或要求最坏时间保证（实时系统）时才用堆排。

七、三种非比较排序：不是「更快的比较排序」

它们根本不比较元素大小，靠「值的分布信息」直接定位。所以能突破 O(n log n) 下界——前提是你知道值域。

计数排序：数一数每个值出现几次

两个关键：

  • 为什么要前缀和：cnt[v] 从「v 出现了几次」变成「≤v 的元素有几个」，于是 cnt[v]-1 就是 v 在结果里的最后一个位置。
  • 为什么必须逆序遍历：正序的话，后出现的相等元素会被放到更前面的位置，稳定性崩掉。逆序填充是计数排序稳定的唯一原因。

复杂度里的 k 是陷阱。实测 n=200000、值域 10⁷（随机取 0~10⁷ 的数）：

计数排序比快排慢了 3 倍！因为 k = 10⁷，那个 cnt 数组要跑 1000 万次前缀和累加，而 n 只有 20 万——k 主导了总成本。

所以计数排序的适用条件是 n 大、k 小：年龄（0150）、成绩（0100）、ASCII 字符（0~255）。反过来「用户 ID」就绝对不能用。

基数排序：按位排，从低位到高位

为什么从低位开始？ 因为「高位优先」需要递归分组（先按高位分桶，桶内再按低位排），而「低位优先」只要一轮轮稳定地分配-收集，高位最后一趟定胜负。这依赖每一趟的分配（追加到桶尾）和收集（按桶顺序取出）都是稳定的——基数排序的稳定性是从这里来的，而不是自己实现的。

实测 n=200000（7 位数）：151.6 ms，比快排还快 1.5 倍。因为 7 趟线性扫描 ≈ 7n 次操作，而 n log n ≈ 200000×17.6。

代价是空间：每趟要开 10 个桶（或 n 的辅助数组）。负数还要特殊处理（统一加偏移，或者分成正负两部分各排一次再拼）。

桶排序：先分区间，桶内再排

实测 88.1 ms，是十种里最快的——但别急着记住这个结论，它成立的原因很苛刻：

  • 数据是均匀随机的（我用的 random.sample），所以每个桶里只有约 20 个元素，插入排序在 20 个元素上几乎免费；
  • 桶的数量由「值域 / 桶大小」决定，本例是 10000 个桶。

如果数据全挤在一个桶里，桶排序就退化成一个桶内的 O(n²) 插入排序。所以桶排序的复杂度会写「最好 O(n)、最坏 O(n²)」——它好不好，取决于你对数据分布的了解程度。

八、稳定性：四个最小反例

「稳定」的意思是：相等的元素，排序后相对顺序不变。这在多关键字排序里是硬需求——先按姓名排、再按分数排，如果第二轮不稳定，同分的人姓名顺序就被打乱了。

理论结论是：冒泡、插入、归并、计数、基数、桶 稳定；选择、希尔、快排、堆排 不稳定。

四个反直觉的读数，逐个解释：

  1. 计数排序垫底（720.6 ms）：O(n+k) 里的 k=10⁷ 远大于 n=2×10⁵，前缀和那段是纯浪费。非比较排序的优势以「值域小」为前提。
  2. 堆排 561.1 ms 输给快排 234.9 ms：同为 O(n log n)，差在缓存。堆跳跃访问、快排顺序访问，现代 CPU 上这个差距是常数项里最大的一项。
  3. 归并 356.7 ms 比快排慢约 1.5 倍：Python 里切片 a[:m] 会复制，合并又新建列表，内存分配成本全摊在结果里。C/C++ 里这个差距会小很多（可以用预分配的辅助数组）。
  4. 桶排序最快（88.1 ms）但最不可靠：它的成绩建立在「均匀随机 + 值域已知 + 桶大小调得合适」三个前提上，换一批数据就可能变成最慢的。

怎么选：一张决策图

再补三条工程常识：

  • sorted() / Arrays.sort() 不是任何一种教科书算法。Python 用的是 Timsort（归并 + 插入的混合，稳定，2023 年起还加了 galloping 优化），Java 对基本类型用双轴快排（不稳定）、对对象用 Timsort（稳定）。自己手写快排几乎不可能快过标准库。
  • 小数组（n < 50 左右）直接插入排序，别递归。CPython 的 list.sort 在长度小于 64 时就是直接走二分插入排序。
  • 「基本有序」是很值钱的性质。插入排序在基本有序时接近 O(n)，Timsort 正是靠识别「已有的有序片段（run）」把常见场景做到接近线性。

十、小结

  • O(n²) 三种里只有插入有实用价值：它常数最小、稳定，还是希尔和 Timsort 的地基。选择排序的唯一卖点是「交换次数 ≤ n−1」。
  • 选择排序对输入完全无感：实测四类输入都是 90~97 ms。「最佳=最坏=平均」不是笔误，是它不看数据。
  • 希尔是「改两行换 38 倍」的性价比之王（插入 120 ms → 希尔 3.16 ms），代价是不稳定。gap //= 2 是最差的一种间隔序列，要优化换 3h+1。
  • 归并的 <= 就是它的稳定性；它的主场是外部排序、链表排序和求逆序对。
  • 快排必须随机化，否则有序输入直接退化成 O(n²)。四个优化（随机基准、小数组插排、三路分区、尾递归）分别解决退化、常数、重复元素、栈深。
  • 堆排是唯一「O(n log n) 最坏 + O(1) 空间」，但实测比快排慢 2.4 倍，输在缓存。
  • 非比较排序不是「更快的比较排序」：计数排序在值域 10⁷ 时比快排慢 3 倍；桶排序最快但最依赖分布。
  • 稳定性要用「原始下标标记」验证，光看数值看不出来。最小反例：选择 [2a,2b,1a]、快排 [2a,1a,1b]、堆排 [1a,1b,1c]、希尔 [1a,2a,1b,1c]。
