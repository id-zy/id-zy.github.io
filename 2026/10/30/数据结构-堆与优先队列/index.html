堆与优先队列：只保父子有序，为什么就够用了

普通队列按「先进先出」出队，优先队列按「优先级高者先出」出队——听起来只是换个出队规则，但要把它实现得又快又能动态插入，反而没有一种平凡结构能同时满足。

有序数组插入 O(n)、无序数组取出 O(n)、有序链表插入 O(n)——每种朴素结构总有一头是 O(n)。堆的价值就在于把两头都压到 O(log n)，代价是放弃全局有序，只维护「父子有序」。

这个取舍换来了什么？看实测：50 万次插入 + 50 万次弹出的吞吐，堆比「每次 insort 的有序数组」快 50 倍。

一、优先队列：出队顺序由优先级定

普通队列 优先队列
出队规则 先进先出 优先级高者先出，与入队顺序无关
典型操作 enqueue / dequeue / front push / pop / peek
现实类比 排队买票 医院急诊分诊（危重先看）

关键在「与入队顺序无关」。所以优先队列不能用简单的「两头指针」实现——你必须随时知道「现在谁最大」。

二、三种实现，各有一头是 O(n)

实现 入队 出队（取最大） 问题在哪
无序数组 O(1) 尾插 O(n) 扫一遍找最大 出队慢
有序链表/数组 O(n) 找插入位置 O(1) 取头/尾 入队慢
二叉堆 O(log n) O(log n) 两头都不快，但都不慢

原因很现实：Python 的 bisect.insort 底层是 C 的 memmove，挪 2000 个 8 字节整数只要几微秒；而 heappush 虽然只有 log n 次交换，但每次都是 Python 层的比较 + 交换。小规模时常数项压倒复杂度。规模上去，O(n²) 的 insort 才对 O(n log n) 的堆彻底失守。

结论：N 小于几千时，别为了「理论上更优」上堆——有序数组或直接排序更省事。堆的优势从几万才开始显现。

三、堆：完全二叉树 + 只保证父子有序

堆 = 完全二叉树 + 堆序性：

  • 大顶堆：任意结点 ≥ 它的两个孩子（根是全局最大）
  • 小顶堆：任意结点 ≤ 它的两个孩子（根是全局最小）

⚠️ 注意「堆序性」只约束父子，不约束兄弟、更不约束整棵树。所以：

  • 堆不是二叉搜索树，中序遍历不会得到有序序列；
  • 堆的层序也不是排序结果（第二层两个结点的大小随意）；
  • 唯一能确定的是：根是全局极值，且每条根到叶的路径单调。

这个「弱保证」恰好够用，因为优先队列只需要两件事：快速拿到极值（根，O(1)）、删掉它之后快速恢复（下移，O(log n)）。

为什么必须是完全二叉树

因为完全二叉树能用数组零浪费地存：编号连续、父子关系靠算、不需要任何指针。换成一般二叉树，就得用链式存储，指针跳转带来缓存不命中和额外内存。

这是「形态约束换存储效率」的典型案例——堆牺牲了树的形态自由度，换来数组存储和 O(1) 的父子定位。

四、用数组存堆：编号公式

0-based 数组（Python、C 的写法）：

关系 公式
结点 i 的双亲 (i - 1) // 2
结点 i 的左孩子 2*i + 1
结点 i 的右孩子 2*i + 2
最后一个非叶结点 n//2 - 1
叶子范围 下标 n//2 到 n-1

最后两行很实用：建堆时只需从 n//2 - 1 往前扫，叶子天然满足堆序，不用处理。

教材的 1-based 版本是 i//2、2i、2i+1——两套混用是堆代码 off-by-one 的第一大来源。本文全部用 0-based。

五、上移 shift-up：插入

插入只有两步：放到数组末尾（保持完全二叉树的形态），然后往上冒（恢复堆序）。

两个细节：

  • 循环条件写 i > 0，不要写 (i-1)//2 >= 0。后者在 Python 里靠 -1 // 2 == -1 侥幸成立，换语言（C 的整数除法向零取整，-1/2 == 0）就死循环。
  • break 是正确性的一部分：一旦不比父亲大，再往上也不可能大（因为父亲本来就 ≥ 祖父），所以可以直接停。

上移最多走「树高」步，即 O(log n)。

六、下移 shift-down：弹出堆顶

弹出不能直接删根——删了根，树就散了。标准做法是把根和末尾交换，弹出末尾（原根），再让新根往下沉：

为什么要「先选出较大的孩子」？ 如果直接和左孩子换，换完之后右孩子可能比新位置的值还大，堆序又破了，得回头再修。所以每层只跟「较大的那个孩子」换，一次到位。

七、建堆为什么是 O(n)，不是 O(n log n)

如果对 n 个元素逐个 heappush，是 O(n log n)。但原地建堆（heapify）可以做到 O(n)：从最后一个非叶结点开始，往前对每个结点做一次下移。

为什么是 O(n)？ 关键在于「越往下，结点越多，但下沉距离越短」：

  • 高度为 h 的结点最多 n / 2^(h+1) 个
  • 每个这样的结点最多下沉 h 层
  • 总代价 Σ h · n / 2^(h+1) = (n/2) · Σ h/2^h，而 Σ h/2^h = 2（收敛的几何级数）

所以总代价是 (n/2) × 2 = n，即 O(n)。

反过来，如果从上往下建（每个结点上移），代价是 Σ (n - h) 级别，主导项是那些「数量最多、却要爬最高」的底层结点，结果就是 O(n log n)。

2. 要最大堆：全部取负

九、堆的四个易错点

1. 把堆当有序结构用

堆只保证父子有序。heap[0] 是最小值，heap[1] 不一定是第二小。要按顺序取全部元素，只能反复 pop（O(n log n)），或者干脆排序。

2. 改元素后不修堆

heapq 没有 decrease-key。改完某个元素的值，堆序就被破坏了，但你不知道它在数组里的位置（除非自己维护「元素 → 下标」映射）。

Dijkstra 的常见写法就是绕开这个问题：不修改旧元素，直接 push 一份新的，出队时如果发现是过期版本就丢弃（lazy deletion）。代价是堆里可能有重复元素，空间变大但代码简单。

3. 混淆 heappushpop 和 heapreplace

函数 先做什么 返回 适合
heappushpop(h, x) 先压入再弹出 弹出后的最小值 新元素可能比堆顶还小（此时原样返回 x，等价于没进堆）
heapreplace(h, x) 先弹出再压入 被弹掉的旧堆顶 确定新元素需要进堆

两者都是 O(log n) 但语义不同，用反了会少一个元素或多一个元素。

4. 大顶堆取负的溢出/精度问题

用浮点数取负没问题；但如果是「无符号整数」或「超过 double 精度的定点数」，取负可能溢出或丢精度。这时要么用「反向比较对象」，要么看语言是否支持自定义比较器（C++ priority_queue 可以直接传 greater<T>，Java 传 Comparator.reverseOrder()）。

十、小结

  • 优先队列的关键是「出队顺序由优先级决定」，所以朴素结构总有一头是 O(n)：无序数组出队 O(n)、有序结构入队 O(n)。
  • 堆把两头都压到 O(log n)，代价是放弃全局有序，只保父子。而优先队列正好只需要「快速拿极值 + 快速恢复」。
  • 完全二叉树是堆的地基：只有形态接近完全，才能用数组零浪费存储、靠公式算父子。
  • 上移 O(log n)、下移 O(log n)；下移每层约 2 次比较（先选大孩子再比自己），实测平均 pop 比较次数 ≈ 1.5 × log₂n。
  • 建堆是 O(n) 不是 O(n log n)：因为「结点越多的地方下沉越浅」，Σ h/2^h 收敛到 2。实测 heapify 比逐个 push 快 1.55→3.80 倍（规模越大差距越大）。
  • heapq 是最小堆；最大堆用取负；要稳定就用 (priority, seq, item) 三元组；Top-K 用 nlargest（n=10⁶ 时比全排快 15 倍）。
  • 小规模别迷信堆：N=2000 时有序数组和堆打平（1.19 倍），到 50 万才拉开 50 倍。常数项在小规模时比复杂度更重要。
