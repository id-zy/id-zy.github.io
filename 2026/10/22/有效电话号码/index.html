193. 有效电话号码

难度：简单 | 题号：193 | 链接：193. 有效电话号码 - 力扣（LeetCode） | 数据结构：Shell（正则 / grep）

关联：统计词频（同为 Shell 管道题，本文考「正则筛行」，那题考「管道聚合」）· 「逐项校验」思维可对照 有效的数独（校验规则要一次写全，漏一项就误判）。

🎯 问题描述

描述：给定一个包含电话号码列表（一行一个电话号码）的文本文件 file.txt，写一个单行 bash 脚本输出所有有效的电话号码。

有效号码只有两种格式（x 为数字 0-9）：

  • xxx-xxx-xxxx
  • (xxx) xxx-xxxx —— 右括号后必须有一个空格

提示：

  • 判据是「整行匹配」，不是「行内含有一个像电话号码的子串」→ 行首 ^ / 行尾 $ 锚点不能省。
  • 两种格式的公共后缀是 [0-9]{3}-[0-9]{4}，差异只在前缀：[0-9]{3}- 或 \([0-9]{3}\) 。
  • 花括号量词 {3} 在 grep 里要转义成 \{3\}（-E / -P 模式下不用转义）。

💻 解题思路

思路 1：grep -P + PCRE 正则（用户解法）

核心逻辑

用 PCRE 模式写一条完整正则：^ 开头 →「前缀二选一」→ 公共后缀 → $ 结尾。只要整行匹配就输出该行，grep 默认就是"筛行"，不需要额外动作。

📊 性能分析

  • 时间复杂度：O(n⋅m)O(n \cdot m)O(n⋅m)，nnn 行数、mmm 行均长（正则为线性回溯的有限状态匹配，无嵌套量词所以不会灾难性回溯）。
  • 空间复杂度：O(1)O(1)O(1)（逐行流式匹配，不缓存全文）。

思考

  • -P 与 -E 的区别是本题的分水岭：-P 走 PCRE，\( 表示字面括号、\d 可用；-E 走 POSIX ERE，\d 不支持（必须写 [0-9]），括号同样要转义。用户写法在 -P 下正确；若换成 -E 则必须删掉 -P 并确认 \( \) 仍是转义写法（ERE 下 \( 也是字面括号，可通用）。
  • Mac / BSD grep 没有 -P：本机跑得通、换 Mac 就报 invalid option -- P。跨平台要退到 -E：
  • 漏了 ^ / $ 会误判：1234 987-123-4567 这种"行内包含合法号码"的行会被错误输出 —— 这正是"校验"与"搜索"的区别。
  • 括号后的空格是一处易漏细节：写成 \([0-9]{3}\) 而不跟空格，会漏掉全部 (xxx) xxx-xxxx 格式。

思路 2：awk 整行正则

核心逻辑

awk 的「模式 {动作}」中只写模式、不写动作时，默认动作是 print $0。用 ERE 正则作模式即可，等价于 grep -E。

📊 性能分析

  • 时间复杂度：O(n⋅m)O(n \cdot m)O(n⋅m)，与 grep 同阶（awk 是解释执行，常数项略大）。
  • 空间复杂度：O(1)O(1)O(1)。

思考

  • 也可用 sed -nE '/regex/p' file.txt，三种写法思路一致：「整行正则 → 打印匹配行」。
  • awk 里把前缀写成 (\([0-9]{3}\) |[0-9]{3}-)（把空格放进第一分支），可以省掉外层再套一组括号，等价但更短。

📝 总结

Shell 正则校验题的模板：grep/awk + 带 ^…$ 锚点的完整正则 + 二选一前缀。

核心坑点：① 忘写行首行尾锚点 → 变成子串搜索；② 量词 {3} 在基础正则里要转义；③ -P（PCRE）与 -E（ERE）的能力差异，跨平台优先 -E；④ 格式里的空格必须一字不差。

一句话：校验型正则的第一原则是「锚死两端」，否则你测的不是"这行是不是电话号码"，而是"这行里有没有电话号码"。
