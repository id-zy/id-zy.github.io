换座位

难度：中等 | 题号：626 | 链接：626. 换座位 | 数据结构：sql

🎯 问题描述

描述：

表 Seat 存了学生的座位号 id（连续递增）和学生姓名 student。要求相邻的两个学生互换座位：1↔2、3↔4、5↔6……

如果学生总数是奇数，最后一个学生的座位保持不变。

返回结果按 id 升序排列。

提示：

  • id 是连续递增的整数（无空洞），所以「id 的奇偶」等价于「行的位置奇偶」。
  • 只有 3 行时，第 3 行不动。

💻 解题思路

思路 1：按奇偶分三种情况改 id（IF 嵌套）

这道题的关键不是「交换数据」，而是**「给每一行算一个新 id」**——行本身不用动，只要把 id 重排，ORDER BY 就完成了交换。

一共只有三种情况：

行的位置 新 id 说明
偶数行（id & 1 = 0） id - 1 和前一行换
奇数行，且不是最后一行 id + 1 和后一行换
奇数行，且是最后一行 id 人数为奇数，原地不动

核心逻辑

「是不是最后一行」必须判 id = 总行数，不能只看奇偶：否则奇数行的最后一行会算出 id + 1，凭空多出一个座位。

代码实现

& 是按位与，id & 1 取最低位：偶数得 0、奇数得 1，比 id % 2 更短。

📊 性能分析

  • 时间复杂度：O(n log n)。扫描是 O(n)，ORDER BY id 的排序是 O(n log n)；子查询 (SELECT COUNT(*) FROM seat) 不引用外层列，属于非相关子查询，MySQL 8 只会执行一次，不会退化成 O(n²)。
  • 空间复杂度：O(1)（不计排序所需的临时空间）。

如果把子查询写成引用外层 id 的相关子查询（例如逐行 COUNT(*) WHERE id <= s.id），就会变成 O(n²)——两者看起来只差一个条件，代价差一个数量级。

思考

三个值得记住的点：

  1. 改 id 不改行。交换的本质是「重排标签」，比重排数据简单得多。
  2. 边界单独处理。奇数长度时最后一行是唯一例外，id = COUNT(*) 是唯一的判据。
  3. ORDER BY id 排的是别名。SQL 的 ORDER BY 优先解析 SELECT 列表里的别名，所以这里按「新 id」排序；如果把别名改掉（AS new_id），这里必须同步改，否则会按旧 id 排出一条「没换过」的结果。

  • 同类题目：判断三角形（同为 SQL 题，用条件表达式生成新列）

📝 总结

  • 交换类问题先问「交换的是什么」：这里是 id（标签），不是行内容。
  • 三种情况用两层 IF 表达，读起来比 CASE 嵌套更接近数学分段函数。
  • 非相关子查询只算一次，别把它当成 O(n²) 的罪魁祸首；真正的成本通常在排序。
  • ORDER BY 认别名——改 SELECT 的别名时，ORDER BY 要一起改。
