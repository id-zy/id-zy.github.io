Java 运算符：整数除法、短路，以及那个 -1

运算符是编程里最不设防的一块：语法一眼就懂，所以出错时第一反应总是「逻辑写错了」，而不是「这个符号本身的行为和我想的不一样」。

但真正在项目里造成事故的，往往就是这些符号的默认行为。整数除法把 0.5 悄悄吃掉，% 在负数上返回负值，浮点数比不出相等，位运算和比较混写直接编译不过。这些都不是 bug，是语言规定，只是没人提前告诉你。

这篇按「最容易误解」的顺序过一遍：算术、赋值、逻辑、位运算、优先级、浮点、三元。

一、整数除法截断，取余跟着被除数走

四个结果，两条规律：

  • 两个整数相除，结果还是整数，小数部分直接截断（不是四舍五入）。想要小数，至少一边得是浮点：7 / 2.0。
  • % 的结果符号跟被除数走，不跟除数。所以 -7 % 2 是 -1，7 % -2 是 1。

二、复合赋值能过、拆开写就编译不过

两行在做同一件事，一行过一行不过。原因分两步：

  1. byte / short / char 参与算术运算时会先提升为 int，所以 s + 1 的类型是 int。
  2. s = (int 值) 赋给 short 需要强转；而 s += 1 被规定为等价于 s = (short)(s + 1)，自带隐式强转。

结论：复合赋值不是简写，是简写 + 强转。需要保留精度时，别图省事。

顺带把比较运算符放这里： ==、!=、>、<、>=、<= 产出的都是 boolean。比基本类型比值，比引用类型比地址——所以字符串比较永远用 equals()。这条在后面字符串那篇会展开，但根因就在这里。

四、补码：~5 为什么是 -6

Java 的整数用补码存：正数原码即补码，负数取反加一。最高位是符号位，所以 int 的范围是 -2³¹ ~ 2³¹-1，负数比正数多一个。

补码的设计目的是让减法用加法实现，硬件只需要一套加法器。代价是一批反直觉的位运算结果。

设 a = 5、b = 3，实测：

表达式 结果 说明
5 & 3 1 都为 1 才 1
5 | 3 7 有一位 1 就 1
5 ^ 3 6 不同才 1
~5 -6 逐位取反，含符号位
5 << 1 10 左移等于乘 2
-5 >> 1 -3 高位补符号位
-5 >>> 1 2147483645 高位一律补 0

三个必须记住的性质：

  • ~n = -n - 1。~5 是 -6，不是 4。看到这个结果别怀疑编译器。
  • >> 与 >>> 在负数上完全不同。>> 补符号位，结果仍是负数；>>> 把符号位当普通位搬走，得到一个巨大正数。所以 >>> 处理负数几乎没有意义——它真正的用途是二分查找里避开溢出：mid = (low + high) >>> 1。
  • 移位数先对 32 取模。实测 1 << 32 是 1（不是 0），1 << 33 是 2。想清某一位别指望移位，直接赋值。

五、五个能直接抄的位运算套路

前两个值得知道原理，因为面试会追问：

  • n & -n 取最低位 1：-n 是取反加一。取反后最低位的 1 变 0、右边全变 1；加一时进位把那一位重新变回 1、右边归 0。相与时只有那一位两边都是 1。实测 6 & -6 = 2。
  • n & (n-1) 清最低位 1：n-1 把最低位的 1 变 0、右边全变 1，相与正好清掉它。实测 6 & 5 = 4。用它数二进制里 1 的个数，循环次数等于 1 的个数，比逐位扫快。

异或交换有个致命前提：a != b。a == b 时第一步 a ^= b 就把 a 清零，后面全错。这个技巧只在面试里有价值，工程里用临时变量。

六、优先级：只需记三条

完整优先级表有十几级，背它没有意义。实际只需要三条：

  1. && 高于 ||：a || b && c 等价于 a || (b && c)。
  2. == 高于 &：1 == num & 1 被解析成 (1 == num) & 1，即 boolean & int，直接报 bad operand types for binary operator '&'。
  3. 不确定就加括号。括号不花钱，猜优先级要花半小时。

第二条是位运算与比较混用时的标准翻车姿势。报错信息看起来像类型问题，实际是优先级问题：

还有个跨语言差异值得记：MySQL 里 & 的优先级高于等号，id & 1 = 0 能跑；Java 里反过来。同一条表达式换个语言就编译不过，结论是「跨语言一律加括号」。

三元运算符 条件 ? 值1 : 值2 有两条限制：

  • 两个分支的类型必须兼容——编译器要推导出唯一类型。一边 int 一边 String 直接报错。
  • 它是表达式不是语句，必须产出值，不能单独当一行调用。

七、浮点数：0.1 + 0.2 与金额红线

这不是 bug，是 IEEE 754 的必然：float / double 用二进制表示小数，而 0.1 在二进制里是无限循环小数，和十进制里的 1/3 一样。存进去的那一刻就已经截断了。

小结

  • 整数除法截断，% 的符号跟被除数；判奇数写 n % 2 != 0 或 (n & 1) == 1，别写 == 1。
  • 复合赋值 = 简写 + 隐式强转，所以 s += 1 能过、s = s + 1 不能。
  • && / || 短路是正确性基础（空判靠它），& / | 不短路，只在需要两边都执行时用。
  • 补码决定了 ~n = -n-1、>> 补符号位、>>> 补 0、移位数对 32 取模（1 << 32 是 1）。
  • 位运算五个套路：判奇偶、n & -n、n & (n-1)、异或交换（a != b）、取第 k 位。
  • 优先级只记三条：&& 高于 ||、 == 高于 &、不确定就加括号。
  • 浮点数永不比相等，金额用 BigDecimal（字符串构造）或「分」为单位的 long。
