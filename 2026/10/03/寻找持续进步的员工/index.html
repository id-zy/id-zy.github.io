3580. 寻找持续进步的员工

难度：中等 | 题号：3580 | 链接：3580. 寻找持续进步的员工 - 力扣（LeetCode）

关联：2016年的投资 · SQL-TopN查询（TopN 的 ROW_NUMBER / MAX(CASE WHEN) 套路）。

🎯 问题描述

描述：找出过去三次评估中持续提高绩效的员工。

规则：

  • 员工至少需要 3 次评估才能被考虑；
  • 过去 3 次评估（按 review_date 取最近 3 次）评分必须严格递增；
  • 进步分数 = 最近 3 次中最后一次评分 − 最早一次评分；
  • 结果按进步分数降序，再按名字升序排序。

提示：

  • 核心是「取每组最近 3 条 + 判断严格递增」，ROW_NUMBER() 按日期降序打号即可定位最近 3 次。

💻 解题思路

思路1：ROW_NUMBER 打号 + MAX(CASE WHEN) 转列（用户解法）

核心逻辑

① 按 employee_id 分组、review_date DESC 用 ROW_NUMBER() 打号，rn=1 是最近一次、rn=3 是三次前；
② 用 MAX(CASE WHEN rn=1/2/3 THEN rating END) 把最近三次评分转成三列；
③ HAVING COUNT(*) = 3 保证评估次数够 3 次；
④ WHERE r3 > r2 > r1 判断严格递增；进步分 = r3 - r1；最后 JOIN employees 取名字并排序。

⚠️ 变量名易混：这里 r1 = rn=3（三次前、最早），r3 = rn=1（最近、最新），命名是"反"的。递增条件 r3 > r2 > r1 对应的正是"最新 > 中间 > 最早"，逻辑没错，但建议改成 r_new / r_mid / r_old 更不易读错。

📊 性能分析

  • 时间复杂度：O(nlog⁡n)O(n \log n)O(nlogn)（窗口函数排序主导）。
  • 空间复杂度：O(n)O(n)O(n)。

思考

  • HAVING COUNT(*) = 3 与 WHERE rn <= 3 配合：不足 3 次的员工会被 COUNT(*) < 3 过滤掉，比先查"评估次数 ≥ 3"子查询更简洁。
  • 若存在同一员工同一天多条评估，需在 ORDER BY 里加 review_id 作为稳定次序（题目保证 review_id 唯一，实际数据可能要看业务定义）。

📝 总结

「取每组最近 N 条 + 判断单调」模板：ROW_NUMBER() ... DESC 打号 → rn <= N → 用 MAX(CASE WHEN rn=k) 转列（或 LAG），再比较单调性、算差值，最后 ORDER BY 输出。
