寻找用户推荐人

难度：简单 ｜ 题号：584 ｜ 链接：584. 寻找用户推荐人 - 力扣（LeetCode） ｜ 数据结构：sql

🎯 问题描述

表: Customer

±------------±--------+
| Column Name | Type |
±------------±--------+
| id | int |
| name | varchar |
| referee_id | int |
±------------±--------+
在 SQL 中，id 是该表的主键列。
该表的每一行表示一个客户的 id、姓名以及推荐他们的客户的 id。

找出以下客户的姓名：

  1. 被任何 id != 2 的用户推荐。
  2. 没有被 任何用户推荐。

以 任意顺序 返回结果表。

提示：referee_id 可能为 NULL。注意三值逻辑——NULL <> 2 的结果是 NULL 而不是 TRUE，不会进结果集，所以必须显式补 IS NULL。

💻 解题思路

思路 1：WHERE 直接过滤（推荐）

核心逻辑

把「符合条件」拆成两个分支做并集：

  • referee_id <> 2 —— 被非 2 号用户推荐；
  • referee_id IS NULL —— 没有任何用户推荐。

关键坑：只写 referee_id != 2 会漏掉 referee_id IS NULL 的行，因为 NULL != 2 求值为 NULL（即 UNKNOWN），WHERE 只保留 TRUE。

代码实现

📊 性能分析

  • 时间复杂度：O(n)O(n)O(n)，全表扫描（条件含 OR 与 IS NULL，难以有效走索引）
  • 空间复杂度：O(1)O(1)O(1)

思路 2：CTE 先筛后取（等价写法）

核心逻辑

把筛选取数封进 CTE 再在外层 SELECT，语义分层更清楚，便于作为更复杂查询的中间步骤。

代码实现

与思路 1 完全等价；本例中 CTE 没有语义收益，仅作写法对照。

思考

  • MySQL 里 != 与 <> 完全等价，建议统一用 <> 保持可读性。
  • 只要条件里出现 NULL，就回到三值逻辑（TRUE / FALSE / UNKNOWN），WHERE 只保留 TRUE。

📝 总结

一句话：<> 条件遇到 NULL 会「漏人」；凡是「不满足某条件的人」的题，都必须显式 OR <列> IS NULL 兜底。
